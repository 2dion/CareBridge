# 자동 점검 (e2e)

테스트 계획(`문서/설계/시연-일정-v1.1.md` '테스트 계획')과 이슈로 올린 버그를 명령 하나로 다시 확인하는 Playwright 점검입니다.

- **목적:** 버그를 고친 사람이 QA를 기다리지 않고 바로 확인합니다. 다른 곳이 다시 깨지지 않았는지도 같이 봅니다.
- **배경:** QA(10/28~10/29)에서 찾은 버그가 이슈로 30건 넘게 올라갔습니다. 손으로 같은 순서를 매번 따라 하기 어렵습니다.
- **사유:** 공용 Supabase에 시험 기관을 매번 새로 만들어 돕니다. 그래서 시연용 데모 기관과 데모 계정은 건드리지 않습니다.

## 처음 한 번

`web/` 폴더에서 돌립니다.

```bash
npm ci
npx playwright install chromium        # 점검용 브라우저 (한 번만)
```

`web/.env.local`에 아래 세 값이 있어야 합니다. 앱 실행에 쓰는 값과 같습니다.

| 변수                                   | 설명                                                                               |
| -------------------------------------- | ---------------------------------------------------------------------------------- |
| `NEXT_PUBLIC_SUPABASE_URL`             | 공용 Supabase 주소                                                                 |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | 공개 키                                                                            |
| `SUPABASE_SERVICE_ROLE_KEY`            | 서버 전용 키. 시험 기관·계정을 만들 때 씁니다. **백엔드 담당에게 DM으로 받습니다** |

`npm run test:e2e:ai`는 실제 AI를 부르므로 `ANTHROPIC_AUTH_TOKEN`·`GROQ_API_KEY`도 있어야 합니다(`web/README.md` '실제 AI를 부르고 싶을 때'). 개발 중에는 `AI_MODEL_MAIN=claude-haiku-4`로 아낍니다.

키 값은 채팅·이슈·커밋에 붙이지 않습니다.

## 명령

| 명령                      | 하는 일                                                                 | 걸리는 시간 |
| ------------------------- | ----------------------------------------------------------------------- | ----------- |
| `npm run test:e2e`        | AI를 빼고 모두(코드 검사·API·작성자 화면·관리자 화면)                   | 10~15분     |
| `npm run test:e2e:logic`  | 서버 검사 함수만. 키·서버 없이 돕니다                                   | 10초        |
| `npm run test:e2e:ai`     | 실제 Claude로 합성 사례 10개와 AI 이슈 문장. **코디세이 토큰을 씁니다** | 30분 넘게   |
| `npm run test:e2e:report` | 마지막 결과를 브라우저로 봄(실패한 화면 사진·기록 포함)                 | —           |

- 이 PC에서 앱을 3100번 포트로 띄워 돕니다(`npm run dev`와 따로). 이미 떠 있으면 그대로 씁니다.
- 배포본으로 돌리려면 `E2E_BASE_URL=https://care-bridge-kappa.vercel.app`을 붙입니다. 배포본은 AI가 켜져 있으니 `test:e2e:ai`는 로컬에서만 돌립니다.
- 한 이슈만: `npx playwright test -g "#135"`. 한 줄만: `npx playwright test -g "계획 승인-1"`.
- 화면을 보면서: `npx playwright test --headed --project=worker -g "#139"`.

## 결과 읽는 법

- **점검 이름 앞 `[#번호]`** 는 이슈, **`[계획 …]`** 은 테스트 계획 줄입니다. 이슈의 '끝난 기준'을 그대로 옮겼습니다.
- **아직 고치지 않은 이슈의 점검은 실패하는 것이 정상입니다.** 고친 PR에서 그 이슈 점검이 통과하면 됩니다.
- 이미 고친 이슈(#114, #118)와 테스트 계획 줄은 통과해야 합니다. 실패하면 다시 깨진 것입니다.
- PR 본문 '어떻게 확인했나'에 `npx playwright test -g "#번호"` 결과를 적습니다.

## 시험 데이터

| 무엇                 | 어떻게                                                                                                                                                                                       |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 기관                 | 실행마다 `[E2E] 시험 요양센터 …`(일반)과 `[E2E] 시험 교육원 …`(교육용)을 새로 만듭니다                                                                                                       |
| 계정                 | `e2e-worker`·`e2e-worker2`·`e2e-worker3`(작성자), `e2e-manager`(관리자), `e2e-trainee`(교육생), `e2e-trainer`(강사) `@carebridge.test`. 실행마다 새 기관으로 옮기고 비밀번호를 새로 정합니다 |
| 비밀번호·로그인 쿠키 | 이 PC의 `e2e/.state/`에만 둡니다(커밋 안 됨). 다음 실행 때 바뀝니다                                                                                                                          |
| 어르신               | 점검마다 `시험 ○○ 3f9a1c`처럼 새 합성 어르신을 만듭니다(실명 없음)                                                                                                                           |
| 기록 초안            | AI를 부르지 않고 서버 저장 함수(`save_record_ai_draft`)로 넣습니다. 내용은 합성 사례 S-F01·S-H01을 줄인 것(`support/drafts.ts`)                                                              |

**정리:** 지난 실행의 시험 기관은 계정이 떠나 화면에 보이지 않지만 DB에는 남습니다. 가끔 백엔드 담당이 SQL Editor에서 `supabase/e2e-cleanup.sql`을 돌려 지웁니다. 데모 기관과 마지막 실행의 시험 기관은 지우지 않습니다.

### 시연 전 (시연대본 시나리오 1 '시연 전 준비')

자동 점검은 시험 기관에서 돌아서 데모 기관 상태를 보지 않습니다. 시연 직전에는 대본의 체크 목록을 사람이 확인합니다. 특히 W1에서 김○○ 카드가 '작성 전'인지, 화면 위 MOCK 띠가 맞게 보이는지, 휴대폰 마이크 권한을 직접 봅니다.

## 알아 둘 것

- **처음 만든 판입니다(10/29).** 코드 검사(`logic`)는 돌려 봤습니다. 화면·API 점검은 Mock 화면으로 버튼·칸 이름만 맞춰 봤고, 공용 Supabase로는 아직 돌려 보지 않았습니다. 처음 돌릴 때 준비 단계(`setup`)가 실패하면 QA 담당에게 알려 주세요.
- **#139의 '숫자 칸 이름' 점검은 지금도 통과합니다.** Playwright의 Chromium 접근성 트리에서는 칸 이름이 읽힙니다. QA 때 본 '이름 없는 칸'은 다른 도구에서 본 것일 수 있어, 실제 화면 낭독기로 다시 확인합니다(위 수동 점검).
- 점검이 늘거나 바뀌면 이 표도 같이 고칩니다.
