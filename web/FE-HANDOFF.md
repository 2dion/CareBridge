## Mock의 정확한 한계

- 녹음은 브라우저에서 시작/정지하며 5분 자동 종료. 음성은 **서버 업로드/받아쓰지 않음**. 녹음 결과와 상관없이 S-F01 초안을 반환하는 시연이며 파일은 보관하지 않습니다.
- `글로 쓰기` 입력 내용 또한 AI 파싱에 사용되지 않고 S-F01 정답을 보여 줍니다. 실제 사용자 입력을 분석하는 기능이 아닙니다.
- 진행 상태는 **localStorage에만 저장**되고 같은 브라우저 프로필 탭 간에만 공유됩니다. 서로 다른 휴대폰/PC에서 동일한 상태를 확인할 수 없습니다. 시연은 한 브라우저에서 역할을 바꾸거나 백엔드 API를 붙인 뒤 두 기기에서 진행해야 합니다.
- API 호출은 아직 하지 않습니다. 권한과 서버 승인 차단(RLS, 403/409 등)은 보장되지 않습니다. 실제 서비스에 배포하지 말고 `Mock`으로만 사용하세요.
- 화면에서 작성·관리자 전환은 실제 로그인 아님. 승인/수정/되돌리기는 Mock 브라우저 상태에만 적용됩니다.
- 직접 수정 시 베트남어 번역을 지어내거나 구버전으로 남기지 않고 공란 처리했습니다. Backend 번역 호출이 연결되어야 합니다.
- W6 교재 검색·교육기관 코멘트·법정 서식 원본 그대로 인쇄·재가 분 단위 입력·실제 음성 업로드는 **아직 구현되지 않았습니다**.
- M3 인쇄는 별지 제16호와 똑같은 양식이 아닌 `공식 기록지 아님` 표기의 간이 기록지입니다.
- `AI 작업 기록` 4행은 시연 대본에서 추린 예시이며 **실제 Agent 호출 로그가 아닙니다**.

## 백엔드 연결 순서

1. Supabase Auth로 worker/reviewer 권한 및 기관별 RLS 검증(상단 전환 UI 제거).
2. `records`, `record_items`, `record_events`, `agent_steps` 읽기를 Supabase/서버 API에 연결. 화면의 상태 객체를 서버 데이터로 대체.
3. W2 녹음: `/api/records/:id/audio/upload-url` → Storage 직접 업로드 → `/api/records/:id/audio`; 전사 완료 뒤 `/agent-run`. 원본 파일은 성공·오류 때 보관 정책 준수.
4. W3 `PATCH /api/records/:id/items/:key` 와 `POST .../submit`, 관리자 `PATCH`, `/approve`, `/return`. **서버 검증이 유일한 최종 승인 관문**.
5. M3의 `/print`와 제16호/제12호 인쇄 서식 연결. 교육기관, W6, 재가 흐름 등 후속 구현.

## 10/22 Mock 안전성 보완 및 확인 결과

- W1에서 아직 초안을 만들지 않은 `draft`는 ‘작성 전’, 초안을 생성한 `draft`는 ‘임시 저장’으로 구분합니다. 뒤로 이동한 다음에도 생성된 초안을 다시 열 수 있습니다(`draftPrepared`).
- 녹음 중 다른 화면으로 이동하거나 시연 초기화·글 입력 모드 변경 시 MediaRecorder와 마이크 트랙을 중지합니다. 마이크 권한을 허용하는 사이 이동한 경우에도 뒤늦게 녹음이 시작되지 않도록 요청 세션을 무효화합니다.
- 글로 쓰기 입력창에는 대본 문장을 미리 넣지 않습니다. 어떤 문장을 적어도 S-F01 Mock 초안이 표시되는 **시연 전용** 동작임을 유지합니다.
- 단독 QA: TypeScript/TSX 변환 구문 검사, CSS 구문 검사, JSON 원본 일치 확인, 상태 전환 테스트(확인 필요 2→1→0, 미해결 승인 차단, 되돌린 기록 승인 차단) 통과.
- 미검증: `npm ci`가 이 환경에서 실패/시간 초과되어 Next.js 빌드, ESLint, Prettier, Vitest, 실제 브라우저 조작은 팀 개발 환경에서 확인해야 합니다.
- 저장소에 직접 커밋하지 않았으며 팀 main이 변경됐을 경우 최신본과 비교한 뒤 적용해야 합니다.
