# 문서

우리 팀이 만든 문서를 둡니다.

| 폴더 | 넣는 것 |
|---|---|
| `기획/` | 무엇을, 누구를 위해 만드는지 정한 문서 (기획안, 확정안) |
| `설계/` | 어떻게 만드는지 정한 문서 (화면, 데이터, AI 규칙)와 그 문서를 검토한 기술검토 |
| `회의록/` | 회의·멘토링 기록. 파일 이름은 `날짜-제목.md`. 지난 회의록도 그대로 둡니다 |
| `결정/` | 결정 하나에 파일 하나: 배경, 검토한 대안, 사유, 영향 (ADR). 바뀌어도 지우지 않고 상태만 '대체됨' |
| `보관/` | 새 문서로 바뀐 이전 문서 (참고만, 기준 아님) |

기획·설계 문서는 새 버전을 만들면 이전 파일을 `보관/`으로 옮깁니다. 옮길 때 이름 앞에 옮긴 날짜를 붙입니다(예: `보관/설계/2026-10-25-데이터구조-v1.2.md`). 그 파일을 가리키는 링크도 같이 고칩니다.

## 파일 이름 규칙

이 규칙은 `문서/`와 `참고자료/`에만 적용합니다. 코드 폴더(`web/`, `supabase/`, `.github/` 등)는 Next.js·Supabase·GitHub이 정한 이름(`[id]`, `(auth)`, `_` 등)을 그대로 따르고, 코드가 깨졌는지는 CI가 확인합니다.

1. Shift 없이 입력되는 글자만 씁니다: 한글, 영문, 숫자, `-`, `.`
2. 공백, `_`, 괄호, `[]`, `·`, `+`는 쓰지 않습니다.
3. 단어는 붙여 쓰고, 덩어리 사이만 `-`로 나눕니다.
4. 순서는 `날짜-내용-사람-버전`이고, 해당하는 것만 씁니다. 서식 개정일처럼 "몇 년 판"을 뜻하는 날짜는 버전 자리(맨 끝)에 둡니다.
5. `케어브릿지` 접두어와 폴더 이름과 겹치는 말은 뺍니다.

예: `회의록/2026-10-15-멘토링.md`, `기획/기획-v0.3.md`, `인터뷰/2026-10-12-간호사-데이터담당.md`

올리면 GitHub Actions의 "파일 이름 검사"가 `문서/`·`참고자료/`의 1·2번 규칙을 자동으로 확인합니다. 커밋 옆에 빨간 X가 뜨면 Actions 로그에 나온 파일 이름을 고쳐 다시 올립니다.
