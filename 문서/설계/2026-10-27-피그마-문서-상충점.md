## 이어서 작업할 때의 지시

1~12번을 위 표와 결정 기록에 맞춰 확인합니다. 이미 반영된 동작은 유지하고, 실제 API 번역·이유 번역 저장·피그마 편집은 완료 증거가 있을 때만 구현 완료로 바꿉니다. 제16호 notes 저장 구조나 API 칸을 임의로 신설하지 않습니다. 코드 검사 결과와 남은 작업은 PR #67의 담당별 목록에도 맞춥니다.

## 이번 변경의 확인 결과

- `web/`에서 `npm run check` 통과: 린트·형식·타입 검사, 테스트 94개. W3 입력 보존·재처리 차단, 원문 PDF의 값 기입·뒤쪽·이어쓰기·notes 영역 선택·미입력 분·기록 안 함 제외 테스트를 포함합니다.
- `npm run build -- --webpack` 통과. 기본 Turbopack 빌드는 이 실행 환경의 임시 로컬 포트 생성 제한(`Operation not permitted`)으로 실패했으므로 통과로 적지 않습니다.
- 격리한 브라우저의 합성 녹음 객체로 W2 재녹음 시 이전 콜백 분리·이전 트랙 종료, 나가기 취소·확인, 해당 날짜 기록 시작으로 복귀·모든 트랙 종료를 확인했습니다. 실제 마이크·기기 검증은 아닙니다.
- W3 글 입력 실패 → 같은 주소에서 재시도 → 음성 인식 없는 처리 단계 → 카드 표시를 확인했습니다. 원문과 `inputMode = text`가 보존됩니다.
- W4 탭 5개 이름과 [지금 쓰기]의 `/start/:residentId?date=...` 경로, R2 [확인함]·다시 열기의 ‘확인 필요·처리 완료’ 숫자를 확인했습니다.
- 앱의 제16호·제12호 빈 원문 사본은 참고자료와 SHA-256이 일치합니다. 10/28 수정에서 원문에 기록을 채우는 PDF 생성과 뒤쪽 보존, 긴 글 이어쓰기를 추가했습니다. 이전의 빈 양식 연결만으로 인쇄 완료로 보지 않습니다.
- 생성한 제16호·제12호 PDF를 이미지로 렌더해 한글·날짜·시간·원문 배치·이어쓰기 페이지를 확인했습니다. 브라우저에서도 두 양식의 기록 PDF 생성·다운로드 링크, 제16호 영역 선택 전 생성 차단과 선택 변경 뒤 이전 PDF 숨김, 390px 가로 넘침 없음, 콘솔 오류·경고 0건을 확인했습니다. 실제 A4 인쇄의 글자 크기·페이지 수는 QA에서 확인합니다.
- 실제 기록 API 번역, `reason_native` DB·Agent 연결, 피그마 파일 수정은 남습니다. 제16호 notes를 여러 영역으로 나눠 저장하는 계약은 신설하지 않았습니다.
