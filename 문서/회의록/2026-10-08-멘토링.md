## 한 줄 요약

**단순 번역기가 아니라, 요양보호사가 편하게 말하면 AI가 서식을 채워 주고 빠진 항목은 되묻는 "다독이는 대화형 챗봇"으로 방향을 바꾼다.** 관리자는 요약·원문·번역을 검토해서 승인한다.

---

## 1. 멘토 피드백: 지금 기획의 문제

- "외국어 메모를 한국어로 번역해서 서식에 맞게 작성"하는 것만으로는 **번역기나 ChatGPT와 다를 게 없다.** 공모전 심사에서도 바로 "차별성 없음"으로 떨어질 것.
  - 실제로 베트남 학생들은 이미 GPT로 한국어 문서를 잘 써 온다.
- 기획서의 "원문 입력" 단계 자체가 걸림돌이다. 보호사가 무엇을 어떻게 입력해야 할지부터 모른다.
- 공모전 과제의 핵심은 **"비식별 관찰 메모를 어떻게 쉽게 플랫폼 서식으로 옮기느냐"**다. 단순 번역과 기록 작성을 넘어, AI가 무엇을 해결하는지 "킥"이 필요하다.

## 2. 결정된 방향

### 2-1. 대화형(음성 + 텍스트) 챗봇
- 음성과 채팅 **두 방향 모두 지원**한다. 젊은 보호사는 채팅을, 나이 드신 분은 음성을 선호할 것.
- **항목별로 하나씩 말하게 하면 안 된다.** 수면, 식사, 제공 서비스 등을 순서 없이 옆 사람에게 얘기하듯 말하면 된다.
- AI가 말한 내용을 텍스트로 받아 적고, 번역하고, **서식 항목에 자동으로 나눠 채운다.**
- **빠진 항목이 있으면 AI가 되묻는다.** ("이분 수면은 어땠어요?") 주고받으면서 서식을 완성한다.
- 다 채워지면 "오늘도 수고했어요"로 마무리하고 다음 환자로 넘어간다.

### 2-2. 보호사 화면 흐름
- 출근해서 로그인하면 **내가 맡은 환자 목록**이 업무일지처럼 쭉 보인다.
- 환자를 누르면 채팅이 열린다. 겉은 채팅이지만 속은 업무일지다.
- 시작은 AI가 먼저 묻는 형태가 좋다. ("오늘 이분 상태는 어땠어요? 편하게 다 얘기해 주세요.")

### 2-3. 채팅 무드: 다독이는 감성
- 캐묻는 말투가 아니라, **하루를 잘 정리하고 "고생했다"고 다독이는 느낌**으로 간다.
- 타국에서 일하는 외로움을 감싸 주는 포근한 톤.
- 콘셉트: **"감성이 무드였지만, 업무였다."** 감성 일기 같은 분위기로 쓰는 부담을 낮춘다.
- 보호사가 너무 대충 말하거나 말이 없으면 다그치지 말고 독려한다.
- 감시나 추적하는 느낌을 주면 안 쓰게 된다. "업무를 편하게 하려고 만든 앱"이라는 인상이 중요하다.

### 2-4. 관리자 화면
- 관리자는 음성을 들을 필요가 없고 대화 전체를 볼 필요도 없다. **그날 정리된 서식(요약)**만 보고 싶어 한다.
- 다만 의심이 들 때 확인할 수 있도록 **원문(외국어 텍스트), 번역문, 요약본**을 함께 제공한다.
- **검토 → 수정 → 승인** 후 실제 시스템으로 보낸다. 바로 넘어가면 안 된다.

### 2-5. 보호사 상태 파악 (부가 기능)
- 음성 톤이나 평소와 다른 기록 패턴(평소엔 길게 쓰다가 오늘은 대충 쓴다 등)으로 **보호사의 기분·컨디션을 관리자에게만** 알려 준다. 보호사 본인에게는 보여 주지 않는다.
- 논리: 보호사의 기분이 곧 태도가 되므로, **환자에게 집중할 수 있도록 보호사의 감정과 상태를 관리한다.**

### 2-6. 확장성 (발표·기획서용 포인트)
- 실제 요양 데이터나 기관 서식을 받으면 채팅 필수 항목만 바꾸면 되므로 **어떤 포맷에도 맞출 수 있다.**
- 나중에 기관 공지 등도 같은 채팅방으로 전달할 수 있다.
- 외국인뿐 아니라 **고령의 한국인 요양보호사**에게도 쓸 수 있다. 보호사 고령화가 계속되므로, 문서 작성 부담을 줄이면 더 오래 일할 수 있다. (통계 조사해서 넣으면 좋음)

## 3. 데이터 문제

- 실제 요양 기록 레퍼런스는 아직 못 구했다. 못 구하면 가상 데이터를 만든다.
- 멘토 의견: 법적 요약 문서는 기관마다 쓰는 시스템이 달라 그대로는 큰 의미가 없고, 실제 문서도 외부로 잘 안 나온다.
- 대신 **"요양보호사 업무 인터뷰를 통해 실제 업무 항목을 정의했고, 그 정의를 기준으로 채팅을 구성했다"**는 식으로 기획서를 쓰면 공모전에서 플러스가 된다.

## 4. 공모전 관련

- 출품 대상: 2026 AI 라이프 솔루션 챌린지 (주제가 정해져 있고 그중 선택).
- 팀장 팀원이 주최 측에 "비식별 메모가 정확히 무엇인지, 현장에서 어떤 문제가 있었는지" 문의 메일을 보냈고, **다음 주 월요일(10/12)에 답변 공지 예정.**
- 다른 팀들도 비슷한 플랫폼을 낼 것이므로 대화형·감성 UX로 차별화해서 승부한다.
- 파이널 프로젝트와 공모전 중 하나를 포기할 필요는 없다는 결론.

## 멘토 서면 피드백 요약

멘토가 회의 뒤 따로 보낸 피드백을 요약했습니다.

- **기존 번역 서비스와의 차별성:** 번역과 서식 채우기만으로는 번역기·ChatGPT와 차이가 작다. 빠지거나 모호한 정보를 AI가 판단해 모국어로 되묻는 방식을 고민할 것.
- **AI 기능 구체화:** 원문 근거 확인, 누락 정보 검증을 어떻게 구현할지, AI가 원문에 없는 내용을 만들지 않았는지 확인하는 방법을 정할 것. 단순 API 호출을 넘어 AI가 무엇을 판단하고 수행하는지 정의할 것.
- **화면 구성:** 보호사 모바일 화면과 담당자 PC 화면을 나누고, 메모 입력부터 승인까지의 흐름을 화면으로 보여 줄 것(Figma 등).
- **멘토링 정리:** AI 버디가 먼저 묻고 기록을 완성하는 '오늘의 채팅', 관리자의 원문·번역·기록 비교와 승인, 업무 뒤 정서적 대화(업무 기록과 분리, 본인 동의한 요청만 관리자에게), 다음 멘토링에서 프로토타입 검토.
