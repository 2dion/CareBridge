## 1. 기획의도

### 1.1 해결하려는 문제

외국인 요양보호사가 관찰한 내용을 한국어 기록 문장과 서식으로 옮기는 과정에서 언어와 용어의 장벽을 겪고, 기관 담당자가 이를 다시 확인·작성해야 한다는 문제 가설에서 출발한다. 일상 한국어 능력과 공식 기록 작성 능력은 다를 수 있으며, 단순 번역만으로는 관찰 사실의 누락, 수치 오류, 기록 항목 배치, 불확실한 표현의 처리를 해결하기 어렵다.

V1에 제시된 언론 사례와 해외 연구는 조사 출발점으로 사용하되, 국내 시설의 현재 업무 부담이나 본 서비스 효과를 직접 입증한 자료로 해석하지 않는다. 제출 전에는 통계·연구 원문과 적용 한계를 정리하고, 접근 가능한 요양기관 담당자 인터뷰로 실제 기록 흐름과 재작성 부담을 확인한다.

### 1.2 목표 사용자와 사용 상황

| 사용자 | 과업 | 서비스에서 얻을 가치 | 검증 질문 |
| --- | --- | --- | --- |
| 외국인 요양보호사 | 돌봄 이후 관찰 내용을 기록 | 모국어 메모로 한국어 초안을 만들고 사실 여부를 확인 | 입력·확인 흐름을 혼자 이해할 수 있는가? 역번역이 원래 관찰과 다른 점을 찾는 데 도움이 되는가? |
| 기관 기록 담당자(사회복지사·팀장 등) | 기록의 내용·누락 확인 및 승인 | 원문 근거와 확인 요청을 보며 검토·수정 | 기존 작성 방식보다 검토 시간이 줄고 수정 부담이 감소하는가? |

유학생은 상황 카드 기반 평가 참여자로 섭외할 수 있으나, 현직 사용자와 구분해 결과를 보고한다. 보호자, 재가서비스 사용자, 내국인 신입, 다른 언어 사용자는 이번 핵심 대상에 포함하지 않는다.

### 1.3 해결 방식과 AI 적용의 필수성

베트남어 관찰 메모를 시설급여 기록 항목에 맞는 한국어 초안으로 구조화하고, 각 값에 원문 근거를 연결한다. 메모에 없는 정보는 미기재로 남기며 모호한 내용은 확인 요청으로 제시한다. 요양보호사가 모국어 설명을 보고 확인한 뒤, 기관 담당자가 검토·수정·승인한다.

AI는 자유로운 베트남어 표현의 한국어 구조화와 한국어 초안의 모국어 설명을 맡는다. 프로그램은 개인정보 가리기, 용어집 검색, 출력 형식·근거·수치 검사, 권한 확인, 승인 절차를 맡는다. 규칙만으로는 다양한 자연어 표현을 처리하기 어렵고, AI만으로는 근거 및 승인 기준을 강제하기 어렵다는 점에서 둘을 결합한다. 이번에는 기존 모델 API를 활용하며 자체 모델 학습은 필수 범위에 넣지 않는다.

### 1.4 차별성과 검증 가설

일반 번역 결과를 보여 주는 것에 더해, 기록 항목별 근거·미기재·확인 필요 상태와 담당자 승인 이력을 제공한다. 차별성이 실제 효과로 이어지는지는 다음 가설을 평가해 판단한다.

- H1: 동일 AI 모델에 단순 번역·항목 배치만 시킨 방식보다 원문 정보 누락과 값 오류가 적다.
- H2: 원문에 없는 돌봄 사실을 추가하는 오류를 검사와 검토 과정에서 발견할 수 있다.
- H3: 기존 한국어 직접 작성·수정 방식보다 담당자 검토 시간과 수정 항목 수가 줄어든다.

S1 응급 보고 문장과 S2 음성 입력은 10/10 팀 결정 전까지 개발 범위에 포함하지 않는다. 포함하더라도 필수 F1~F5의 일정과 검증을 우선한다. 진단·처치 추천, 자동 공식 제출, ERP·건보공단 연동, 다국어 확장, 앱스토어 배포, 교대 요약, 한국어 학습은 제외한다.

시설급여 서식은 10/10까지 원문·버전·항목 목록을 고정한다. 관찰 메모로 생성하는 항목과 계정·수급자 선택·작성일 등 시스템이 채우는 항목을 분리한다. 아래 사례는 서식 확정 전의 설명이며 법정 서식 항목 확정본이 아니다.

### 3.2 화면과 사용자 흐름

| 화면 | 주요 내용 |

| ① 어르신 선택 | 담당 가상 수급자, 오늘 작성 현황, 반려 알림 |

사용 예: ‘점심을 반 정도 드셨고, 어지럽다고 말씀하셨으며, 간호사에게 알렸다’에 해당하는 베트남어 메모를 입력한다. 초안은 식사량·호소 내용·보고 행동을 정리하고 각각 원문 근거를 표시한다. 배설 정보는 미기재로 남기며, 시각 등 추가 확인이 필요한 내용은 질문한다. 베트남어 예시 문장과 기대 결과는 검수자가 확인한 뒤 데이터셋에 넣는다.

`어르신 선택 → 메모 작성 → 개인정보 가리기 → AI 초안 생성·검사 → 요양보호사 확인·제출 → 담당자 검토 → 승인 또는 반려 → 기록 이력`

### 3.3 상태·버전·예외 처리

아래 상태와 처리 기준은 V1의 흐름을 구체화한 보완 제안이다.

| 상태 | 다음 행동 | 제한 |
| --- | --- | --- |
| 작성 중 | 메모 저장·초안 생성 | 생성 실패를 제출 완료로 취급하지 않음 |
| 요양보호사 확인 대기 | 질문 답변·추가 메모·확인 후 제출 | 재생성으로 내용이 바뀌면 새 버전 확인 |
| 담당자 검토 대기 | 검토·수정·반려·승인 | 확인 필요 항목 및 서식 승인 조건 확인 |
| 반려 | 사유 확인·추가 입력·재생성·재제출 | 이전 초안과 반려 사유 보존 |
| 승인 | 이력 조회·PDF 생성 | 본문 직접 수정 금지. 정정이 필요하면 기존 승인본을 참조하는 새 버전 생성 |

‘확인 요청 해결’은 추가 근거 확보·원문 정정·명시적 정보 확인 불가로 구분한다. 관찰하지 않은 내용을 질문의 답을 맞추듯 채우지 않는다. 확인 불가 상태로 승인할 수 있는 항목과 반드시 보완해야 하는 필수 항목은 서식 기준에 따라 정한다. 담당자가 돌봄 사실을 바꾼 경우 요양보호사에게 재확인을 요청하고, 단순 표현 교정은 수정 이력에 남긴다.

중복 제출·승인 버튼 반복은 한 번만 반영하고, 동시 수정 시 다른 버전을 덮어쓰지 않도록 확인한다. 오류 시 메모를 보존하고 재시도 가능 여부를 안내한다. 시연 준비 사례를 재사용하는 경우에도 실시간 생성인지 저장된 결과인지 구분한다.

### 3.4 AI 처리와 시스템 구조

```text
모바일·PC 웹
   ↓ 로그인·기관/역할 권한 확인
서비스 서버 ── DB(메모·초안 버전·확인·승인 이력)
   ├─ 가상 수급자·가명 대응표(접근 제한)
   └─ 개인정보 가리기 → 용어집 검색 → LLM 구조화
                                       ↓
                              형식·근거·수치 검사
                                       ↓
                              LLM 베트남어 설명
                                       ↓
                           요양보호사 확인 → 담당자 승인
                                       ↓
                               승인본 조회·PDF 생성
```

용어집은 팀이 정리한 베트남어 표현·한국어 요양 용어·설명·출처로 구성하며 표준교재 본문을 무단으로 서비스에 적재하지 않는다. AI 출력은 항목 ID, 값, 원문 근거, 상태, 확인 질문의 구조를 요구한다. 근거 문장은 가명처리된 입력과 대조하고 수치·단위·누락을 검사한다. 부정 표현과 의미 오류는 규칙만으로 완전히 판별하기 어려우므로 평가셋과 사람 검토로 확인한다.

관찰 메모는 데이터로 취급한다. 메모 속 ‘규칙을 무시하라’ 등의 문장으로 시스템 지시·출력 형식·승인 권한을 바꾸지 않도록 설계하고 별도 시험한다. 외부 AI 키와 서비스 비밀정보는 브라우저에 전달하지 않는다.

백엔드·프론트엔드·DB·배포 환경은 10/8까지 담당자가 선택하고, AI 모델·호출 예산·재시도 제한은 10/10까지 결정한다. 개발 경험, 구조화 출력 지원, 베트남어 평가 결과, 비용과 응답 시간을 비교한다. 모델 버전·프롬프트·용어집·검사 규칙 버전을 평가 기록과 연결한다.

### 3.6 평가 설계

자동 평가와 사용자 테스트는 비교 대상이 다르므로 결과를 별도로 보고한다.

**자동 평가:** 동일한 입력·모델·서식 기준으로 ‘단순 번역·항목 배치 프롬프트’와 ‘케어브릿지 전체 처리’를 비교한다. 규칙이 근거 없음을 감지한 건수와 AI 초안 자체의 오류 건수, 사람 승인 후 잔존 오류를 구분한다. 여러 번 실행할 때에는 실행 횟수와 변동 폭을 기록한다.

**사용자 테스트:** 동일한 난이도의 서로 다른 가상 사례로 ①한국어 직접 작성·담당자 수정, ②일반 번역기+수동 항목 배치, ③케어브릿지를 비교한다. 요양보호사 입력 시간과 담당자 검토 시간을 따로 측정하며, 방식 순서를 바꾸어 반복 학습 영향을 줄인다. 미완료·반려·실패 사례도 기록한다.

## 4. 기대효과 및 활용방안

### 4.1 기대효과

요양보호사는 관찰 내용을 모국어로 표현하고 자신의 기록을 확인할 수 있으며, 담당자는 근거와 불확실한 항목을 중심으로 검토할 수 있다. 원문·수정·승인 이력이 남아 팀이 오류 원인과 업무 흐름을 분석하는 데 도움이 될 것으로 기대한다. 기록 누락 감소·담당자 시간 절감·현장 정착·안전 개선은 기대효과이며, 완료된 성과로 표현하지 않는다. 이번에는 기록 품질과 검토 부담에 대한 제한된 검증을 수행한다.

### 4.2 활용과 사업화 가설

첫 활용처는 가상 사례 기반 양성 과정 실습과 요양기관 담당자의 프로토타입 검토다. 실제 기관 도입은 서식 적합성·권한·보안·운영 책임 및 개인정보 처리 조건을 검토하고 현장 시험을 거친 뒤 추진한다.

기관 구독을 주 수익 가설로 두고 교육용 라이선스·ERP 제휴·공공 시범사업을 확장 경로로 검토한다. 요양보호사는 무료로 사용하는 구조를 제안한다. 기관이 비용을 지불할 만큼 검토 시간이 줄어드는지, 교육기관의 연습 수요가 있는지 인터뷰로 확인한다. V1의 요금·시장 규모·매출 전망은 검증 전 가정이므로 이 기획서에서 확정 수치로 사용하지 않는다.
