## 이 문서 읽는 법

이 문서는 개발을 몰라도 프로젝트 전체를 판단할 수 있도록 쓴 PM용 기획서입니다. 구현을 맡는 사람과 AI는 같은 내용을 더 엄격하게 쓴 (기획 담당) 구현 명세서를 봅니다.

| 문서 | 읽는 사람 | 담는 내용 |
| --- | --- | --- |
| (기획 담당) PM용 기획서 (이 문서) | PM, 팀 전체, 멘토 | 왜, 누구를 위해, 무엇을, 어디까지, 언제 |
| (기획 담당) 구현 명세서 | 백엔드·프론트·QA, 코딩 AI | 화면, 데이터 구조, AI 규칙, 검증 기준, 테스트 |

- V1과 V2가 다르면 V1의 '범위'가 우선입니다. 기획 담당이 V2를 고칩니다.
- 아직 정하지 않은 것은 마지막 '리스크 및 추가 결정사항'에 모아 두었습니다. 추측으로 채우지 않았습니다.

## 한눈에 보기

케어브릿지는 외국인 요양보호사가 모국어로 남긴 관찰 메모를, 근거가 남는 한국어 급여제공기록지 초안으로 바꿔 주고 담당자가 확인만 하고 승인하게 하는 서비스입니다.

| 항목 | 내용 |
| --- | --- |
| 핵심 사용자 | 외국인 요양보호사(메모 입력), 요양기관 담당자(검토·승인) |
| 핵심 기능 | 모국어 메모 → 기록지 초안, 원문 근거·미기재 표시, 담당자 검토·승인 |
| 활용처 | AI 라이프 솔루션 챌린지(10/31 제출), 코디세이 파이널 프로젝트(11/8 제출) |
| 기록 기준 | 요양보호사 양성 표준교재 9장 기록 원칙(사실 그대로, 육하원칙, 공식 용어) |

**원안과 우리의 해석**

공모전 후보작 원안(「2026 AI 라이프 아이디어 챌린지 수상 후보작 목록」): "외국인 요양보호사 후보 및 돌봄인력의 비식별 관찰메모를 AI가 분석·번역, 한국어 구조화 초안으로 정리하여 돌봄인력 담당자의 의사결정을 보조하는 서비스"

우리는 원안의 범위 안에서 구체화했고, 원안에 없는 기능(응급 보고 등)은 선택 기능으로 분리했습니다. 후보작을 구현해야 가점 5점을 받고, 결과물의 지식재산권은 아이디어 제안자와 50:50으로 공동 소유합니다.

| --- | --- | --- |
| 외국인 요양보호사 후보 및 돌봄인력 | 현직 외국인 요양보호사와 양성 과정 유학생 | 사전질의 |
| 비식별 관찰메모 | AI로 보내기 전에 이름 등을 가린 관찰 메모 | — |
| AI가 분석·번역 | 메모를 읽고 기록지 칸별로 나눠 한국어로 옮김 | — |
| 한국어 구조화 초안 | 법정 서식 '장기요양급여제공기록지' 형식의 초안 | 사전질의 |
| 돌봄인력 담당자의 의사결정 보조 | 담당자가 기록을 검토·승인하는 판단을 돕는 것(채용·배치 판단은 아님) | 사전질의 |

## 왜 만드나

외국인 요양보호사는 어르신을 돌볼 수는 있지만, 한국어로 쓰는 공식 기록·응급 보고·인수인계에서 막힙니다. 그 결과 현장 정착이 늦어지고, 담당자는 기록을 다시 쓰는 부담과 안전 위험을 떠안습니다.

| 근거 | 수치 | 출처 |
| --- | --- | --- |
| 돌봄 수요 증가 | 장기요양 인정자 123만 5천 명(2025년, +6.0%) | 건보공단 통계연보 |
| 인력 공백 | 2028년 요양보호사 약 11만 7천 명 부족 전망 | 건강보험연구원(2023) |
| 외국인 인력의 병목 | 자격 보유자 2만 6,596명 중 실제 근무 7,623명(28.7%, 2025년 말) | 김선민 의원실 자료(한겨레21) |
| 신규 인력 유입 예정 | 양성대학 재학생 505명, 2028년 하반기 현장 투입 | 한겨레21(2026.7.7) |
| 기록이 병목이라는 증거 | 일본 사업소가 꼽은 외국인 인력의 한계: "개호기록, 전화 등" | JILPT(2024) |

현장의 목소리도 같은 지점을 가리킵니다. 15년을 한국에서 산 응옥린(가명)은 일지, 의학용어, 응급 연락이 여전히 어렵다고 말합니다(한겨레21). 기계번역을 그대로 쓰면 위험하다는 연구도 있어서(중국어 오역 19%, JAMA Intern Med 2019), 단순 번역기가 아닌 '근거와 검토가 있는 도구'가 필요합니다.

수치의 상세 출처와 한계는 '1단계 문제 조사 보고서'를 따릅니다.

## 누가 쓰나

이번 버전의 사용자는 두 명입니다. 메모를 쓰는 요양보호사와, 그 기록을 확인하고 승인하는 담당자입니다.

| 구분 | A. 외국인 요양보호사 | B. 기록 담당자 |
| --- | --- | --- |
| 대표 인물 | 응옥린형: 38세, 베트남 출신, 한국 생활 15년, 요양원 근무 | 요양원 사회복지사·팀장, 요양보호사 20명 안팎의 기록을 확인 |
| 하는 일 | 어르신 상태를 관찰하고 기록지에 남김 | 기록을 검토·수정하고, 기관 평가에 대비 |
| 어려운 점 | 일상 한국어는 되지만 일지, 의학용어, 공식 문장이 어려움. 틀리면 지적받을까 불안 | 외국인 직원의 기록을 다시 쓰는 시간, 사고 시 책임 소재 |
| 바라는 것 | 본 것을 정확하게, 혼나지 않게 쓰고 싶다 | 다시 쓰지 않고 확인만 해서 승인하고 싶다 |
| 서비스에서 쓰는 곳 | 휴대폰 화면(메모 입력, 초안 확인) | PC 화면(검토·승인 대시보드) |

나중에 넓힐 사용자(이번엔 대상 아님): 양성대학 유학생, 기록이 어려운 내국인 신입 요양보호사, 보호자.

## 무엇을 만드나

이번에는 베트남어 한 개 언어와 시설급여 기록지 한 종류만 다룹니다. 필수 기능 5개를 완성하는 것이 목표이고, 선택 기능은 필수가 끝난 뒤에만 손댁니다.

| 구분 | 기능 | 쉽게 말하면 |
| --- | --- | --- |
| 필수 F1 | 기록지 초안 만들기 | 베트남어 메모를 넣으면 한국어 기록지 칸이 채워진다 |
| 필수 F2 | 근거·미기재·확인 요청 표시 | 각 칸이 메모의 어느 부분에서 나왔는지 보여 주고, 없는 내용은 비워 둔다 |
| 필수 F3 | 요양보호사 확인 | 초안을 모국어로 다시 보여 주고 "맞아요"를 받는다 |
| 필수 F4 | 담당자 검토·승인 | 담당자가 고치거나 승인하고, 승인 기록이 남는다 |
| 필수 F5 | 개인정보 가리기(가명처리) | AI에 보내기 전 이름·호실·연락처를 가린다 |
| 선택 S1 | 응급 보고 문장 | 정해 둔 문장 틀로 간호사·보호자용 보고 문장을 만든다 |
| 선택 S2 | 음성 입력 | 말로 한 메모를 글로 바꾼다(필수는 글로 입력) |

**이번에 하지 않는 것**

- 사투리 이해 지원, 교대 인수인계 요약, 한국어 학습 기능
- 베트남어 외 다른 언어, 재가(방문요양) 기록지
- 건보공단·기존 요양 프로그램(ERP)과의 실제 연동
- 실제 어르신 개인정보 사용(모두 가상 사례)
- 앱스토어 앱(휴대폰 브라우저에서 여는 웹 서비스로 대신)

빠진 기능은 발표의 '향후 계획'과 성과보고서의 '한계 및 개선방안'에 적습니다.

## 서비스 흐름

메모 하나가 승인된 기록이 되기까지 두 사람의 확인을 거칩니다. AI는 초안만 만들고, 확정은 항상 사람이 합니다.

&#91;embedded content: 메모가 승인 기록이 되기까지 · 사람 확인 2단계\]

**사용자 이야기**

1. 오후 2시, 응옥린 씨는 휴대폰에서 305호 어르신을 고르고 베트남어로 메모합니다. "점심 반만 드심, 어지럽다고 하심, 간호사에게 알림."
2. 몇 초 뒤 한국어 기록지 초안이 나옵니다. 식사량 칸에는 '1/2'이 들어가 있고, 누르면 메모의 해당 문장이 표시됩니다.
3. 배설 칸은 메모에 없어서 '미기재'로 비어 있고, "어지럽다"는 "언제부터였나요?"라는 확인 요청이 붙어 있습니다.
4. 응옥린 씨는 베트남어로 되돌린 설명을 보고 내용이 맞는지 확인한 뒤 제출합니다.
5. 팀장은 PC 대시보드에서 '승인 대기' 목록을 열고, 확인 요청 칸을 모두 해결해야 승인할 수 있습니다. 내용이 부족하면 사유를 적어 돌려보냅니다.
6. 승인된 기록은 화면과 PDF에서 어르신 실명으로 보이고, 승인자와 시간이 함께 남습니다. 승인된 기록은 더 고칠 수 없습니다.

**화면 목록**

| 화면 | 사용자 | 하는 일 |
| --- | --- | --- |
| ① 어르신 선택 | 요양보호사 | 오늘 담당 어르신 중 한 명을 고른다 |
| ② 메모 입력 | 요양보호사 | 모국어로 메모를 쓴다(선택: 음성) |
| ③ 초안 확인 | 요양보호사 | 한국어 초안과 모국어 설명을 보고, 확인 요청에 답하고 제출한다 |
| ④ 승인 대기 목록 | 담당자 | 제출된 기록을 확인 요청이 많은 순서로 본다 |
| ⑤ 기록 검토 | 담당자 | 칸별 근거를 보고 수정·승인·반려한다 |
| ⑥ 어르신별 기록 이력 | 담당자 | 승인된 기록을 날짜별로 보고 PDF로 내보낸다 |

로그인 화면은 목록에서 뗰습니다. 반려된 기록은 ①에 알림으로 뜨고, ③에서 반려 사유를 확인한 뒤 답변이나 추가 메모를 더해 다시 제출합니다. 추가 메모를 쓰면 초안을 다시 만들고 달라진 칸을 표시합니다.

## AI는 어떻게 일하나

케어브릿지의 AI는 번역기가 아니라 '서식을 채워 주는 조수'입니다. 메모를 읽고 기록지의 각 칸에 맞는 내용을 찾아 넣되, 메모에 없는 내용은 절대 지어내지 않습니다.

메모 하나가 초안이 되는 과정은 여섯 단계입니다. AI(대형 언어 모델)가 하는 것은 3번과 5번뿐이고, 나머지는 우리가 직접 짠 프로그램 규칙이 맡습니다.

1. **개인정보 가리기**: 이름·호실·연락처를 "\[수급자A\]" 같은 표시로 바꿉니다. (프로그램)
2. **용어집 찾아 붙이기**: 메모에 나온 단어와 관련된 공식 요양 용어를 찾아 AI에게 함께 줍니다. (프로그램)
3. **기록지 칸 채우기**: AI가 칸마다 내용, 그 근거가 된 메모 문장, 상태(기재·미기재·확인 필요)를 적어 냅니다. (AI)
4. **검사하기**: 근거 문장이 정말 메모에 있는지, 숫자가 메모와 같은지, "많이" 같은 애매한 말이 남아 있는지 확인합니다. 통과하지 못한 칸은 '확인 필요'로 바뀝니다. (프로그램)
5. **모국어로 되돌리기**: 초안을 베트남어로 다시 설명해 요양보호사가 확인할 수 있게 합니다. (AI)
6. **이름 되돌리기**: 화면과 PDF에 보여 줄 때만 "\[수급자A\]"를 실명으로 바꿉니다. 저장은 가명 상태와 대응표로 합니다. (프로그램)

AI를 끄면 3번과 5번이 멈춰서 서비스가 성립하지 않습니다. 반대로 AI가 틀려도 4번 검사와 사람의 확인이 걸러냅니다. 두 가지 모두 발표에서 강조할 포인트입니다.

## 개인정보는 어떻게 지키나

외부 AI에는 이름 없는 내용만 보내고, 실명 연결은 기관 서버 안에서만 합니다. 담당자는 평소처럼 어르신 실명으로 기록을 찾고 관리합니다.

| 단계 | 어디서 | 이름이 보이나 |
| --- | --- | --- |
| 메모 입력 | 기관 서비스 안 | 보인다 (어르신을 먼저 선택) |
| AI로 보낼 때 | 외부 AI | 안 보인다 ("\[수급자A\]"로 대체) |
| 초안 돌아옴 | 기관 서비스 안 | 다시 보인다 (실명으로 복원) |
| 검토·승인·보관 | 기관 서비스 안 | 보인다 (권한 있는 사람만) |

- 근거: 표준교재 9장은 기록을 외부로 반출하지 말고, 서비스 관련자만 열람하게 하라고 규정합니다. 돌봄 기록의 건강 정보는 개인정보보호법상 민감정보입니다.
- 이번 프로젝트는 개발·시연·테스트 모두 가상 어르신과 가상 사례만 씁니다.
- 화면에는 "AI가 만든 초안입니다"를 표시합니다(인공지능기본법 고지 의무 대응).
- 표준교재 본문은 서비스에 넣지 않고, 팀이 정리한 규칙과 용어집만 씁니다(교재 이용 조건).

## 성공 판단 기준과 평가 방법

같은 메모를 세 가지 방식으로 기록지에 옮겨 비교합니다. 케어브릿지가 누락·지어낸 내용·확인 시간에서 다른 두 방식보다 나으면 성공입니다.

**비교하는 세 가지 방식**

- 기존 방식: 요양보호사가 한국어로 직접 쓰고, 담당자가 고친다
- 일반 번역기: 메모를 번역기로 번역해 기록지에 옮긴다
- 케어브릿지: 이 서비스로 초안을 만들고 확인한다

비교는 두 번 합니다. 자동 평가에서는 '일반 번역기' 자리에 같은 AI에 "번역해서 칸을 채워라"만 시킨 단순 방식을 넣습니다. 번역기를 쓰고 사람이 옮기는 방식과 기존 방식은 사용자 테스트에서 시간을 재며 비교합니다.

| 지표 | 재는 방법 | 목표(팀 확정 필요) |
| --- | --- | --- |
| 필수 항목 누락률 | 정답 기록지에 있는 내용 중 빠진 것의 비율 | 일반 번역기의 절반 이하 |
| 지어낸 내용 | 메모에 없는데 초안에 들어간 내용의 건수 | 0건 |
| 값 오류 | 내용이 틀린 칸의 건수(예: 식사량 1/2을 전량으로) | 일반 번역기보다 적게 |
| 담당자 확인 시간 | 검토 화면을 연 때부터 승인까지 걸린 시간(초). 서비스가 자동 기록 | 기존 방식보다 짧게 |
| 담당자 수정 칸 수 | 승인 전 담당자가 고친 칸의 개수 | 기존 방식보다 적게 |
| 사용 의향 | 테스트 참여자 설문(5점 척도) | 4점 이상 |

**평가 데이터**

- 개발용: AI로 만든 가상 메모 100\~200건과 정답 기록지. 일부를 원어민이 검수
- 최종 평가용: 유학생이 상황 카드를 보고 직접 쓴 메모 20\~30건. 개발에는 쓰지 않고 마지막 평가에만 씁니다
- 실제 메모를 모으지 못하면 성과보고서에 '합성 데이터 기준 결과'라고 밝힙니다

사용자 테스트 참여자에게는 참여 동의서를 받고, 이름 대신 참여자 번호로 기록합니다. 설문 답변과 소요 시간 외의 개인정보는 받지 않습니다.

## 수익 모델 요약

돈은 요양기관이 내고, 요양보호사는 무료로 씁니다. 기관이 돈을 낼 이유는 '담당자가 외국인 직원의 기록을 다시 쓰는 시간'과 '기록 누락에 따른 평가·사고 위험'을 줄이는 것입니다.

| 수익원 | 대상 | 방식 |
| --- | --- | --- |
| 기관 구독 | 외국인 요양보호사를 고용한 요양기관 | 기본료 + 외국인 요양보호사 1인당 월 요금. 기존 요양 기록 프로그램(ERP)이 월 1만\~3만 원대라 그 수준에서 출발(가정) |
| ERP 제휴 | 이지케어·케어포 등 기록 프로그램 업체 | 추가 기능(애드온) 판매 수익 배분 또는 이용료 |
| 교육용 라이선스 | 외국인 요양보호사 양성대학, 요양보호사 교육원 | 실습 기록 연습용 연간 라이선스 |
| 공공 사업 | 지자체·사회서비스원 | 외국인 돌봄인력 지원 시범사업 위탁 |

**단계별 계획(가정)**

1. 1년차: 공모전 상금·지원금으로 개발, 양성대학·요양시설 무료 시범 운영
2. 2년차: 양성대학 교육용 라이선스, 지자체 시범사업으로 첫 매출
3. 3년차: 2028년 하반기 양성대학 졸업생 현장 투입에 맞춰 ERP 제휴로 기관 구독 확대, 기록이 어려운 내국인 요양보호사까지 대상 확장

외국인 요양보호사를 고용한 기관만 보면 연 5\~15억 원 수준의 작은 시장입니다. 전체 장기요양기관(2025년 2만 9,734곳)으로 넓히면 연 약 107억 원입니다. 두 수치 모두 요금과 도입률을 가정한 추정치입니다.
