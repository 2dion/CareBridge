# 케어브릿지 기획안 v0.4.1 (제안)

2026-10-16 · 근거는 각 문장 끝 각주와 맨 아래 [참고 자료](#참고-자료)에 있습니다. 주요 자료: [10/15 멘토링 회의록](../../회의록/2026-10-15-멘토링.md), [최소구조설계 v0.1](../설계/2026-10-16-최소구조설계-v0.1.md), 10/12 공모전 답변서 요약(레포 밖 공유 자료), [기획서 V1 (PM용)](../기획/기획초안/2026-10-16-PM용기획서-기획담당.md)

> **상태: 팀 결정 전 제안.** 각 항목의 "제안"은 Claude의 추천이고, 팀이 ✅/✏️ 로 표시해 확정하면 이 문서가 기준이 됩니다.

**v0.4.1에서 바뀐 점 (v0.4 대비)**
- 결정 3: 관리자 화면을 **"받은 기록 확인 화면"** 3가지 구성(목록·검토·처리)으로 구체화하고, 교육 모드에서는 강사 화면으로 겸용.[^team-admin2]
- 결정 5·7: 해외 사례(호주 Buddy)에서 가져온 **"이 뜻 맞아요?" 확인**과 **지침 질문("이럴 땐 어떻게 해요?")** 추가.[^buddy-cd]
- 결정 14 추가와 새 절: [비슷한 서비스와의 차별점](#비슷한-서비스와의-차별점) (스마트장기요양, 호주 Buddy).[^team-diff]
- 결정 13: 크로스 플랫폼 검토 추가, 담당자 화면을 일렉트론 데스크탑 앱(브라우저는 대안)으로 변경.[^team-xplat]
- 기준 서식 목록: 제12~14호 개정 내용 확인 결과 반영(변경 칸 미확인, ⚠️ 유지), 화면 ID에 화면 이름 병기.[^team-forms2]
- 결정 7: [표현 충돌 처리 규칙](#표현-충돌-처리-규칙) 추가.[^team-conflict]
- 결정 2: 베트남어가 나오는 모든 곳에 확인용 한국어를 함께 표시.[^team-vi-ko]
- 평가 지표에 "기록 1건 작성 시간" 추가, 팀 확인 사항에 베트남어 검수자·언어 선택 근거 추가.

**v0.3 → v0.4에서 바뀐 점**
- 결정 4: 서비스 범위를 **재가급여 + 시설급여**로 넓히고, MVP 서식은 시설급여 1종으로 유지.[^team-scope]
- 결정 11~13 추가: 법정 서식 기반 확장 방향 3가지, 캡처 방지, 사용 기기.[^team-v04]
- 결정 1·5: 버디 대화를 **한국어 중심, 모국어 보조**로 변경.[^team-ko]
- 새 절: [법정 서식 기반 확장 방향](#법정-서식-기반-확장-방향), [캡처 방지와 사용 기기](#캡처-방지와-사용-기기).

## 확정 방법 (한 줄)

**아래 결정 14개만 이번 주 안에 팀 회의 한 번으로 못 박고, 나머지는 개발하면서 정한다.** 10/22 멘토링 화면 시연에 필요한 것부터 순서대로 놓았습니다. 1~6이 정해지면 바로 개발에 들어갈 수 있습니다.

새 기획의 출발점은 교육용 v0.2가 아니라 **현장용 v0.1**입니다. v0.1에 "한국어 중심 + 모국어 보조, 듣기/말하기"를 더하고 관리자 흐름은 핵심(M3(승인 대기 목록)·M4(기록 검토)·M6(승인))만 남기면 v0.3이 됩니다. v0.2(교육생·강사 구조)는 보관만 합니다.

### 표현 충돌 처리 규칙

결정 7의 보충입니다.[^team-conflict] 기록은 "공식화된 용어로, 애매한 표현은 구체적으로" 쓰는 것이 교재 원칙이므로,[^tb-principle] 사용자의 말과 교재·용어집이 다를 때 AI는 아래 순서로 처리합니다.

**근거 우선순위:** ① 법정 서식의 칸 이름·선택지(예: "1/2 미만") → ② 표준교재 본문 용어 → ③ 용어집(영어, 베트남어 근거는 확보 예정) → ④ 그 밖의 AI 일반 지식은 **기록 문장에 쓰지 않음**.[^m-data]

| 경우 | 예시 | AI가 하는 일 | 화면에 남는 것 |
|---|---|---|---|
| 관용·구어 표현을 공식 용어로 옮길 수 있음 | "밥을 깨작깨작 드셨어요" | 교재 표현으로 바꿔 쓰기 전에 "반보다 적게 드셨다는 뜻이에요?"로 확인(결정 5-⑥) | 기록: "1/2 미만". 근거: 원래 표현. "AI 변환" 표시(결정 3-②) |
| 관용 표현의 뜻이 둘 이상 | "속이 안 좋대요"(배 아픔? 메스꺼움? 기분?) | **추정하지 않고** 보기 2~3개로 되묻기 | 답을 못 받으면 해당 칸 "확인 필요" |
| 관용 표현이 위험 신호처럼 들림 | "허리가 부러지겠대요", "죽겠대요" | 문자 그대로 사고·급변으로 기록하지 않음. "실제로 넘어지거나 다치셨어요?"로 확인한 뒤에만 "보고 필요" 안내 | 확인 결과만 기록, 원래 표현은 근거로 |
| 교재 용어와 용어집 번역이 다름 | (가상 예시) 교재 "체위변경"과 용어집 번역어가 서로 다른 경우 | **실행 중에 AI가 고르지 않음.** 개발 단계에서 "용어 대조표"로 미리 정리해 교재 용어를 기록에 쓰고, 용어집 표현은 모국어 풀이에만 씀 | 용어 카드: 교재 용어 + 풀이 + 출처 쪽수 |
| 교재·용어집 어디에도 없는 표현 | 사투리, 신조어, 베트남어 관용구 | 기록에 새 용어를 만들어 넣지 않음. 사용자 표현을 그대로 근거로 두고 쉬운 말로 다시 물음 | 해당 칸 "확인 필요", 담당자가 판단 |
| 사용자가 AI 변환을 거부 | "그런 뜻 아니에요" | 사용자 말을 기준으로 다시 묻고, 그래도 안 맞으면 원문 그대로 둠 | "작성자가 변환 거부" 표시, 담당자 확인 |

**운영 원칙**
- 바뀐 칸은 항상 원래 표현과 함께 남깁니다. Buddy가 직역 대신 뜻을 옮기되 제출 전 원문·번역을 확인하게 한 방식과 같습니다.[^buddy-cd][^buddy-ix]
- 용어 대조표에서 정리되지 않은 충돌은 베트남어 검수자와 현장 검수자가 판정하고, 판정 결과를 대조표에 추가합니다.[^v1-review]
- 교육 모드에서는 같은 규칙으로 "이 표현은 기록에서는 이렇게 써요"를 용어 카드로 보여 줘서, 충돌 자체가 학습 장면이 됩니다.

## 캡처 방지와 사용 기기

### 기기별로 캡처를 어디까지 막을 수 있나

| 기기 | 스크린샷 | 화면 녹화·미러링 | 할 수 있는 것 |
|---|---|---|---|
| 안드로이드 앱 | **차단 가능** | **차단 가능** | OS의 보안 화면 설정(FLAG_SECURE). 최근 앱 미리보기도 가려짐 |
| iOS 앱 | 차단 불가, **찍은 뒤 감지만** | 녹화·미러링 중이면 **화면을 가릴 수 있음** | 스크린샷 감지 시 경고·기록, 녹화 감지 시 내용 가림 |
| 웹 (PC·모바일 브라우저) | **차단 불가** | **차단 불가** | 억제만: 사용자명·시각 워터마크, 창을 떠나면 내용 흐리게, 인쇄 차단, 오른쪽 클릭·복사 제한, 열람 기록, 자동 로그아웃 |
| 데스크탑 앱 | 윈도우·맥에서 캡처 제외 설정 가능 | 같음 | 일부 캡처 도구에서는 안 먹힐 수 있음(확인 필요). 별도 앱을 하나 더 만드는 비용이 큼 |
| 모든 기기 공통 | 다른 폰 카메라로 화면을 찍는 것은 **못 막음** | | 그래서 화면에 보이는 개인정보를 줄이는 게 가장 확실함 |

> 이 표는 각 OS가 공식으로 제공하는 기능에 대한 일반적인 내용이고, 우리 기술 스택에서 직접 시험해 본 결과는 아닙니다. 개발 담당이 하루 안에 실기기로 확인해 주세요.

### 추천 구성

- 아래 구성의 개발 방식은 [크로스 플랫폼 검토](#크로스-플랫폼-검토)를 따릅니다.
- **보호사·교육생: 모바일 앱.** 캡처를 실제로 막을 수 있는 건 앱뿐이고, 마이크(STT)와 스피커(TTS)도 앱에서 가장 안정적입니다. 한 코드로 안드로이드와 iOS를 함께 만드는 방식(예: React Native·Expo)을 쓰고, 검증은 캡처 차단이 완전한 **안드로이드부터** 합니다. 기술 선택은 개발 담당이 정합니다.
- **담당자: 데스크탑 앱(일렉트론), 브라우저는 대안.** v0.1 전제대로 PC로 검토합니다.[^v01-device] 일렉트론으로 감싸면 캡처 제외 설정으로 차단할 수 있고, 브라우저로 열 때는 워터마크·열람 기록·자동 로그아웃으로 억제합니다. 어느 쪽이든 이름은 가명·부분 가림으로 보여 줍니다.
- **가족: 설치 없는 웹 링크.** 본인 확인 후 열리고 기한이 지나면 만료되는 링크로, 요약만 담습니다.
- **공통 원칙:** 어르신 이름은 기본 부분 가림(예: 김○○), 원문 대화·음성은 기본 숨김,[^v01-device] 음성 파일 저장 안 함.[^qa]

### 크로스 플랫폼 검토

**왜 검토하나:** 보호사·교육생(휴대폰), 담당자(PC), 가족(링크) 세 기기를 2주 안에 따로 만들 수는 없습니다.[^team-xplat] 코드 하나로 여러 기기를 덮되, 캡처 차단(결정 12)과 듣기·말하기(결정 6)가 각 기기에서 되는지가 기준입니다.

> 아래 표는 각 프레임워크의 일반적인 기능에 대한 내용이고, 우리 환경에서 직접 시험해 본 결과는 아닙니다. 특히 캡처 차단과 베트남어 STT는 개발 담당이 실기기로 확인해야 합니다.

| 선택지 | 덮는 기기 | 코드 공유 | 캡처 차단 | 듣기(TTS)·말하기(STT) | 배우는 비용 | 2주 일정 위험 |
|---|---|---|---|---|---|---|
| **A. 웹 하나 + Capacitor(모바일) + 일렉트론(데스크탑)** | 휴대폰·PC·브라우저 전부 | 가장 높음 (화면 코드 1벌) | 안드로이드: 플러그인으로 차단. iOS: 녹화 가림·감지만. 데스크탑: 일렉트론 캡처 제외 설정 | 브라우저 음성 기능은 기기마다 차이가 있어, 앱으로 감쌀 때 기기 음성 기능을 쓰는 플러그인 필요 | 낮음 (웹 기술 그대로) | 낮음. 브라우저 시연을 먼저 하고 포장은 나중에 |
| B. React Native(Expo) 모바일 + 담당자 웹 | 휴대폰 + 브라우저 | 중간 (모바일과 웹 화면이 따로) | 안드로이드 차단, iOS 녹화 가림·감지 (공식 모듈 있음). 데스크탑은 억제만 | 모바일 음성이 안정적 | 중간 | 중간. 화면을 두 벌 만들어야 함 |
| C. Flutter | 휴대폰·PC·브라우저 전부 | 높음 | 플러그인으로 안드로이드 차단, iOS 일부, 데스크탑 별도 | 플러그인 | 높음 (새 언어 Dart) | 높음. 팀이 처음이면 위험 |

| E. 반응형 웹만 | 브라우저 | 최고 | **불가** (억제만) | 브라우저 음성 기능에 의존 | 최저 | 최저. 대신 "캡처 차단" 시연 불가 |

**추천: A안을 단계적으로.**
1. **10/22 멘토링까지:** 웹 하나로 보호사 화면(B2 오늘 담당 어르신 목록 ~ B5 마무리 요약 확인)과 담당자 화면(M3 승인 대기 목록 ~ M6 승인)을 만들고, 휴대폰·PC 브라우저로 시연합니다. 포장하지 않아도 화면 확인에는 충분합니다.
2. **공모전 제출(10/31) 전:** Capacitor로 **안드로이드 앱**을 만들어 캡처 차단과 기기 음성(STT·TTS)을 확인합니다. 시연용 데모 모드(차단 끄기)도 이때 넣습니다.
3. **파이널 제출(11/8) 전, 시간이 남으면:** 담당자 화면을 **일렉트론**으로 감싸 PC 캡처 차단을 보여 주고, iOS 빌드를 시험합니다.
4. 가족 리포트는 계속 **웹 링크**로 둡니다(포장하지 않음).

**A안의 약점과 대응**
- 웹 화면을 앱으로 감싸면 화면 전환·키보드 반응이 네이티브 앱보다 덜 매끄러울 수 있습니다. 대화 화면 하나가 핵심이라 영향은 작다고 봅니다(추론).
- 포장할 때마다 설치 파일 서명·배포가 따로 듭니다(안드로이드 APK, 윈도우·맥 설치 파일). 시연은 APK 직접 설치로 충분하고, 스토어 등록은 하지 않습니다.
- 팀에 React Native 경험이 있다면 B안이 모바일 품질 면에서 낫습니다. **기술 선택은 개발 담당이 팀 경험을 보고 최종 결정**합니다.

### 시연 때 주의

안드로이드에서 캡처 차단을 켜면 **화면 미러링·녹화도 검은 화면**이 됩니다. 공모전·파이널 시연에서 폰 화면을 띄우려면 합성 데이터일 때만 캡처 방지를 끄는 **데모 모드**가 필요합니다. 발표에서는 "실제 운영에서는 켜져 있다"를 한 장면으로 보여 주면 됩니다.

### 일정이 부족할 때의 대안

위 추천 순서에서 2~3단계를 건너뛰면 E안(반응형 웹만)이 됩니다.

모바일 앱 빌드가 부담되면, MVP를 **반응형 웹 하나**로 만들고 캡처는 억제 기능만 넣은 뒤 "운영 단계에서 모바일 앱으로 감싸 차단"을 로드맵으로 둘 수 있습니다. 개발은 빨라지지만, 시연에서 "캡처 방지가 된다"고 보여 줄 수는 없습니다.

- 표준교재 원본과 영어 용어집은 확보됨.[^m-data] 그 외에 **베트남어 용어** 근거를 어디서 가져올지 (용어 카드와 할루시네이션 방지에 필요)
- 개발 담당의 프레임워크 최종 선택(A안 Capacitor+일렉트론 vs B안 React Native, 팀 경험 기준)과 캡처 차단·베트남어 STT 실기기 확인 (결정 13)
- STT·TTS 기술 선택(브라우저 내장 vs 외부 API)과 베트남어 인식 품질: 개발 담당이 하루 안에 시험해 보고 결정
- 멘토가 화면으로 보여 준 국민건강보험 기록 앱이 스마트장기요양이 맞는지 (추정, 다음 멘토링에서 확인)[^m-data]
- **베트남어 검수자** 확보: 번역·용어 카드 검수용 (V1 검토 때부터 미확보)[^v1-review]
