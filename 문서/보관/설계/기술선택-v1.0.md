# 케어브릿지 기술 선택 v1.0 (확정)

Oct 16, 2026 · @2dion

## 요약

기획안 v0.5 결정 12(반응형 웹앱 하나)를 따라, **TypeScript 코드 한 벌로 화면·서버·배포를 끝내는 조합**을 추천합니다.\[1\] 10/16 팀(2dion)이 이 조합으로 확정했습니다.

| 부분 | 추천 | 한 줄 이유 |
| --- | --- | --- |
| 화면+서버 | Next.js (TypeScript) 반응형 웹앱 | 작성자 폰과 담당자 PC를 한 코드로, 서버 API도 같은 프로젝트에 |
| 배포 | Vercel | GitHub에 올리면 자동 배포, 시연용 주소 바로 생김 |

| 녹음 | 브라우저 MediaRecorder, 시작·정지 버튼 | 결정 4: 자동 정지 없음\[2\] |
| 음성→글자 (STT) | 서버 STT: OpenAI 음성 인식 API (대안 Google STT) | 브라우저 내장 인식은 iOS·Firefox에서 불안정\[3\] |
| 항목 채우기·번역·도우미 | Claude API (정해진 JSON 형식으로 답받기) | 9개 항목을 항목별 근거 문장과 함께 받음 |
| 듣기 (TTS) | 브라우저 내장 음성 먼저, 부족하면 서버 TTS | 무료, 한국어·베트남어 지원 |

## 구성도

&#91;embedded content: 시스템 구성 · 브라우저 2개, 서버 1개, 외부 서비스 3개\]

폰과 PC는 모두 서버만 부르고, STT·Claude·DB는 서버만 부릅니다. 그래서 API 키가 브라우저에 나가지 않고, 음성 삭제와 AI 답 형식 검사를 한 곳에서 처리합니다. 이 그림은 평가 항목의 ‘시스템 아키텍처 다이어그램’의 초안으로 쓸 수 있습니다.\[5\]

## 부분별 선택과 이유

고르는 기준은 세 가지입니다. ① 10/31 공모전까지 약 2주 반 안에 돌아가는 시연본을 만들 수 있는가, ② 코디세이 평가의 기술 완성도 항목(아키텍처 다이어그램, 예외 처리, 비용 효율, “즉시 배포가 가능한 수준”)을 채울 수 있는가,\[5\] ③ 기획안 v0.5의 결정(반응형 웹앱 하나, 수동 녹음, 한국어 최종 기록, 기관별 분리)과 맞는가.\[1\]\[2\]

### 1. 화면+서버: Next.js (TypeScript)

- **이유:** 작성자 화면(폰), 담당자 화면(PC), 서버 API(음성 업로드, AI 호출)를 한 프로젝트 한 언어로 만듭니다. AI API 키는 서버 쪽에만 두어 브라우저에 노출되지 않습니다.\[8\]
- **근거:** v0.5 결정 12가 “반응형 웹앱 하나”이고, 나중에 캐처 방지가 필요하면 같은 웹 코드를 Capacitor(안드로이드)·일렉트론(PC)으로 감쌉니다.\[1\] 웹 코드가 기본이어야 이 길이 열려 있습니다.
- **대안:** React 화면 + Python(FastAPI) 서버는 AI 라이브러리가 많지만, 코드 두 벌과 배포 두 곳을 관리해야 합니다. 이번 기능은 모두 외부 AI API 호출이라 Python이 꼭 필요하지 않습니다. Flutter·React Native는 v0.4.1에서 팀 학습 부담과 화면 두 벌 문제로 뒤로 밀렸습니다.\[9\]
- **확정:** 10/16 이 조합으로 확정(2dion).

### 2. 배포: Vercel

- **이유:** GitHub 저장소에 올리면 자동으로 배포되고, 브랜치마다 미리보기 주소가 생깁니다.\[10\] 멘토가 요청한 “다음 주 보이는 화면”을 주소 하나로 보여줄 수 있고, 평가의 “즉시 배포 가능” 항목에 바로 답이 됩니다.\[5\]
- **근거:** Next.js를 만든 회사의 서비스라 추가 설정이 거의 없습니다.
- **주의:** 서버 함수에 실행 시간 제한이 있어, 1분 넘는 음성은 STT를 나눠 보내거나 처리 중 화면을 보여 줍니다(아래 ‘음성 기록 처리 흐름’).

### 3. DB·로그인·파일: Supabase (Postgres)

- **이유:** 기록·어르신·계정은 관계가 분명한 데이터라 표(SQL) DB가 맞고, 로그인과 파일 저장이 같이 제공됩니다.
- **근거:** ‘행 단위 권한(RLS)’으로 “내 기관 데이터만 보기”를 DB 안에서 강제합니다.\[7\] 이것이 교육용 기관 분리(사용자 결정 10/16)와 실제 어르신 개인정보 보호를 가장 적은 코드로 지키는 방법입니다.\[11\]
- **대안:** Firebase는 문서형 DB라 ‘기록-항목-검토’ 같은 연결 조회가 불편합니다.
- **주의:** 무료 요금제는 일주일 동안 쓰지 않으면 일시 중지됩니다. 시연 전날 한 번 열어 둡니다.\[7\]

### 4. 녹음: MediaRecorder, 시작·정지 버튼

- **이유:** 브라우저 표준 녹음 기능이라 추가 설치가 없고, 작성자가 시작·끝을 직접 누르는 결정 4와 맞습니다.\[2\]
- **근거:** 크롬·삼성 인터넷·사파리(iOS 포함)에서 모두 지원됩니다. 다만 파일 형식이 브라우저마다 달라(크롬 webm, 사파리 mp4) 둘 다 STT가 받는지 확인해야 합니다.\[6\]

### 5. 음성→글자: 서버 STT (OpenAI 음성 인식 API, 대안 Google STT)

- **이유:** 녹음 파일을 서버로 보내 글자로 바꾸면, 브라우저 종류와 상관없이 결과가 같습니다. 한국어와 베트남어가 섞인 말도 한 번에 처리됩니다.
- **근거:** 브라우저 내장 인식(Web Speech API)은 파이어폭스가 지원하지 않고 iOS 사파리에서 자주 끊깁니다.\[3\] v0.5 문서 코멘트에서 같은 이유로 서버 STT를 추천했습니다.
- **대안:** Google STT는 언어 코드를 미리 지정해야 하고 설정이 더 복잡합니다. 두 서비스 모두 호출 부분만 바꾸면 교체할 수 있게 만듭니다.
- **확인:** 사투리·외국인 발음 한국어 인식 품질은 문서로 알 수 없어, 팀원이 직접 샘플 5개를 녹음해 비교합니다.

### 6. 항목 채우기·번역·도우미: Claude API

- **이유:** 받아쓴 글에서 9개 항목을 채우고, 항목마다 상태(관찰/언급 없음/확인 필요)와 근거 문장을 정해진 JSON 형식으로 돌려받습니다. 형식이 고정되면 화면이 깨지지 않고, 형식이 틀리면 다시 요청하는 예외 처리를 넣을 수 있습니다.
- **근거:** 평가 기준은 “AI API를 그대로 가져다 쓴 수준을 넘어”서는지를 봅니다.\[5\] 케어브릿지는 서식 항목 규칙, 확인 필요 판정, 항목별 근거, 담당자 검토를 팀이 직접 설계한 흐름 안에서 AI를 씁니다. 이 규칙은 따로 ‘AI 규칙’ 문서로 쓸 예정입니다.
- **비용:** 항목 채우기는 정확도가 중요해 중간 등급 모델, 번역·도우미는 가벼운 모델로 나눠 비용을 줄입니다.
- **대안:** OpenAI GPT도 같은 일을 할 수 있습니다. 팀이 이미 쓰는 API 키가 있으면 그쪽으로 가도 구조는 같습니다.

### 7. 듣기(TTS): 브라우저 내장 음성 먼저

- **이유:** 한국어·베트남어 문장을 읽어 주는 기능(speechSynthesis)은 무료이고 서버가 필요 없습니다.
- **주의:** 목소리 종류와 품질이 기기마다 다릅니다. 시연 기기에서 베트남어 목소리가 없으면 서버 TTS로 바꿉니다.

### 8. 도우미 자료 찾기: 교재 절 단위 저장 + 검색

- **이유:** 교재 상황 대처 매뉴얼을 제목·본문 단위로 DB에 넣고, 질문과 관련 있는 절 몇 개만 Claude에 건네 답하게 합니다. 답에 교재 쪽수를 함께 보여 줄 수 있습니다.
- **근거:** 교재는 공개 자료라 텍스트는 그대로 사용하고, 이미지는 확인 후 씁니다(사용자 10/16).\[4\] 처음에는 Postgres 기본 검색으로 시작하고, 답이 엉뚱하면 번역·의미 검색(벡터 검색, Supabase 내장 pgvector)을 붙입니다.

### 9. 인쇄·PDF: 인쇄용 화면 + 브라우저 인쇄

- **이유:** 승인된 기록을 별지 서식 모양의 인쇄용 화면으로 만들고, 브라우저 인쇄에서 ‘PDF로 저장’을 고르면 됩니다. 한글 글꼴이 깨지지 않고 추가 라이브러리가 필요 없습니다.
- **근거:** 인쇄·PDF는 MVP 포함으로 정해졌고,\[4\] v0.5대로 “공식 기록지 아님” 표시를 넣습니다.\[1\]

## 음성 기록 처리 흐름

1. **녹음 (작성자 폰):** W2 음성 메모에서 \[시작\]을 누르면 타이머와 빨간 표시가 나오고, \[정지\]를 누르면 끝납니다.\[2\]
2. **업로드 (서버):** 녹음 파일을 서버로 보냅니다. 네트워크가 끊기면 폰에 잠시 보관했다가 다시 보냅니다.
3. **글자로 바꾸기 (STT):** 서버가 STT를 부르고, 글자가 나오면 **음성 파일을 즉시 삭제**합니다(v0.5 결정 4).\[2\]
4. **항목 채우기 (Claude):** 받아쓴 글과 어르신 정보(시설/재가, 서식 종류)를 보내 9개 항목의 내용·상태·근거 문장을 받습니다. 형식이 틀리면 한 번 더 요청하고, 그래도 안 되면 ‘확인 필요’로 둡니다.
5. **확인 (작성자):** W3 기록 초안 확인에서 한국어가 위, 모국어가 아래로 보입니다. 빈 항목은 음성이나 글자로 보태고, 특이사항은 글자 수를 보여 200자를 넘으면 경고만 합니다.\[4\]
6. **검토 (담당자 PC):** R2 검토 화면에서 항목별 근거를 보고 승인하거나 돌려보냅니다. 승인본에서 인쇄·PDF를 만듭니다.

처리에는 수십 초가 걸릴 수 있어, 3\~4단계 동안 “글자로 바꾸는 중 → 항목 채우는 중”을 화면에 보여 줍니다. 실제 걸리는 시간은 팀이 샘플로 재서 기록합니다.

## 비용·위험·확인할 것

**비용:** Vercel과 Supabase는 무료 요금제로 시연이 가능합니다.\[7\]\[10\] STT와 Claude는 쓴 만큼 내는 방식이라, 계정마다 월 사용 한도를 걸어 둡니다. 같은 음성을 두 번 보내지 않게 하고, 시연용 데이터는 미리 만든 결과를 저장해 두면 비용과 시연 실패 위험이 함께 줄어듭니다.

| 위험 | 대응 |
| --- | --- |
| 외국인 발음 한국어를 STT가 잘못 받아씀 | 작성자가 W3에서 항목을 고치고, 담당자가 근거 문장을 보고 판단. 샘플 녹음으로 먼저 비교 |
| 아이폰 사파리 녹음 형식(mp4)이 다름 | 개발 첫 주에 아이폰·안드로이드 실기기로 녹음→STT를 끝까지 확인\[6\] |
| 서버 함수 실행 시간 제한 | 긴 녹음은 나눠 처리, 처리 중 화면 표시 |
| 웹에서는 화면 캐처를 막을 수 없음 | v0.5대로 MVP는 합성 데이터만 쓰고, 차단은 Capacitor 단계에서\[1\] |
| Supabase 무료 프로젝트 일시 중지 | 시연 전날 접속해 확인\[7\] |

**팀이 확인할 것**

-
- STT·Claude API 키와 결제 수단을 누가 준비하는지
- 시연 기기 (아이폰인지 안드로이드인지)
- 팀원 목소리 샘플 5개 (한국어, 베트남어 섞인 말 포함)
