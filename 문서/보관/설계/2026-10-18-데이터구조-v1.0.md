# 케어브릿지 데이터 구조 v1.0

Oct 16, 2026 · @2dion

## 요약과 표 목록

Supabase(Postgres)에 표 10개를 둡니다.\[1\] 모든 표에 `org_id`(기관)가 있고, DB 권한 규칙으로 “내 기관 데이터만” 보이게 합니다. 교육용 기관은 표를 따로 만들지 않고 `organizations.is_training` 표시 하나로 구분합니다.\[2\]

| 표 | 담는 것 | 쓰는 화면 |
| --- | --- | --- |
| organizations | 기관(일반/교육용) | R4 |
| profiles | 계정(작성자/담당자), 언어·글자 크기 | W0, W5, R4 |
| residents | 어르신(가명, 시설/재가) | W1, R4 |
| assignments | 작성자-어르신 담당 연결 | W1, R4 |
| records | 기록 1건(날짜, 상태, 받아쓴 글) | W1\~W4, R1\~R3 |
| record\_items | 기록의 9개 항목 | W3, R2 |
| record\_events | 이력(누가 언제 무엇을) | R2, R3 |
| comments | 강사 코멘트(교육용 기관) | R2, W3 |
| audio\_jobs | 음성 처리 상태(음성 파일은 글자로 바뀐 뒤 삭제) | W2 |
| manual\_sections | 교재 상황 대처 매뉴얼(절 단위) | W6 |

W6(도우미) 대화는 MVP에서 저장하지 않고 화면에만 둡니다. 개인정보가 담길 수 있고, 기록과 도우미는 별개이기 때문입니다.\[3\]

## 표별 칸

모든 표에 `id`(uuid)와 `created_at`이 있습니다. 아래에는 그 밖의 칸만 씁니다.

### organizations (기관)

| 칸 | 형식 | 뜻 |
| --- | --- | --- |
| name | text | 기관 이름 |
| is\_training | boolean | 교육용 기관이면 true. 만들 때 정하고 바꾸지 않음\[2\] |

### profiles (계정)

| 칸 | 형식 | 뜻 |
| --- | --- | --- |
| id | uuid | Supabase 로그인 계정 id와 같음 |
| org\_id | uuid | 소속 기관 (한 계정 = 한 기관) |
| role | worker / reviewer | 작성자 / 담당자. 교육용 기관에서는 교육생 / 강사로 보임 |
| name | text | 이름 |
| native\_lang | text | 모국어 코드. MVP는 vi(베트남어) 하나, 한국어만 쓰면 ko |
| font\_size | 1 / 2 / 3 | W5(내 정보) 글자 크기 |
| onboarded | boolean | W0(사용 안내)를 봤는지 |

### residents (어르신)

| 칸 | 형식 | 뜻 |
| --- | --- | --- |
| org\_id | uuid | 기관 |
| alias | text | 가명 (예: 김○○ 어르신) |
| care\_type | facility / home | 시설급여 / 재가 방문요양. 서식(별지 제16호 / 제12호)을 정함\[4\] |
| is\_synthetic | boolean | 합성 사례이면 true (데모·교육용은 모두 true) |

### assignments (담당 연결)

| 칸 | 형식 | 뜻 |
| --- | --- | --- |
| worker\_id | uuid | 작성자 |
| resident\_id | uuid | 어르신 |
| schedule | text | 방문·돌봄 시간 표시용 (예: “평일 14:00\~17:00”) |

### records (기록)

| 칸 | 형식 | 뜻 |
| --- | --- | --- |
| org\_id, resident\_id, worker\_id | uuid | 기관, 어르신, 작성자 |
| care\_date | date | 돌봄 날짜 |
| form\_type | 16 / 12 | 어르신 care\_type에서 정해져 기록에 고정 |
| status | draft / submitted / returned / approved | 작성 중 / 보냄 / 되돌아옴 / 승인됨 |
| transcript | text | 받아쓴 글 원문 (여러 번 녹음하면 이어 붙임) |
| transcript\_ko | text | 원문의 한국어 번역 (R2 왼쪽) |
| visit\_start, visit\_end | time | 재가 방문 시작·종료 (별지 제12호)\[4\] |
| form\_fields | jsonb | 서식에만 있는 칸 (아래 ‘서식 칸 대응’) |
| return\_reason, return\_reason\_native | text | 되돌린 사유와 모국어 번역 |
| submitted\_at, approved\_at | timestamptz | 보낸 시각, 승인 시각 |
| approved\_by | uuid | 승인한 담당자 |

### record\_items (9개 항목)

기록 1건에 항상 9행이 만들어집니다(빈 항목도 ‘언급 없음’으로).

| 칸 | 형식 | 뜻 |
| --- | --- | --- |
| record\_id | uuid | 기록 |
| item\_key | 아래 9개 중 하나 | visit\_time, support, meal, sleep, discomfort, medication, cognition, notes, next\_check |
| value\_ko | text | 한국어 내용 (최종 기록) |
| value\_native | text | 모국어 번역 (W3 아래쪽) |
| status | observed / not\_mentioned / needs\_check | 관찰 / 언급 없음 / 확인 필요 |
| evidence | text | 근거가 된 원문 문장 (없으면 빈칸) |
| reason | text | ‘확인 필요’인 이유 (예: 사투리 ‘걸신진다’ 뜻 짐작) |
| source | ai / worker / reviewer | 마지막으로 쓴 사람 |
| confirmed | boolean | 작성자가 \[맞아요\] 또는 고침 |
| detail | jsonb | 항목별 추가 값 (예: support의 지원별 분, cognition의 호전/유지/악화) |

### record\_events (이력)

| 칸 | 형식 | 뜻 |
| --- | --- | --- |
| record\_id, actor\_id | uuid | 기록, 한 사람 |
| type | created / ai\_filled / edited / submitted / returned / commented / approved | 무엇을 했는지 |
| item\_key | text | 항목을 고쳤으면 그 항목 |
| before, after | jsonb | 고치기 전과 후 (R2 수정 전후, R3 4단계 이력) |

### comments (강사 코멘트)

| 칸 | 형식 | 뜻 |
| --- | --- | --- |
| record\_id, author\_id | uuid | 기록, 강사 |
| item\_key | text | 항목에 단 코멘트면 그 항목, 전체면 빈칸 |
| body, body\_native | text | 코멘트와 모국어 번역 |

### audio\_jobs (음성 처리)

| 칸 | 형식 | 뜻 |
| --- | --- | --- |
| record\_id | uuid | 기록 |
| target | record / item / helper | 전체 기록 메모인지, 항목 보태기인지, 도우미 질문인지 |
| storage\_path | text | 임시 음성 파일 위치 (글자로 바뀐 뒤 파일 삭제, 칸도 비움)\[5\] |
| status | uploaded / transcribing / filling / done / failed | W2 처리 중 표시에 씀 |
| error | text | 실패 이유 |

### manual\_sections (교재 매뉴얼)

| 칸 | 형식 | 뜻 |
| --- | --- | --- |
| chapter, title | text | 장·절 제목 |
| page | text | 교재 쪽 (W6 출처 표시) |
| body | text | 본문 텍스트 (이미지 제외)\[6\] |
| search | tsvector | 검색용 (body에서 자동 생성) |

이 표는 모든 기관이 함께 읽어서 `org_id`가 없습니다.

## 기록 상태 변화

`records.status`는 아래 길로만 바뀝니다. 서버가 이 표에 없는 변경을 거절하고, 바뀔 때마다 `record_events`에 한 줄을 남깁니다.

| 지금 | 누가 | 무엇을 하면 | 다음 |
| --- | --- | --- | --- |
| (없음) | 작성자 | W1에서 어르신을 고르고 녹음 시작 | draft |
| draft | 작성자 | W3 \[담당자에게 보내기\] | submitted |
| submitted | 담당자 | R2 \[되돌리기\] (사유 필수) | returned |
| submitted | 담당자 | R2 \[승인\] | approved |
| returned | 작성자 | W3에서 고친 뒤 \[보내기\] | submitted |
| approved | — | 변경 불가 (읽기·인쇄만) | — |

**교육용 기관:** 강사는 \[승인\]이 없고 \[코멘트 보내기\]만 있습니다. 코멘트를 보내면 submitted → approved로 바뀌고 화면에는 ‘코멘트 받음’으로 보입니다. 상태 값을 늘리지 않기 위한 선택입니다.\[2\]

## 권한 규칙 (기관 분리)

Supabase 행 단위 권한(RLS)으로 DB 안에서 강제합니다. 화면 코드가 실수해도 다른 기관 데이터는 나가지 않습니다.\[1\]

| 표 | 작성자 | 담당자 (일반 기관) | 강사 (교육용 기관) |
| --- | --- | --- | --- |
| residents | 내가 담당인 어르신만 읽기 | 같은 기관 전체 읽기·쓰기 | 같은 기관 전체 읽기·쓰기 |
| records, record\_items | 내 기록만. draft·returned일 때만 쓰기 | 같은 기관 전체. submitted일 때만 수정·승인 | 같은 기관 전체 읽기만 (수정 불가) |
| comments | 내 기록에 달린 것 읽기 | (쓰지 않음) | 쓰기·읽기 |
| record\_events | 내 기록 것 읽기 | 같은 기관 전체 읽기 | 같은 기관 전체 읽기 |
| manual\_sections | 읽기 | 읽기 | 읽기 |

- 어느 경우든 `org_id`가 내 계정의 `org_id`와 같아야 합니다.
- ‘담당자’와 ‘강사’는 같은 role(reviewer)이고, 기관의 `is_training`에 따라 수정·승인 권한이 달라집니다.\[2\]
- AI 호출(STT, Claude)은 서버에서만 하고, 서버도 요청한 사람의 권한으로 DB에 씁니다.\[1\]

## 서식 칸 대응

R2(검토 화면)의 ‘공식 기록지 칸 안내’와 R3(승인한 기록)의 인쇄 화면이 이 표를 씁니다. 별지 제16호는 v0.5 대응표를 따르고,\[3\] 별지 제12호는 교재판(2019.6.12) 기준입니다 ⚠️. 최신판(2025.12.12) 원문을 받으면 12호 줄만 다시 맞춥니다.\[4\]

| 항목 (item\_key) | 별지 제16호 (시설) | 별지 제12호 (재가) ⚠️ | 저장 위치 |
| --- | --- | --- | --- |
| ① 방문 시점 (visit\_time) | 서비스 날짜·시간 | 일정관리 시작·종료·총시간 | records.visit\_start·visit\_end |
| ② 제공 지원 (support) | 신체활동지원(세면·목욕·체위변경·이동), 배설 | 신체활동·인지활동·인지관리·정서·가사 및 일상생활 지원, 각 제공시간(분) | detail: 지원 칩 목록, 지원별 분 |
| ③ 식사 (meal) | 신체활동지원 > 식사(섭취량) | 식사 도움, 변화상태 식사기능 | detail: 섭취량 / form\_fields.meal\_trend |
| ④ 수면 (sleep) | 특이사항 | 특이사항 | value\_ko |
| ⑤ 불편감 표현 (discomfort) | 특이사항, 기능 변화 | 변화상태 신체기능, 특이사항 | form\_fields.body\_trend |
| ⑥ 복약 관찰 (medication) | 건강관리 > 투약관리 (조건부) | 최신판에서 확인 필요 | value\_ko |
| ⑦ 인지 변화 (cognition) | 특이사항(기능 변화) | 변화상태 인지기능 호전/유지/악화 | detail.trend → form\_fields.cognition\_trend\[5\] |
| ⑧ 특이사항 (notes) | 특이사항 (200자 복사) | 특이사항 | value\_ko |
| ⑨ 다음 확인사항 (next\_check) | 칸 없음 (기관 내부 메모) | 칸 없음 (기관 내부 메모) | value\_ko |

**form\_fields (재가 제12호 전용):** total\_minutes, body\_trend, meal\_trend, cognition\_trend (각각 improved / same / worse), toilet\_accidents(배변 실수 횟수). AI가 항목에서 채우고, 담당자가 R2에서 확인합니다.\[4\]
