# 케어브릿지 AI 규칙 v1.0

Oct 16, 2026 · @2dion

## AI가 하는 일

AI는 **초안만** 만듭니다. 작성자가 확인하고 담당자가 승인해야 기록이 됩니다.\[1\] 모든 AI 호출은 서버에서 합니다.\[2\]

| 일 | 언제 | 모델 | 결과가 가는 곳 |
| --- | --- | --- | --- |
| ① 받아쓰기 | W2 \[정지\] 뒤 | 서버 STT | records.transcript |
| ② 항목 채우기 + 번역 | 받아쓰기 직후 | Claude (중간 등급) | record\_items 9행, transcript\_ko |
| ③ 항목 보태기 | W3에서 한 항목을 다시 말하거나 썼을 때 | Claude (중간 등급) | 그 항목 1행만 |
| ④ 짧은 번역 | 되돌린 사유, 강사 코멘트 | Claude (가벼운 등급) | \*\_native 칸 |
| ⑤ 도우미 답 | W6에서 질문할 때 | Claude (가벼운 등급) + 교재 검색 | 화면에만 (저장 안 함)\[3\] |

모델 이름은 코드의 설정 한 곳에만 두어 바꾸기 쉽게 합니다.

## 항목 채우기: 입력과 출력

**서버가 보내는 것**

- 받아쓴 글 원문(한국어·베트남어가 섞일 수 있음)
- 어르신 정보: 급여 종류(시설/재가 → 별지 제16호/제12호), 조건(예: 와상이라 체위변경 대상, 복약 대상)\[4\]
- 작성자 모국어 코드(vi)
- 데모용 용어 목록(한국어-베트남어 고정 번역)

**돌려받는 것 (정해진 JSON)**

```json
{
  "transcript_ko": "원문 전체의 한국어 번역",
  "items": [
    {
      "item_key": "meal",
      "value_ko": "점심 죽을 1/2 이상 드심.",
      "value_native": "Bà ăn hơn một nửa bát cháo buổi trưa.",
      "status": "observed",
      "evidence": "점심에 죽 반 넘게 드셨어요",
      "reason": "",
      "detail": { "intake": "half_or_more" }
    }
  ],
  "form_fields": { "meal_trend": "same" }
}
```

- `items`는 항상 9개, 순서도 고정(visit\_time, support, meal, sleep, discomfort, medication, cognition, notes, next\_check).\[5\]
- `form_fields`는 재가(별지 제12호)일 때만 채웁니다(데이터 구조 v1.0 ‘서식 칸 대응’).\[5\]
- 예시의 베트남어는 형식을 보여 주려는 것이고, 검수되지 않았습니다.

**항목 보태기(③)** 는 같은 형식으로 `item_key` 하나와 새로 말한 글만 보내고, 그 항목 1개만 돌려받습니다. 다른 항목은 건드리지 않습니다.

## 상태 판정 기준

| 상태 | 언제 | 내용(value\_ko) | 근거(evidence) |
| --- | --- | --- | --- |
| 관찰 (observed) | 원문에 그 항목 내용이 분명히 있음 | 원문을 기록체로 정리 | 원문 문장 그대로 (필수) |
| 언급 없음 (not\_mentioned) | 원문에 그 항목 내용이 없음 | **빈칸** (지어내지 않음) | 빈칸 |
| 확인 필요 (needs\_check) | 아래 경우 중 하나 | 짐작한 내용 | 원문 문장 + reason 필수 |

**‘확인 필요’로 두는 경우**

1. **양·정도가 모호함:** “조금 드셨어요”처럼 서식 칸(전량 / 1/2 이상 / 1/2 미만)을 고를 수 없을 때.\[4\]
2. **사투리·일상 표현:** 뜻을 짐작했을 때. reason에 “‘걸신진다’를 ‘많이 먹는다’로 짐작”처럼 남김.\[1\]
3. **말이 서로 맞지 않음:** 예) “잘 주무셨다”와 “밤에 세 번 깨셨다”가 함께 있을 때.
4. **건강·안전 신호:** 낙상, 상처, 호흡·의식 변화, 심한 통증, 약을 안 드시거나 두 번 드신 경우. 특이사항에도 넣고 W3에 “담당자에게 바로 알리세요”를 보여 줌.
5. **숫자·이름이 불확실:** 약 이름, 시간, 횟수를 잘못 들었을 수 있을 때.
6. **재가 시간이 안 맞음:** 지원별 제공시간(분)의 합이 방문 시간보다 클 때(서버가 계산).

‘언급 없음’은 실수가 아닙니다. W3에서 작성자가 말로 보태거나, 정말 없었으면 \[맞아요\]로 두면 됩니다.\[1\]

## 쓰기 원칙

1. **지어내지 않는다.** 원문에 없는 내용은 어떤 항목에도 넣지 않음.
2. **관찰만 쓴다, 진단하지 않는다.** “치매가 심해짐”이 아니라 “오늘 날짜를 두 번 물으심”. 호전/유지/악화는 원문에 비교가 있을 때만, 없으면 ‘확인 필요’.\[6\]
3. **한국어 기록체.** “\~하심”, “\~드심”처럼 짧고 존칭을 일관되게. 교재 용어를 쓰고, 작성자가 말한 사투리는 근거에만 남김.\[4\]
4. **특이사항은 200자 안쪽을 목표로.** 넘어도 자르지 않고 그대로 두며, 화면이 경고함.\[7\]
5. **사람을 이름으로 부르지 않는다.** 어르신은 ‘어르신’, 가족은 ‘보호자’. 원문에 실명이 나오면 기록에는 옮기지 않음.
6. **다음 확인사항은 제안일 뿐.** “내일 아침 다시 체온 확인”처럼 원문에서 나온 할 일만.

## 도우미·번역 규칙

**W6(도우미)**

1. 질문으로 교재 매뉴얼(manual\_sections)을 검색해 상위 몇 절만 Claude에 건냅니다. 답은 **그 절에 있는 내용만**, 끝에 장·쪽 출처.\[2\]\[3\]
2. 교재에서 찾지 못하면 “교재에서 찾지 못했어요. 담당자에게 물어보세요.” 상식으로 채우지 않음.
3. 건강·안전 질문(낙상, 호흡 곤란 등)은 교재 답보다 먼저 “담당자에게 바로 보고하세요”.
4. 사투리·일상 표현 풀이는 ‘짐작’이라고 밝힘. 여러 뜻이 가능하면 모두 보여 줌.
5. 기록을 고치거나 대신 쓰지 않음. 기록과 도우미는 별개.\[8\]
6. 답은 한국어 위, 모국어 아래. 쉬운 말로 짧게.

**번역**

1. 최종 기록은 한국어. 베트남어는 작성자가 이해하도록 돕는 보조입니다.\[1\]
2. 데모용 용어 목록(예: 체위변경, 와상, 투약)은 정해진 번역만 쓰도록 프롬프트에 넣습니다.
3. 베트남어 검수자가 없으므로 팀이 직접 검증합니다.\[7\] 방법: 베트남어 번역을 다시 한국어로 되돌려(역번역) 뜻이 달라지는 곳을 표시하고, 용어 목록을 고칩니다.

## 서버 검사와 예외 처리

AI 답을 그대로 믿지 않고 서버가 검사한 뒤 DB에 넣습니다. 코디세이 평가의 ‘예외 처리’ 항목에 해당합니다.\[9\]

| 검사 | 통과 못 하면 |
| --- | --- |
| JSON 형식과 9개 항목이 다 있는지 | 한 번 다시 요청. 또 실패하면 9개 모두 ‘확인 필요’ + 원문을 그대로 보여 줌 |
| evidence가 원문에 실제로 있는 문장인지 (문자열 비교) | 그 항목을 ‘확인 필요’로 낮추고 reason에 “근거를 찾지 못함” |
| ‘관찰’인데 evidence가 비었는지 | ‘확인 필요’로 낮춤 |
| ‘언급 없음’인데 value\_ko가 있는지 | value\_ko를 비움 |
| 재가: 제공시간 합 ≤ 방문 시간인지 | ‘제공 지원’을 ‘확인 필요’로 |
| STT·Claude 응답 시간 초과, 연결 오류 | audio\_jobs.status = failed, W2에 \[다시 시도\]와 \[글로 쓰기\] |
| 작성자가 고친 항목 | AI 보태기가 덮어쓰지 않음 (source = worker 이면 건너뜀) |

**비용 아끼기:** 같은 음성을 두 번 보내지 않음(audio\_jobs로 확인), 항목 보태기는 한 항목만, 짧은 번역·도우미는 가벼운 모델.\[2\]

## 품질 확인 방법

팀이 직접 만든 **합성 사례와 정답표**로 AI 결과를 잽니다. 숫자는 팀이 재서 채웁니다.

1. 합성 사례 10개를 만듭니다: 시설 5개, 재가 5개. 각 사례에 한국어만 / 베트남어 섞임 / 사투리 포함 / 건강 신호 포함을 고루 넣습니다.
2. 사례마다 정답표(9개 항목의 올바른 상태와 내용)를 팀이 작성합니다.
3. 팀원이 사례를 소리 내어 읽어 녹음하고, 케어브릿지에 넣습니다.
4. 세는 것: ① 상태가 정답과 같은 항목 수 ② 지어낸 내용(원문에 없는데 채운 항목) 수, 목표 0 ③ 건강 신호를 ‘확인 필요’로 잡은 비율 ④ 처리 시간.
5. 프롬프트를 바꿀 때마다 같은 10개로 다시 재고, 결과를 표에 남깁니다. 이 표가 발표의 ‘AI 적용 근거’가 됩니다.\[9\]

## 프롬프트 초안 (항목 채우기)

개발 첫 버전에 그대로 넣고, ‘품질 확인 방법’으로 고쳐 갑니다. `{ }` 안은 서버가 채웁니다.

```text
너는 요양기관의 돌봄 기록 초안을 만드는 도우미다.
외국인 요양보호사가 돌봄을 마친 뒤 말한 메모를 받아쓴 글을 보고,
아래 9개 항목을 채운다. 너의 결과는 초안이며, 작성자가 확인하고 담당자가 승인한다.

[어르신] 급여 종류: {시설 | 재가}, 서식: 별지 제{16 | 12}호, 조건: {조건 목록}
[작성자 모국어] {vi}
[용어 목록] {한국어 = 베트남어 고정 번역}
[항목] visit_time, support, meal, sleep, discomfort, medication, cognition, notes, next_check

규칙:
1. 원문에 없는 내용은 쓰지 않는다. 없으면 status=not_mentioned, value_ko="".
2. 내용을 쓴 항목은 evidence에 원문 문장을 한 글자도 바꾸지 않고 옮긴다.
3. 양·정도가 모호하거나, 사투리를 짐작했거나, 말이 서로 맞지 않거나,
   낙상·상처·호흡·의식·통증·복약 이상이 있으면 status=needs_check이고 reason을 쓴다.
4. 진단하지 말고 본 것만 쓴다. 호전/유지/악화는 원문에 비교가 있을 때만.
5. value_ko는 한국어 기록체(~하심, ~드심), 교재 용어. value_native는 그 번역.
6. notes는 200자 안쪽을 목표로 한다.
7. 어르신·가족의 실명을 기록에 쓰지 않는다.
8. 재가면 form_fields도 채운다. 시설이면 form_fields는 빈 객체.

아래 JSON 형식으로만 답한다. 설명 문장을 붙이지 않는다.
{출력 형식}

[받아쓴 글]
{transcript}
```
