# MVP 밖 내용은 '추후 적용' 한 가지로 표시

- **상태:** 유효
- **정한 날·사람:** 2026-10-26 · 2dion
- **관련:** 기획안 '범위' 표·'10/23까지 최소 구현 범위' 표, 데이터 구조 '화면과 서버가 지킬 것'(도우미), 화면 설계 v1.1.1 '추후 적용 (MVP 밖)' 절, [병기모드우선](2026-10-25-병기모드우선.md)

## 배경

MVP에서 뺀 내용이 문서마다 '여유 시', '준비 중', 'MVP에 없음', '다음 기능 (MVP 이후)'로 섞여 적혀 있었습니다.[1] '여유 시'는 10/23 기능 마감 전에 시간이 남으면 넣는다는 뜻이었는데, 마감이 지나 뜻이 흐려졌습니다.[2] 10/26 W1 달력을 '추후 적용'으로 정하면서 분류를 정리할 필요가 생겼습니다.

## 결정

1. 화면·기능 범위는 **'MVP'와 '추후 적용' 두 가지**로만 표시합니다.
2. 예전 표시 '여유 시', '준비 중', 'MVP에 없음', '다음 기능 (MVP 이후)'은 모두 '추후 적용'으로 바꿉니다. 이미 지난 결정 기록 안의 문구는 그때 기록이라 고치지 않습니다.
3. 화면 내용 전체 목록은 화면 설계 v1.1.1 '추후 적용 (MVP 밖)' 절 한곳에 둡니다.
4. 표시만 바꾸는 것이라 x.x.1로 올립니다(기획안 v1.1.1, 데이터 구조 v1.5.1, 화면 설계 v1.1.1). 표·API·상태 값은 그대로입니다.

## 검토한 대안

- **'여유 시'와 '추후 적용' 둘 유지:** 마감 전후를 나눌 수 있지만, 기능 마감(10/23)이 지나 '여유 시'로 남은 것도 결국 나중 일이라 구분의 쓸모가 없습니다.
- **문서마다 그대로 둠:** 고칠 것이 없지만, 같은 일을 문서마다 다르게 불러 무엇이 빠졌는지 찾기 어렵습니다(2dion 10/26 "분류가 너무 중구난방").

## 사유

범위를 두 갈래로만 나누면, 팀원과 AI 코딩 도구가 "지금 만들 것인가"만 보고 판단할 수 있습니다.

- **데이터 구조 v1.5.1:** 도우미 음성 질문 한 줄. 공통 계약 내용은 그대로.
