# 용어 목록은 glossary 표에 두고, 칸 이름을 정함

- **상태:** 유효
- **정한 날·사람:** 2026-10-21 · 백엔드 담당 제안, 2dion 승인
- **관련:** 공통 계약 Agent 도구 ② search_terms, 데이터 구조 v1.1 '요약과 표 목록'·'권한 규칙', 기획안 v1.1 결정 6, 기술검토 v1.5 3장

## 배경

Agent 도구 ② 용어 검색(search_terms)은 "교재 공식 용어, 베트남어 고정 번역, 교재 장·쪽"을 돌려주는데, 데이터 구조 v1.1의 표 11개에 용어 목록을 넣을 표가 없습니다.[1][2] 데이터 담당이 10/19~21에 용어 목록을 DB에 넣기로 했지만 넣을 곳이 정해지지 않았습니다.[3]

## 결정

`glossary` 표를 하나 더해 표는 12개가 됩니다. 모든 기관이 같은 목록을 읽으므로 manual_sections처럼 `org_id`가 없습니다.

| 칸 | 형식 | 뜻 |
| --- | --- | --- |
| id | uuid | 기본 키 |
| expression | text | 일상 표현·사투리 그대로 (예: "밥을 반 먹었어요", "걸신진다") |
| aliases | text[] | 같은 뜻의 다른 표현 (없으면 빈 목록) |
| term_ko | text | 교재 공식 기록 용어 (예: "식사량 1/2 섭취") |
| term_vi | text | 베트남어 고정 번역 |
| plain_ko | text | 쉬운 한국어 풀이 (W3(기록 초안 확인) '용어 뜻 보기'). 비워도 됨 |
| chapter | text | 교재 장 |
| page | text | 교재 쪽 |

- **검색:** search_terms는 `expression`·`aliases`·`term_ko`에서 부분 일치(pg_trgm 또는 ILIKE)로 찾고, `term_ko`, `term_vi`, `chapter`, `page`를 돌려줍니다. 못 찾으면 빈 결과입니다(공통 계약 그대로). Postgres 기본 전문 검색(tsvector)은 한국어 조사를 나누지 못해 "밥을"과 "밥"을 다른 말로 보므로 쓰지 않습니다.[4]
- **권한:** 로그인한 사람은 모두 읽기만 합니다.
- **입력 경로:** 저장소의 용어 CSV가 원본입니다. 데이터 담당이 CSV를 고치고 PR로 올리면 시드(`supabase/seed.sql` 또는 마이그레이션)로 DB에 넣습니다. Supabase 대시보드에서 직접 고치지 않습니다(DB를 다시 만들면 사라지고 이력이 남지 않음).
- **크기:** 처음은 시나리오 1·2에 나오는 말 30개, 데모까지 약 50~100개입니다.[5]
- **서식 기준 데이터(get_form_spec용):** 별지 제16호·제12호의 칸·선택지는 잘 바뀌지 않으므로 표를 만들지 않고 서버 코드 안 고정값(JSON)으로 둡니다. 원본은 `참고자료/도메인/서식/법정/` 정리 문서입니다.[6]

## 검토한 대안

- 용어를 코드 안 JSON 파일로 둠: 표가 늘지 않지만, W3에서 화면이 바로 읽을 수 없고 검색을 코드로 짜야 함.
- manual_sections 표에 섞음: 표는 늘지 않지만, 절 단위 본문과 한 줄 용어는 칸이 달라 검색 결과가 섞임.
- tsvector 전문 검색: manual_sections와 같은 방식이지만 한국어 조사 때문에 짧은 표현을 놓침. 100개 규모에서는 부분 일치로 충분함.

## 사유

manual_sections와 같은 방식(공용 표, 읽기만)이라 새로 배울 것이 적고, 용어 고침은 CSV PR 하나로 이력이 남기 때문입니다. 서식 기준은 바뀔 일이 드물어 표보다 코드가 단순합니다.

## 영향

- **데이터 구조 v1.1:** 표 11개 → 12개, glossary 칸 표, 권한 규칙에 glossary 줄, `org_id` 예외에 glossary 추가(이 PR).
- **공통 계약:** API·상태 값·도구 이름은 그대로입니다. search_terms 출력의 칸 이름이 이 표를 따릅니다.
- **DB(백엔드 담당):** 마이그레이션에 glossary 표, 읽기 RLS, pg_trgm 색인을 넣습니다.
- **데이터(데이터 담당):** 용어 CSV 머리줄을 `expression,aliases,term_ko,term_vi,plain_ko,chapter,page`로 맞춥니다. aliases는 여러 개면 `|`로 나눕니다.
- **화면(프론트엔드 담당):** W3 '용어 뜻 보기'는 glossary의 `plain_ko`·`term_vi`를 읽습니다.
