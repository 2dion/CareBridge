# 기록 상태 이름을 작성 전·임시 저장·전송 완료·수정 필요·승인 완료로 바꾼다

- **상태:** 유효
- **정한 날·사람:** 2026-10-27 · 2dion(팀장)
- **관련:** 화면 설계 v1.3 W1·W4·R1·R3, 화면 문구 v1.0 상태 배지·고칠 후보 3·4번, 데이터 구조 v1.6.2 records.status 설명

## 배경

화면 설계는 기록 상태를 작성 전 / 임시 저장 / 보냄 / 되돌아옴 / 승인됨으로, W4(기록함) 탭을 못 쓴 기록 / 임시 저장 / 보냄 / 되돌아옴 / 승인됨으로 정했습니다.[1] 프론트엔드 개발용 피그마 '개발 v1.0'은 일부 화면에 '수정 필요', '전송 완료'를 썼습니다.[2] 화면 문구 문서도 '되돌아옴'이 작성자가 무엇을 해야 하는지 드러나지 않는다는 점을 고칠 후보로 남겼습니다.[3]

## 결정

1. **화면에 보이는 상태 이름:** 작성 전 / 임시 저장 / 전송 완료 / 수정 필요 / 승인 완료.
   | 값 | 예전 이름 | 새 이름 | 베트남어(병기할 때) |
   | --- | --- | --- | --- |
   | (기록 없음) 또는 못 쓴 기록 | 작성 전, W4 탭 '못 쓴 기록' | 작성 전 | Chưa ghi |
   | `draft` | 임시 저장 | 임시 저장 | Đã lưu tạm |
   | `submitted` | 보냄 | 전송 완료 | Đã gửi |
   | `returned` | 되돌아옴 | 수정 필요 | Cần sửa |
   | `approved` | 승인됨 | 승인 완료 | Đã duyệt |
2. **W4(기록함) 탭도 같은 이름:** 작성 전 / 임시 저장 / 전송 완료 / 수정 필요 / 승인 완료. W1(오늘) 주황 띠는 "수정 필요 기록 N건", R1(검토 대기) 한 줄은 "지난 7일 작성 전 기록 N건".
3. **바꾸지 않는 것:** `records.status` 값, `list_missed_records`의 kind(`missing`/`draft`), API. 문서 안의 기능 이름 '못 쓴 기록'(DB 함수가 계산하는 지난 기록)은 그대로 두고, 화면 이름만 '작성 전'입니다.
4. **R3(승인한 기록) 이력:** 작성 → 전송 → 검토·수정 → 승인. 동작 이름이라 '완료'를 붙이지 않습니다.

## 검토한 대안

- **문서 이름 유지(보냄·되돌아옴·승인됨):** 피그마와 달라 검수 때마다 설명해야 하고, '되돌아옴'은 고쳐야 한다는 뜻이 약합니다.
- **'보완 필요'·'고쳐서 다시 보낼 기록':** 화면 문구 문서의 다른 후보입니다.[3] '수정 필요'가 고쳐야 한다는 뜻을 가장 짧게 드러내고, 베트남어 검수 의견(Cần sửa)과도 맞습니다. '확인 필요'와 꼴이 비슷하다는 점은 배지 색(주황)과 위치(기록 전체 상태 대 항목)로 나눕니다.

## 사유

작성자가 상태 이름만 보고 다음에 할 일(쓰기, 고치기, 기다리기)을 알 수 있게 합니다. 값은 그대로라 서버·DB는 바뀌지 않습니다.
