# 어르신은 실명과 사진으로 구분하고 관찰 메모와 분리한다

- **상태:** 유효
- **정한 날·사람:** 2026-10-30 · 팀장 (이 채팅에서 B안 및 실명 표시 승인)
- **관련:** #99, #96, 데이터 구조 residents·권한·공통 계약, 화면 M4·W1

## 배경
같은 성의 어르신을 한 기관에 한 명만 등록하는 화면 제약을 없애야 합니다. 팀장은 사진을 사용하는 B안을 선택하고, 김○○ 형식을 없애고 실명과 사진을 쓰도록 정했습니다. 공모전 답변서2의 비식별 관찰 메모는 이름·연락처 없는 관찰 내용이며, 명단의 대상 확인 정보와 구분합니다.

## 결정
1. 명단의 표시 이름은 `residents.name`에 직접 입력합니다(1~80자). 같은 이름도 허용하고 내부 식별은 기존 uuid로 합니다. 기존 가명은 실명을 추정하지 않고 그대로 옮겨 관리자가 고칠 수 있게 합니다. `alias`는 구버전 호환용으로만 남깁니다.
2. 사진은 선택입니다. 관리자가 M4의 추가·수정에서 등록·교체·삭제하고, 관리자 명단과 작성자의 담당 어르신 카드·대상 확인에 보입니다. 사진이 없어도 이름으로 표시합니다.
3. `resident-photos`는 비공개입니다. 현재 사진은 관리자와 담당 작성자만 읽습니다. 파일 쓰기는 서버만 합니다. 로그인 세션을 확인하는 GET API로 읽고 공유용 서명 URL·공개 URL을 발급하지 않습니다.
4. POST는 원본 JPEG·PNG·WebP 3MiB 이하만 받고, 서버에서 이미지 해독·최대 1200만 화소 확인 후 512px 이하 JPEG로 다시 저장합니다. 원본 파일명·EXIF를 보관하지 않습니다. DB에는 `{org_id}/{resident_id}/{uuid}.jpg` 경로만 둡니다.
5. DELETE·교체는 DB의 현재 경로를 비교해 동시 수정 충돌을 막습니다. 옛 파일은 Storage API로 지웁니다. 지우기 실패 시 성공으로 숨기지 않고 정리 필요를 응답합니다. 현재 경로가 아닌 사진은 RLS로 읽을 수 없습니다.
6. 명단 이름·사진 필드는 AI 입력에 추가하지 않습니다. 서버 전용 실명 검사 목록에는 같은 기관 `residents.name`도 넣습니다. 관찰 본문은 기존대로 '어르신'·'보호자'를 쓰며, 입력자가 실명을 적은 자유 텍스트 전체를 자동 비식별화한다고 보장하지 않습니다. 인쇄·PDF에는 대상 이름을 표시하되 사진은 넣지 않습니다.
7. 시연·테스트는 가상의 이름과 합성 사진만 사용합니다. 실제 인물 사진·실명의 사용 근거와 기관 운영 책임은 도입 전에 확인합니다. 합성 사진을 실제 사람 사진으로 표시하지 않습니다.

## 검토한 대안
- A안 가명 꼬리표: 팀장이 사진을 택하여 채택하지 않음.
- B안 가명과 사진: 이후 실명 표시 결정으로 변경.
- 같은 성 한 명 제한: 대상 등록을 막으므로 폐기.

## 사유
작성자가 대상을 직접 확인할 수 있게 하면서, 관찰 내용·AI 처리와 식별용 명단을 분리합니다. 실명·사진을 저장하는 시스템 전체가 익명이라고 설명하지 않습니다.

## 영향
화면 추가·수정·오늘·대상 확인, residents.name·photo_path, 비공개 Storage RLS, 사진 GET·POST·DELETE API, 개인정보 안내와 검증. 기존 원칙 9의 가명 전제는 이 결정으로 대체하며, 관찰 메모 실명 금지·합성 사례 시연은 유지합니다.
