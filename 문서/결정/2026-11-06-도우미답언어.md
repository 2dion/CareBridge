# 도우미(W6) 답에도 만든 때 작성자 언어를 남기고, 다시 불러올 때와 같은 질문 재사용에서 그 언어로 가른다

- **상태:** 유효 (2번 옛 행 채우기는 2026-11-07 [도우미답언어백필](2026-11-07-도우미답언어백필.md)로 일부 대체)
- **정한 날·사람:** 2026-11-06 · 팀장 기준, 백엔드 담당 구현 (이슈 #354)
- **관련:** 결정 [언어선택화면](2026-11-05-언어선택화면.md) 5번, 결정 [기록언어기준](2026-11-05-기록언어기준.md), 결정 [도우미답재사용](2026-11-03-도우미답재사용.md), 결정 [도우미대화저장](2026-10-31-도우미대화저장.md), 데이터 구조 v2.3.7 `helper_messages`·`GET /api/helper/messages`, 이슈 #315·#336

## 배경

- 기록은 만든 때 언어(`records.native_lang`)를 남기고 지금 언어와 다르면 번역 줄을 숨기기로 했고(#342·#347), 도우미 답도 같은 기준이 필요합니다.
- 그런데 `helper_messages`에는 답의 언어 칸이 없어서 조회 응답이 `answer: { ko, vi: answer_native }`로 언어 없이 내려갔고, 화면은 다시 불러온 답을 모두 `vi`로 봤습니다. 언어를 한 번도 바꾸지 않은 `zh`·`mn`·`en` 작성자도 다시 불러오면 번역 줄이 숨었고, 언어를 바꾼 `vi` 작성자에게는 다른 언어 답이 베트남어 자리에 보일 수 있었습니다.
- 같은 질문 재사용(`find_helper_answer`, #229)은 답을 쓴 사람의 **지금** `profiles.native_lang`으로 비교해, 언어를 바꾼 작성자의 옛 답이 다른 언어 작성자에게 재사용될 수 있었습니다.
- 지금 켜진 언어는 ko·vi뿐이라 사용자 영향은 없지만, 언어를 켜기(#315) 전에 필요합니다.

## 결정

1. **칸 추가:** `helper_messages.native_lang`(필수, 값 `ko`·`vi`·`zh`·`mn`·`en`, 이름·값은 `records.native_lang`과 같음). 서버가 답을 저장할 때 **그 순간의 작성자 언어**를 보냅니다. 보내지 않으면 DB가 작성자의 그때 프로필 언어로 채웁니다. 만든 뒤 바꾸지 않습니다(화면 키는 넣기만 되고, 서버도 트리거가 막음).
2. **옛 행 채우기:** `answer_native`가 빈 행은 `ko`, 나머지는 `vi`. 지금까지 켜진 언어가 ko·vi뿐이라 실제 사용자 행은 이게 맞습니다. 11/06 QA가 zh·mn·en으로 시험한 합성 행은 어느 것인지 알 수 없어 `vi`로 둡니다(언어를 켜기 전 시험 행이라 사용자 영향 없음).
3. **조회 응답:** `GET /api/helper/messages`의 `answer`를 `{ ko, native, native_lang, source, found }`로 바꿉니다. 옛 `vi` 키는 뺍니다(이 응답의 `vi`는 화면이 `native`로 읽도록 고친 뒤라 남길 이유가 없음).
4. **저장 응답:** `POST /api/helper/ask` 출력에 `native_lang`을 더해 이름을 맞춥니다. 전환 기간용 `vi`는 그대로 둡니다.
5. **화면:** 다시 불러온 답의 `recordLanguage`는 응답의 `native_lang`입니다. 언어를 모르면 `vi`로 추정하지 않습니다. 지금 언어와 다르면 번역 줄을 숨깁니다. Mock 데모 대화도 같은 모양(`nativeLang`)입니다.
6. **같은 질문 재사용:** `find_helper_answer`는 `m.native_lang = 묻는 사람의 지금 native_lang`으로 비교합니다. 답을 쓴 사람의 지금 프로필 언어는 보지 않습니다.
7. **바뀌지 않는 것:** 답을 만드는 방식, 저장 실패 시 답은 주는 규칙, 권한(RLS), `GET`·`POST`의 경로와 나머지 칸.

## 검토한 대안

- **대안 A: 작성자 지금 언어로 다시 번역해 보여 주기:** 언어를 바꿔도 번역이 따라옴 / 열 때마다 토큰을 쓰고, 저장된 한국어 답과 모국어 답이 어긋남. 버림
- **대안 B: 가입 때 언어를 고정하거나 '한국어만'을 강제:** 구조가 단순함 / 팀장 결정(언어 변경 허용)과 어긋남. 버림
- **대안 C: 칸 없이 문자로 언어를 추측(한자면 zh 등):** DB 변경이 없음 / 영어·베트남어는 구분이 어렵고 추측이 틀리면 엉뚱한 언어로 표시됨. 버림
- **채택:** 칸 추가 + 서버가 보냄(안 보내면 DB가 채움) + 응답·재사용 모두 그 칸으로 비교

## 사유

- 기록과 같은 기준이라 화면 규칙(`Native recordLanguage`)을 그대로 쓸 수 있습니다.
- 서버가 보내고 DB가 빈 값을 채우므로, 배포 순서가 어긋나도(마이그레이션 먼저, 서버 코드 나중) 새 행이 틀린 언어로 남지 않습니다.
