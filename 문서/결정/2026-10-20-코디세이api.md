# 텍스트 AI(Claude)는 코디세이 공개 API로 부름

- **상태:** 유효 (받아쓰기 STT는 이 결정에 넣지 않음. 따로 정함: [2026-10-20-stt-groq.md](2026-10-20-stt-groq.md))
- **정한 날·사람:** 2026-10-20 · 2dion
- **관련:** [기술 조합](2026-10-16-기술조합.md), 기술 선택 v1.1 §5~8·'비용', [코디세이 API 사용 방법 v1.0](../설계/코디세이api-v1.0.md)

## 배경

v1.1은 Claude API를 Anthropic에 직접 부르고 팀이 결제한다고 가정했지만, 키와 결제 수단을 누가 준비할지는 비어 있었습니다.[1] 팀장은 코디세이 AI API 문서를 따로 쓰고, 그때까지 Mock으로 개발하기로 했습니다.[2] 10/20 코디세이 공개 API가 열렸고, Anthropic 규격(`/v1/messages`)을 받으며 비용은 소속 기관이 냅니다.[3]

## 결정

- 서버의 Claude 호출(기록 검토 준비 Agent, 항목 보태기, 짧은 번역, 도우미)은 코디세이 공개 API의 Anthropic 규격 `POST /v1/messages`로 보냅니다.
- 주소와 키는 서버 환경 변수 `ANTHROPIC_BASE_URL`, `ANTHROPIC_AUTH_TOKEN`에만 둡니다. 키는 `Authorization: Bearer` 헤더로 보냅니다(아래 '시험 결과'). 모델은 `AI_MODEL_MAIN=claude-sonnet-4`, `AI_MODEL_LIGHT=claude-haiku-4`입니다.
- Agent 구조(도구 사용 + 서버 반복, 최대 4번), 도구 4개, 공통 계약은 바꾸지 않습니다.
- 키가 없거나 시험 중일 때는 `USE_MOCK_AI=true`로 개발합니다.
- 받아쓰기(STT)는 공개 API에 없어 이 결정에서 뺍니다. 정할 때까지 Mock으로 둡니다.

## 검토한 대안

- Anthropic에 직접(v1.1): 속도 제한·정책이 확실하지만 팀이 결제해야 하고, 결제 담당이 정해지지 않음.
- 코디세이 공개 API의 OpenAI 규격(`/v1/chat/completions`)으로 GPT·Gemini: 같은 키 하나로 되지만, v1.1의 도구 정의(name, description, input_schema)와 프롬프트를 다시 맞춰야 함.
- 코디세이 공개 API의 Anthropic 규격으로 Claude(고름): 코드 구조 그대로, 비용 없음.

## 사유

주소와 키만 바꾸면 v1.1 설계를 그대로 쓰고, 기관 비용이라 결제 담당 문제가 사라지기 때문입니다.[1][3]

## 영향

- 서버: Anthropic SDK를 그대로 쓰고 주소만 환경 변수로 바꿉니다. 401·403·409·한도 초과·503 처리를 더합니다.
- 비용: 계정마다 월 1,000,000 차감 토큰. Sonnet Agent 기록 1건 ≈ 3만으로 추정해 월 30~40건뿐이라, 개발은 Mock·Haiku 위주로 합니다.
- 보안·데이터: 프롬프트·응답을 기관 운영자가 볼 수 있으므로 합성 사례만 씁니다(AGENTS.md 원칙 9 그대로).
- 위험: 요청 속도 제한·만료 정책이 아직 '협의 중'이고, 매뉴얼이 QA 환경 기준이라 주소가 바뀔 수 있습니다.[3]
- 도구 사용(tool use)은 10/20 시험에서 통과했습니다(아래 '시험 결과'). 이 결정은 그대로 유지합니다.
- 문서: 기술 선택 v1.1 §6~8과 '비용'에 반영, 기술 조합 결정에 이 파일을 연결합니다.

## 시험 결과 (10/20)

**왜:** 이 결정이 기대는 가정, '도구 사용이 공개 API를 통과한다'를 키를 받은 날 확인하기 위해서입니다.[4]

- 방법: 팀장 맥에서 합성 질문 1개와 도구 1개(`lookup_form_rule`)로 `POST /v1/messages`를 두 단계(도구 호출 → 도구 결과 돌려주기)로 보냄. 모델 `claude-haiku-4`.
- 결과: 1단계 `stop_reason: "tool_use"`로 도구를 부르고(입력 657, 출력 93 토큰), 2단계 `end_turn`으로 돌려준 값을 그대로 써서 답함(입력 764, 출력 164 토큰). 도구 사용 왕복이 됩니다.
- 함정: 키를 `x-api-key` 헤더로 보내면 401 `invalid x-api-key`, `Authorization: Bearer`로 보내면 200입니다. 매뉴얼은 두 방식 모두 된다고 하지만 이 주소에서는 `x-api-key`가 안 됩니다. 그래서 환경 변수를 `ANTHROPIC_AUTH_TOKEN`으로 정합니다(SDK가 Bearer로 보냄).
- 남은 것: ⚠️ 도구 4개를 모두 쓰는 Agent 반복(최대 4번), Sonnet 모델, 프롬프트 캐싱은 아직 시험하지 않았습니다(백엔드 담당).
