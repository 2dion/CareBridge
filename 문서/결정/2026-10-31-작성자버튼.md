# W3 작성자 버튼을 '확인 완료·내용 수정·내용 추가·해당 없음'으로 맞춘다

- **상태:** 유효
- **정한 날·사람:** 2026-10-31 · 기획 담당
- **관련:** 이슈 #215, 용어집 v1.0 '항목' 표, 화면 설계 v1.3.1 W3, 결정 [2026-10-30-수정요청배지](2026-10-30-수정요청배지.md)(W3 묶음 제목)

## 배경

W3(기록 초안 확인) 작성자 버튼만 말하는 꼴([맞아요]·[달라요]·[없음이 맞아요])이고, 다른 버튼은 '~하기'·명사형([임시 저장], [전송], [다시 녹음하기], [기록 없음으로 처리])입니다. [보태기]·[없음이 맞아요]는 코드(PR #80)에만 있고 용어집·화면 설계에는 없었습니다. [수정하기]와 [달라요]는 같은 동작인데 이름이 둘이었습니다.[1]

## 결정

1. W3 항목 카드의 작성자 버튼 이름을 아래로 바꿉니다. 버튼은 한국어 위, 베트남어 아래로 함께 씁니다.

   | 카드 | 옛 이름 | 새 이름 | 베트남어 |
   | --- | --- | --- | --- |
   | 내용 있는 카드 | [맞아요] / [달라요] | [확인 완료] / [내용 수정] | Xác nhận / Sửa nội dung |
   | 확인 필요 카드 | [수정하기] / [맞아요] | [내용 수정] / [확인 완료] | Sửa nội dung / Xác nhận |
   | 언급 없음 카드 | [보태기] / [없음이 맞아요] | [내용 추가] / [해당 없음] | Thêm nội dung / Không có |

2. 항목 화면 제목도 버튼에 맞춥니다. '항목 고치기' → '내용 수정', '내용 보태기' → '내용 추가'.
3. 관리자 버튼 [확인함]·[기록 안 함]은 그대로입니다. 작성자 확인(`confirmed_by_worker`)과 관리자 확인(`confirmed_by_reviewer`)은 계속 다른 말로 나눕니다.
4. 동작, API, 표, 상태 값은 바뀌지 않습니다. 화면 글자만 바꿉니다.
5. 서버 안의 AI 호출 이름 '③ 항목 보태기'(AI 규칙·기술 선택)는 화면에 보이지 않으므로 그대로 둡니다.

## 검토한 대안

- 지금대로 두기: 바꿀 것 없음 / 버튼 말투가 섞이고, [달라요]·[수정하기]가 같은 동작에 두 이름
- [확인 완료] / [수정하기] / [추가하기] / [비워 두기]: '~하기' 꼴로 맞음 / '비워 두기'는 '해당 없음'보다 서식에서 덜 익숙함
- [확인] / [수정] / [추가] / [없음]: 가장 짧음 / [없음]만으로는 무슨 버튼인지 알기 어려움

## 사유

버튼을 명사형으로 맞추고, 같은 동작은 한 이름으로 부릅니다. [확인 완료]는 W3 묶음 제목 '확인 완료 항목'과 같은 말이라 누르면 어디로 가는지 바로 보입니다.

## 영향

- **용어집 v1.0:** '항목' 표의 작성자 버튼 줄을 바꾸고, 쓰지 않는 이름에 옛 이름을 적음. W3 하위 상태 '항목 고치기·내용 보태기' → '내용 수정·내용 추가'
- **화면 설계 v1.3.1 W3, 기획안 v1.1.2 MVP 범위·비교표, 데이터 구조 v1.6.6 `confirmed_by_worker` 설명, 시연-일정 v1.1, 시연대본 시나리오 1:** 버튼 이름만 바꿈
- **화면(FE):** `web/app/(worker)/records/[id]/page.tsx` 버튼 6곳, `items/[key]/page.tsx` 제목 2곳(이슈 #215)
- **QA:** 테스트 이름·시나리오의 옛 버튼 이름
- **공통 계약(API·표·상태 값):** 바뀌지 않음
