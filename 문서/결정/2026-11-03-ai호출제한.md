# AI를 부르는 API에 사용자별 호출 제한을 둔다

- **상태:** 유효
- **정한 날·사람:** 2026-11-03 · JiNS03
- **관련:** 이슈 #256, 데이터 구조 v2.1.1 `api_usage`·오류 키 `rate_limited`, 코디세이 API 사용 방법 §4(토큰 한도)

## 배경

코디세이 API는 기관 계정마다 월 차감 토큰이 정해져 있습니다. Agent·항목 고치기·도우미·녹음 API에 사용자별 제한이 없어, 한 계정이 반복해서 부르면 모든 사용자의 AI가 멈출 수 있었습니다.

## 결정

1. 사용자별·종류별로 1시간 호출 수를 셉니다. 한도는 agent 20번, audio 30번, item 30번, helper 60번, translate 120번(항목 고친 뒤 다시 번역, 되돌린 사유 번역)입니다.
2. 넘으면 AI를 부르지 않고 429 `rate_limited`를 돌려줍니다. 화면은 "잠시 뒤 다시 시도" 안내를 보입니다.
3. 횟수는 새 표 `api_usage`에 남기고, 서버 전용 함수 `take_api_quota`만 세고 넣습니다.
4. 제한 검사 자체가 실패하면 서비스를 막지 않고 로그만 남깁니다.
5. Mock 모드는 AI를 부르지 않으므로 세지 않습니다.

## 검토한 대안

- 서버 메모리로 세기: 표가 필요 없음 / Vercel 서버가 여러 개라 횟수가 나뉨
- 기존 표(agent_steps, audio_jobs, helper_messages)로 세기: 마이그레이션 없음 / 항목 글로 고치기는 남는 행이 없고, 세는 기준이 API마다 달라짐
- 기관 단위 제한: 기관 전체 소진을 직접 막음 / 한 사람이 같은 기관의 다른 사람을 막을 수 있음

## 사유

사용자별로 세면 다른 사람에게 영향을 주지 않고 반복 호출만 막습니다. 검사 실패 때 통과시키는 이유는, 11/08 시연에서 제한 기능의 오류가 서비스 중단으로 이어지지 않게 하기 위해서입니다.
