# M4에서 기록이 없는 어르신만 지울 수 있게 한다

- **상태:** 유효
- **정한 날·사람:** 2026-11-04 · 2dion(팀장)
- **관련:** 이슈 #103, 데이터 구조 v2.3.2 공통 계약 `DELETE /api/residents/:id`, 화면 설계 v2.2.2 M4, 바꾸지 않는 원칙 1

## 배경

QA 화면 점검(10/28)에서 "어르신을 빼는 방법이 없다"는 지적이 나왔습니다.[1] M4(어르신·작성자)에 삭제 버튼이 없어, 잘못 더한 어르신이 명단에 계속 남습니다. 기록이 있는 어르신은 `records.resident_id` 외래 키(NO ACTION) 때문에 DB에서도 지워지지 않고, 기록 자체도 앱에서는 아무도 지울 수 없습니다(지우기 권한 없음, 승인 완료는 트리거 `record_locked`).

## 결정

1. M4 [수정] 창에 [어르신 삭제]를 둡니다. **기록이 하나도 없는 어르신만** 지웁니다. 기록이 있으면 버튼을 끄고 "기록이 있는 어르신은 지울 수 없어요"를 보입니다.
2. 새 API `DELETE /api/residents/:id`(관리자)를 둡니다. 서버가 기록 수를 다시 세서 하나라도 있으면 `409 has_records`로 막습니다. 그 사이 기록이 생기면 외래 키가 막고 같은 오류를 돌려줍니다.
3. 지우기는 관리자 RLS(`residents_reviewer_delete`, 이미 있음)로 합니다. 담당 연결(`assignments`)과 기록 없음 처리(`no_care_days`)는 DB가 같이 지웁니다(on delete cascade). 사진 파일은 행을 지운 뒤 서버 키로 정리하고, 실패하면 `cleanup_pending: true`.
4. 표·칸·RLS·상태 값은 바꾸지 않습니다. 기록은 지우지 않습니다.

## 검토한 대안

- B안 '담당 끝남·숨김' 칸: 실제 운영(퇴소·계약 끝)에 맞지만 새 칸·RLS·목록 조건이 필요해 추후 적용으로 둡니다.
- C안 넣지 않음: 일이 없지만 잘못 더한 어르신을 지울 길이 없습니다.
- 브라우저에서 RLS로 바로 지우기: API가 필요 없지만 사진 파일(Storage 쓰기·삭제는 서버만, #99)을 정리하지 못해 실명 사진이 남습니다.

## 사유

기록은 사람이 책임지는 공식 기록이라 어르신을 지워도 남아야 합니다. 기록이 없는 어르신만 지우면 표를 바꾸지 않고 잘못 더한 경우를 해결합니다.

## 영향

- **BE:** `web/app/api/residents/[id]/route.ts`, `web/lib/residents/delete-service.ts`
- **FE:** M4 [수정] 창 아래 [어르신 삭제], Mock은 브라우저 저장에서 같은 규칙
- **문서:** 데이터 구조 v2.3.2 API 표, 화면 설계 v2.2.2 M4
- **QA:** 기록 없는 어르신 삭제, 기록 있는 어르신 버튼 꺼짐·서버 409, 작성자 403
