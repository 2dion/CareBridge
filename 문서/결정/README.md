# 결정 기록

2026-10-19 · @2dion

## 이 폴더는 왜 있나

- **목적:** 무엇을 왜 정했는지, 그때 어떤 대안을 버렸는지를 나중에도 찾을 수 있게 합니다. 개발 문서에서 말하는 ADR(Architecture Decision Record)입니다.[1]
- **배경:** 기획안 결정표는 버전마다 덮어써서 바뀐 이유를 찾으려면 보관 폴더를 오가야 합니다. 대안과 날짜가 없는 결정도 있고, 대화에서만 정한 결정(파일 이름 검사 범위, Vercel 배포 중지 등)은 어느 문서에도 없습니다. 10/19부터 개발하면서 생길 작은 결정도 적을 자리가 필요합니다.[2]
- **근거:** 기획안 v1.1 결정표, 기술 선택 v1.1의 '대안'·'확정' 줄, AGENTS.md의 '공통 계약 위치'입니다.[2][3][4]
- **사유:** 기존 문서를 고치지 않고 결정 하나에 파일 하나를 더하면, 결정표는 '지금 무엇으로 정했나' 요약으로 두고 이력만 따로 쌓을 수 있습니다.[1]

## 결정표와 무엇이 다른가

**왜:** 두 곳에 같은 말을 쓰지 않기 위해 역할을 나눕니다.

| 문서 | 담는 것 | 바뀌면 |
| --- | --- | --- |
| 기획안 결정표 | 지금 유효한 결정 요약 | 새 버전에서 덮어씀 |
| 결정 기록(이 폴더) | 결정 하나의 배경, 대안, 사유, 영향 | 고치지 않고 새 파일을 쓰고, 옛 파일의 상태만 '대체됨'으로 바꿈 |

## 언제 쓰나

**왜:** 모든 일을 적으면 아무도 읽지 않으니, 나중에 "왜 이렇게 했지?"가 나올 만한 것만 씁니다.

- 대안이 둘 이상 있었고 그중 하나를 고른 결정
- 공통 계약(API 경로, 상태 값, Agent 도구 입출력), 표 구조, 권한(RLS)을 바꾸는 결정
- 기획안 결정표의 행을 새로 만들거나 바꾸는 결정
- 대화(카카오톡, Discord, 프로젝트 스레드)에서만 정해서 문서에 없는 결정

오타 수정, 문장 다듬기, 이미 정한 대로 구현하는 일은 쓰지 않습니다.

## 쓰는 방법

**왜:** 같은 순서로 써야 리뷰하는 사람이 한 번에 알아봅니다.

1. 파일 이름은 `날짜-내용.md`입니다. 날짜는 결정한 날, 내용은 붙여 쓴 짧은 말입니다. 예: `2026-10-18-승인차단.md`
2. 아래 양식을 복사해 채웁니다. 모르는 값은 지어내지 않고 '확인 필요'로 남깁니다.
3. 기획안 결정표나 공통 계약을 바꾸는 결정이면, 결정 파일을 먼저 쓰고 같은 PR에서 그 문서를 고칩니다.
4. 결정이 바뀌면 옛 파일은 지우지 않습니다. 새 파일을 쓰고, 옛 파일 상태를 `대체됨 (날짜, 새 파일 이름)`으로만 바꿉니다.
5. 아래 '목록'에 한 줄을 더합니다.

## 양식

```markdown
# 결정 제목 (한 줄)

- **상태:** 유효 | 제안 | 대체됨 (날짜, 새 파일) | 철회
- **정한 날·사람:** 2026-10-18 · 2dion
- **관련:** 기획안 결정 N, 공통 계약 OO 등

## 배경
왜 이 결정이 필요했나. 2~3줄.[1]

## 결정
무엇을 정했나. 다른 사람이 그대로 따라 할 수 있게.

## 검토한 대안
- 대안 A: 좋은 점 / 버린 이유
- 대안 B: 좋은 점 / 버린 이유

## 사유
왜 이 안을 골랐나. 한두 문장.

## 영향
이 결정 때문에 바뀌는 화면, 서버, 표, 테스트, 일정.

## 참고 자료
1. 출처
```

목적·근거는 '배경'과 '참고 자료'가 맡습니다.
