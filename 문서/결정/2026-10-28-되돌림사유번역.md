# 되돌린 사유의 모국어 번역은 작성자가 기록을 열 때 서버가 채운다

- **상태:** 유효
- **정한 날·사람:** 2026-10-28 · 백엔드 담당
- **관련:** [되돌림사유한국어 결정](2026-10-28-되돌림사유한국어.md) 4번(방법 확인 필요), [권한정리 결정](2026-10-27-권한정리.md) 3번(`return_reason_native`는 담당자만), [항목하나저장 결정](2026-10-28-항목하나저장.md)(서버 전용 저장 함수 방식), 데이터 구조 v1.6.2 공통 계약, 화면 설계 v1.3 W3·W4

## 배경

되돌림사유한국어 결정으로 `/return`은 한국어 사유만 저장하고, 번역은 "작성자 화면 쪽에서" 하기로 했지만 방법은 정하지 않았습니다. 작성자 권한으로는 `return_reason_native`를 쓸 수 없고(권한정리 3번, 트리거 `reviewer_only`), 화면이 번역을 저장할 길이 없어 W3·W4에 한국어 사유만 보였습니다.

## 결정

1. 새 API `POST /api/records/:id/return/translate`를 둡니다. 작성자만, 기록이 `returned`일 때만 부릅니다. 입력 없음, 출력 `status`·`return_reason`·`return_reason_native`.
2. 서버가 작성자 자신의 `native_lang`(작성자는 자기 profiles를 읽음)으로 `return_reason`을 ④ 짧은 번역(가벼운 모델)하고, 서버 전용 DB 함수 `save_return_reason_native(record_id, worker_id, expected_reason, native)`(service_role만)로 `return_reason_native`만 채웁니다. 사유가 그사이 바뀌었으면 `stale_reason`으로 거절하고 서버가 새 사유로 한 번 더 합니다.
3. 이미 번역돼 있거나 작성자가 한국어(`ko`)를 쓰면 번역하지 않습니다(토큰 절약). Mock 모드의 빈 번역은 저장하지 않습니다.
4. 화면(작성자)은 되돌아온 내 기록 중 번역이 빈 것을 발견하면 이 API를 기록마다 한 번 부르고 다시 읽습니다. 담당자 화면은 바뀌지 않습니다.
5. 담당자가 다시 되돌리면 `/return`이 `return_reason_native`를 비우므로(되돌림사유한국어 2번) 새 사유는 다시 번역됩니다.

## 검토한 대안

- **화면이 번역만 받아 보여 주고 저장하지 않기:** DB 변경 없음 / 기록을 열 때마다 번역 토큰이 들고, W4 목록처럼 여러 기록이면 더 듦. 버림.
- **`return_reason_native` 쓰기를 작성자에게 열기:** 간단함 / 작성자가 담당자 사유의 번역을 꾸밀 수 있어 권한정리 3번과 어긋남. 버림.
- **`/return`이 service_role로 작성자 언어를 읽어 번역:** API 하나로 끝남 / 되돌림사유한국어 결정(담당자는 한국어만)과 어긋남. 버림.

## 사유

담당자 쪽은 한국어만 다룬다는 결정을 지키면서, 번역을 한 번만 저장해 토큰을 아끼고, 저장은 항목 재번역(`save_ai_item`)과 같은 서버 전용 함수 방식으로 권한 규칙을 그대로 둡니다.

## 영향

- **공통 계약:** API 10개 → 11개. 응답 코드 표에 409 `stale_reason`, 502 `translation_failed`.
- **DB:** 마이그레이션 `20261028150000_return_reason_native.sql`. 이력은 기존 트리거가 `edited`로 남김.
- **서버(BE):** `web/lib/records/return-translation.ts`, `web/lib/ai/translate.ts` 재사용.
- **화면(FE):** `demo-provider`가 되돌아온 내 기록의 빈 번역을 채움. W3·W4는 그대로 `return_reason_native`를 보여 줌.
- **테스트(QA):** 담당자가 되돌린 뒤 작성자(vi)로 W4·W3를 열면 베트남어 사유가 보임. 한국어 작성자는 번역 없음. 다시 되돌리면 새 사유가 다시 번역됨.
