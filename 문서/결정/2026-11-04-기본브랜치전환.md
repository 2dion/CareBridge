# GitHub 기본 브랜치를 main-codyssey로 바꾸고, 공모전 브랜치 이름을 main-contest로 바꾼다

- **상태:** 유효
- **정한 날·사람:** 2026-11-04 · 2dion(팀장)
- **관련:** 결정 `2026-11-02-공모전코디세이분리.md` 2번 끝 문장·6번 대체, AGENTS.md '공모전·코디세이 환경 분리'·'공모전 환경 변경 금지'

## 배경

11/02부터 모든 작업은 `main-codyssey`로 올리는데 GitHub 기본 브랜치는 공모전 `main`이었습니다.[1] 그래서 main-codyssey에 합친 PR의 `Closes #번호`가 이슈를 자동으로 닫지 못하고(#261은 손으로 닫음), 새 PR의 기본 대상도 `main`이라 매번 대상을 직접 골라야 했습니다. 공모전 제출물에는 GitHub 링크를 넣지 않았고, 공모전 Vercel `care-bridge`는 Git 연결을 끊어 더 이상 배포되지 않습니다.

## 결정

1. GitHub 기본 브랜치를 `main-codyssey`로 바꿉니다.
2. 공모전 브랜치 `main`의 이름을 `main-contest`로 바꿉니다. 내용은 그대로 보존하고 커밋을 올리지 않습니다.
3. 보호 규칙(ruleset)은 대상이 '기본 브랜치'(`~DEFAULT_BRANCH`)라 기본 브랜치를 바꾸면 공모전 브랜치가 빠집니다. 대상에 `main-contest`를 이름으로 직접 넣습니다.
4. 예약 실행(schedule)은 기본 브랜치의 workflow만 돌기 때문에, 공모전 사이트의 매시간 녹음 정리를 main-codyssey의 `.github/workflows/audio-cleanup.yml`이 이어 맡습니다. 코디세이 사이트는 지금처럼 Supabase Cron이 맡고, 이 workflow의 코디세이 작업은 수동 진단용입니다.
5. 순서: 이 결정이 담긴 PR 합침 → ruleset에 `main-contest`(이름 바꾸기 전까지는 `main`도) 추가 → 기본 브랜치 변경 → 브랜치 이름 변경 → 팀 공지.

## 검토한 대안

- 기본 브랜치 `main` 유지: 바꿀 것이 없지만 `Closes` 자동 닫기와 PR 기본 대상 문제가 계속 남습니다.
- 기본 브랜치만 바꾸고 이름은 `main` 유지: 이름 바꾸기 뒤처리(로컬 저장소)가 없지만, `main`이 공모전용이라는 것을 이름으로 알 수 없어 계속 헷갈립니다.

## 사유

남은 작업은 모두 main-codyssey에서 하므로 기본 브랜치도 같게 둡니다. 공모전 브랜치는 이름에 용도를 적어 실수로 고르지 않게 합니다.

## 영향

- **GitHub:** 옛 `main` 링크는 GitHub가 새 이름으로 이어 줍니다. 열린 PR 중 `main` 대상은 없습니다.
- **팀원 로컬:** `main`을 받아 둔 저장소는 `git branch -m main main-contest`, `git fetch origin`, `git branch -u origin/main-contest main-contest`, `git remote set-head origin -a`로 맞춥니다.
- **Vercel:** 공모전 `care-bridge`는 Git 연결이 끊겨 영향 없음. 코디세이 `carebridge-codyssey`는 Production Branch가 `main-codyssey`라 영향 없음.
- **workflow:** 라벨 맞추기는 이미 main-codyssey 기준. web 검사·파일 이름 검사는 브랜치와 상관없이 돕니다.
- **문서:** 공모전 브랜치를 `main`이라고 적은 현행 문서를 `main-contest`로 고칩니다. `문서/보관/`의 옛 링크는 그대로 둡니다.
