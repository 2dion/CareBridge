# 기록 검토 준비 Agent: 도구 4개, 최대 4번

- **상태:** 유효
- **정한 날·사람:** 2026-10-18 · 2dion
- **관련:** 기획안 결정 17, AI 규칙 v1.1, 데이터 구조 v1.1 '공통 계약'(도구 입출력), 기술 선택 v1.1 6절

## 배경

v1.0은 받아쓴 글을 Claude API 한 번 호출로 9개 항목에 채웠습니다. 외부 피드백에서 Agent 기능이 필수 조건으로 나왔습니다(A1). 한 번 호출로는 서식 기준 확인, 용어 찾기, 스스로 검사가 빠집니다.[1][2]

## 결정

- 받아쓰기가 끝나면 서버가 '기록 검토 준비 Agent'를 시작합니다.
- 도구 4개: ① 서식 기준 조회 get_form_spec ② 용어 검색 search_terms ③ 기록 검증 validate_draft ④ 초안 반환 submit_draft. 모두 서버 코드가 실행합니다.
- 최대 4번(Claude 응답 4번). 같은 도구·같은 입력은 한 번만. 4번 안에 끝나지 않으면 마지막 초안을 검증해 저장하고, 못 정한 항목은 '확인 필요'.
- 도구 호출은 agent_steps에 남기고 R2(검토 화면)의 접힌 'AI 작업 기록'으로 보여 줍니다.
- 별도 Agent 프레임워크 없이 Claude API 도구 사용(tool use) + 서버 반복으로 짭니다.[3]

## 검토한 대안

- v1.0의 한 번 호출 유지: 빠르고 싸지만 Agent 조건을 못 채우고, 근거 확인 없이 채움.
- Agent 프레임워크 사용: 도구가 늘면 편하지만, 도구 4개·반복 4번이면 서버 코드 수십 줄로 충분하고, 1주 안에 새 도구를 배울 시간이 없음. 반복 상한·같은 입력 막기·기록을 우리 코드가 쥐어야 테스트하기 쉬움.[4]
- 항목 보태기·번역·도우미까지 Agent로: 빨리 답해야 하는 일이라 한 번 호출로 남김.[4]

## 사유

서식·용어·검증을 근거로 스스로 확인하게 하면 지어낸 내용이 줄고, 외부 피드백의 Agent 조건도 채웁니다.[3]

## 영향

- 비용·지연: Claude 호출이 기록당 1번 → 최대 4번. 뒷배경 처리라 W3(기록 초안 확인)에 '정리 중' 표시. 건당 시간·비용을 품질 확인 표에서 잽니다.[4]
- 승인 조건·권한(RLS)·시간 합 계산·상태 변화·덮어쓰기 금지는 계속 코드가 맡습니다(AGENTS.md 원칙 5).
- ⚠️ Vercel 실행 시간 안에 받아쓰기 + 4번이 끝나는지, 뒷배경 처리를 어떻게 할지는 개발 첫 주에 재서 정합니다(확인 필요, BE). 정하면 새 결정 파일을 씁니다.[4]
- 테스트: 도구 실패, 반복 상한, 같은 입력 반복.[5]
