# 기술 조합: Next.js + Vercel + Supabase

- **상태:** 유효 (10/18 Agent 구조를 더함: [2026-10-18-에이전트도구.md](2026-10-18-에이전트도구.md). 10/20 Claude 호출 경로를 코디세이 공개 API로: [2026-10-20-코디세이api.md](2026-10-20-코디세이api.md), STT를 Groq Whisper로: [2026-10-20-stt-groq.md](2026-10-20-stt-groq.md))
- **정한 날·사람:** 2026-10-16 · 2dion
- **관련:** 기획안 결정 13(사용 기기와 개발 방식), 기술 선택 v1.1

## 배경

작성자는 휴대폰, 담당자는 PC를 쓰지만 기기는 사람마다 다를 수 있습니다. 1주 안에 시연본을 만들어야 하고, AI API 키는 브라우저에 두면 안 됩니다.[1][2]

## 결정

- 화면과 서버: Next.js(TypeScript) 반응형 웹앱 하나
- 배포: Vercel
- DB·로그인·파일: Supabase(Postgres), 기관별 RLS
- 녹음은 브라우저 MediaRecorder, 받아쓰기는 서버 STT(OpenAI, 대안 Google), 기록 정리는 Claude API, 듣기는 브라우저 TTS, 인쇄는 인쇄 CSS

## 검토한 대안

- React 화면 + Python(FastAPI) 서버: AI 라이브러리가 많지만 코드 두 벌, 배포 두 곳. 이번 기능은 모두 외부 API 호출이라 Python이 꼭 필요하지 않음.[2]
- Flutter·React Native: 팀 학습 부담과 화면 두 벌 문제로 v0.4.1에서 뒤로 밀림.[3]
- Firebase: 문서형 DB라 '기록-항목-검토' 같은 연결 조회가 불편함.[2]
- 브라우저 내장 음성 인식: 파이어폭스 미지원, iOS 사파리에서 자주 끊김.[2]

## 사유

TypeScript 코드 한 벌로 화면·서버·배포를 끝내야 작은 팀이 1주 안에 시연본을 만들 수 있고, 기관별 분리는 RLS가 가장 적은 코드로 지킵니다.[2]

## 영향

- 모든 API 키는 서버 코드에만 둡니다(AGENTS.md 원칙 6).
- 캡처 차단이 필요해지면 같은 웹 코드를 Capacitor·일렉트론으로 감쌉니다.[2]
- ⚠️ Vercel 함수 실행 시간 안에 받아쓰기 + Agent 4번이 끝나는지는 개발 첫 주에 재서 정합니다(확인 필요, BE).[2]
