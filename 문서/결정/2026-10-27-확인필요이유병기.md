# ‘확인 필요’ 이유도 모국어 번역을 함께 저장하고 보여 준다

- **상태:** 유효
- **정한 날·사람:** 2026-10-27 · 2dion(팀장)
- **관련:** 데이터 구조 v1.6.2 `record_items.reason_native`, AI 규칙 v1.1.1 초안 JSON, 화면 설계 v1.3 병기 원칙 ②, [병기 원칙(10/25)](2026-10-25-병기모드우선.md)

## 배경

병기 원칙 ②는 ‘확인 필요’ 이유를 한국어와 모국어로 함께 보이게 정했고, 피그마 '개발 v1.0'도 이유 아래에 베트남어를 씁니다.[1][2] 그런데 데이터 구조 v1.6.1의 `record_items`에는 한국어 `reason`만 있고 번역을 둘 칸이 없었습니다.[3] 그래서 화면은 한국어 이유만 보여 줄 수밖에 없었습니다.

## 결정

1. **칸 추가:** `record_items.reason_native`(text). `reason`의 작성자 모국어 번역입니다. 이유가 없으면 빈칸입니다.
2. **누가 채우나:**
   - AI가 쓴 이유: Agent가 초안을 돌려줄 때 `reason`과 함께 `reason_native`를 씁니다(`value_native`와 같은 방식).
   - 코드가 쓴 이유(근거를 찾지 못함, 지원별 분 합 초과, 자동 정리 중단 등): 서버 코드가 한국어·모국어 문장을 같이 정해 둡니다. AI에게 번역을 맡기지 않습니다.
   - `reason`이 바뀌면 `reason_native`도 다시 씁니다(`value_ko`와 `value_native`처럼).
3. **화면:** W3(기록 초안 확인)는 이유 한국어 아래에 모국어를 작게 보여 줍니다. 담당자 화면(R2)은 한국어만 봅니다.
4. **API:** 항목을 돌려주는 응답(`GET /api/records/:id`, `PATCH /api/records/:id/items/:key`)에 `reason_native`가 함께 옵니다. 화면이 보내는 값은 아닙니다.

## 검토한 대안

- **한국어 이유만:** 칸과 번역이 줄어듭니다 / 작성자가 왜 다시 봐야 하는지 이해하지 못하면 ‘확인 필요’가 그대로 남거나 잘못 고칩니다.
- **화면이 그때그때 번역 API 호출:** 칸이 필요 없습니다 / 같은 이유를 열 때마다 비용이 들고, 브라우저에서 AI를 부르면 원칙 6(서버에서만 호출)과 어긋납니다.

## 사유

케어브릿지는 외국인 요양보호사의 한국어 학습을 돕는 것을 목표로 하고, 작성자가 아직 담당자의 한국어를 완벽하게 이해하기 어렵다는 가정으로 만들었습니다. ‘확인 필요’ 이유는 작성자가 읽고 행동해야 하는 남이 쓴 글이라 병기합니다.[4]

## 영향

- **데이터 구조 v1.6.1 → v1.6.2:** `record_items`에 칸 1개, 공통 계약 응답에 한 줄.
- **AI 규칙 v1.1 → v1.1.1:** 초안 JSON 예시와 프롬프트 규칙 5에 `reason_native` 한 줄.
- **서버(백엔드 담당):** 마이그레이션(칸 추가), Agent 출력과 기록 검증(`web/lib/agent/validate-draft.ts`)의 코드 이유에 모국어 문장 추가.
- **화면(프론트엔드 담당):** W3 이유 아래 모국어 줄. PR #67에 반영(Mock).
- **테스트(QA 담당):** ‘확인 필요’ 항목마다 `reason_native`가 비어 있지 않은지 확인.
