# 되돌린 기록의 W3에서 관리자가 고른 항목에 '수정 요청' 배지를 붙인다

- **상태:** 유효 (10/30 팀장이 묶음 제목 1안으로 정함)
- **정한 날·사람:** 2026-10-30 · 기획 담당 제안, 2dion(팀장) 1안 확정
- **관련:** 이슈 #100, 결정 [2026-10-27-피그마상충점](2026-10-27-피그마상충점.md) 1번, 화면 설계 v1.3 W3·M2 '되돌림 사유', 용어집 v1.0

## 배경

되돌린 기록을 W3에서 열면 작성자는 맨 위 사유 띠만 보고, 고칠 항목을 9개 카드 중에서 직접 찾아야 합니다. 관리자가 고른 항목이 '확인 완료' 묶음 아래에 묻혀 있기도 합니다(FE 목업 점검 10/28, 이슈 #100).[1] 10/27 결정은 "`return_items` 칸을 만들지 않고 작성자에게 사유 전체를 보여 준다"고 정했고, 화면 설계 M2에도 "작성자 항목별 표시를 만들지 않습니다"라고 적혀 있습니다.[2]

## 결정

1. 되돌린 기록(`returned`)의 W3는 사유 앞 `[식사, 수면]`의 항목 이름을 읽어, 그 항목 카드에 **'수정 요청'** 배지를 붙입니다. 배지는 한국어만 씁니다(병기 원칙 ③).
2. 그 카드들은 맨 위 새 묶음에 모읍니다. W3 묶음 제목은 1안으로, 위에서부터 **수정 요청 항목 / 확인 필요 항목 / 확인 전 항목 / 확인 완료 항목**입니다(기존 '먼저 확인할 항목 / 아직 확인하지 않은 항목 / 확인한 항목'을 바꿈). 제목과 카드 배지가 같은 말을 씁니다.
3. 이미 '확인 완료'인 항목도 배지를 붙여 옮기고, 확인 상태는 그대로 둡니다.
4. `return_items` 칸은 계속 만들지 않습니다. 저장 방식(사유 앞에 항목 이름)은 10/27 결정 그대로입니다.

## 검토한 대안

- 대안 B `return_items` 칸 추가: 가장 정확함 / 표·API(공통 계약)가 바뀌어 10/31 전에 무리
- 대안 C 지금대로(사유 띠만): 바뀌는 것 없음 / 작성자가 고칠 항목을 직접 찾아야 함
- 묶음 제목 2안(새 묶음만 '고쳐야 할 항목', 기존 제목 유지): 바꿀 문구가 적음 / 묶음 제목과 배지 말이 달라 버림

## 사유

저장 방식은 그대로 두고 화면 표시만 바꿔, 작성자가 고칠 항목을 바로 찾게 합니다.

## 영향

- **옛 결정:** `2026-10-27-피그마상충점` 1번 중 "작성자에게 사유 전체를 보여 준다"는 그대로, '항목별 표시 안 함' 부분만 이 결정으로 대체. 옛 파일 상태 줄에 "1번 일부 대체됨 (2026-10-30, 수정요청배지)"를 더함

- **용어집 v1.0:** '수정 요청'(배지·묶음, 베트남어 Yêu cầu sửa) 줄과 W3 묶음 제목 줄 추가
