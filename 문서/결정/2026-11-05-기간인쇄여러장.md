# 기간 인쇄는 서식 한 장의 날짜 수를 넘으면 새 서식 장을 잇고, 서식 세부 칸은 실제 기록 모양으로 채운다

- **상태:** 유효
- **정한 날·사람:** 2026-11-05 · 백엔드 담당 (이슈 #317 다시 열림)
- **관련:** 결정 [인쇄이어쓰기쪽](2026-11-05-인쇄이어쓰기쪽.md) 1번 ‘서식 쪽은 언제나 한 장’(대체), 결정 [기간인쇄](2026-11-03-기간인쇄.md) 3번 ‘끝 날짜는 서식의 1장 날짜 수’·13번 ‘여러 장을 한 번에 찍기는 추후 적용’(대체), 데이터 구조 v2.3.5 공통 계약 `GET /api/residents/:id/print`, 화면 설계 v2.3.0 M3 · 기간 인쇄, `data/forms/form-16.json`, 이슈 #317

## 배경

- PR #318은 ‘서식 쪽은 언제나 한 장’으로 고쳤는데, 이 기준이 틀렸습니다. 기록이 서식 한 장의 날짜 수(별지 제16호 3일, 제12호 7일)를 넘으면 **새 서식 장**이 이어져야 합니다. 그때까지 기간 인쇄는 시작 날짜부터 한 장 분량만 찍을 수 있었습니다.
- 서식의 세부 칸이 비어 나왔습니다. 코디세이 DB의 실제 AI 기록으로 확인한 원인:
  - 제16호 체크: 서식 기준(`web/lib/agent/form-spec.ts`)은 AI에게 `세면 등`, `체위변경`, `이동`처럼 짧은 이름을 쓰게 하는데, 인쇄는 서식 칸의 전체 이름(`체위변경(2시간마다)` 등)이 들어 있어야 체크했습니다.
  - 제16호 식사 종류: 인쇄는 `meal.detail.meal_type`을 보는데 서식 기준에 이 칸 안내가 없어 AI가 채운 적이 없습니다.
  - 제16호 화장실이용하기 횟수: 인쇄는 `support.detail.toilet_count`를 보는데 횟수는 글(‘기저귀 교환 3회’)에만 있었습니다.
  - 제12호 화장실이용하기 체크: 동의어가 `화장실`뿐이라 `기저귀 교환`이 빠졌습니다.

## 결정

1. **서식 장 수:** 기록 1건 인쇄는 서식 한 장입니다. 기간 인쇄는 시작 날짜부터 서식 한 장의 날짜 수(제16호 3일, 제12호 7일)마다 새 서식 장을 만들어 날짜 순으로 한 PDF에 잇습니다. 승인한 기록이 하나도 없는 장은 만들지 않습니다.
2. **기간:** 관리자가 시작 날짜와 **끝 날짜**를 고릅니다. 끝 날짜의 처음 값은 서식 한 장 분량(제12호 시작 + 6일, 제16호 시작 + 2일)이고, 시작 날짜부터 31일까지 늘릴 수 있습니다.
3. **API:** `GET /api/residents/:id/print?from=&to=`. `to`는 선택이고 없으면 지금처럼 한 장 분량입니다. `to`가 `from`보다 앞이거나 31일을 넘으면 400 `invalid_input`. 출력 `days`는 from~to 날마다 한 칸이고, `days_per_sheet`(7 / 3)를 함께 줍니다.
4. **이어쓰기 쪽:** 칸을 넘친 글은 그 서식 장 **바로 뒤** 이어쓰기 쪽에 찍습니다(인쇄이어쓰기쪽 2~4번 그대로). 쪽 표시는 전체 쪽 기준 ‘3/5’, 이어쓰기 쪽은 ‘4/5 이어쓰기’. 뒤쪽 유의사항은 맨 끝에 한 번입니다.
5. **제16호 체크 칸:** 짧은 이름도 같은 칸으로 봅니다. 세면·구강청결·머리감기·몸단장·옷 갈아입 → 세면 칸, 몸 씻기 → 목욕, 체위변경 → 체위변경(2시간마다), 이동·보행 → 이동도움, 인지관리 → 인지관리 지원, 의사소통·말벗·격려 → 의사소통도움.
6. **제16호 식사 종류·화장실 횟수:** 저장 칸(`meal.detail.meal_type`, `support.detail.toilet_count`)이 있으면 그 값을 찍습니다. 없으면 **승인한 글에 하나로 분명히 적혀 있을 때만** 그 값을 찍습니다(‘죽, 조금 드심’ → 죽, ‘기저귀 교환 3회’ → 3). 종류가 둘 이상이거나 ‘2~3회’ 같은 범위, 횟수가 여러 번이면 비웁니다. 승인한 글 밖의 내용은 짐작하지 않습니다(원칙 2).
7. **서식 기준(AI):** 제16호 서식 기준에 `meal.detail.meal_type`(선택지 3개)과 `support.detail.toilet_count`(정수) 안내를 더합니다. 저장 칸 이름은 `data/forms/form-16.json`에 이미 있던 것입니다.
8. **제12호:** 화장실이용하기 체크의 동의어에 `기저귀`, `배변`을 더합니다.
9. **바뀌지 않는 것:** 칸 좌표, 승인한 기록만 찍는 것, 제16호 notes 영역을 관리자가 날마다 고르는 것, 표·RLS·상태 값.

## 검토한 대안

- **대안 A: 3일(7일)씩 여러 번 따로 인쇄:** 코드 변경 없음 / 한 달이면 제16호 10번을 따로 만들고 내려받아야 함. 버림
- **대안 B: 세부 칸은 AI·서버 검사에서만 채우기(인쇄는 저장 칸만):** 인쇄가 단순함 / 이미 승인한 기록은 계속 비어 나오고, 검사·AI 규칙을 바꿔 다시 검증해야 함. 버림(서식 기준 안내만 더함)
- **대안 C: 글에서 종류·횟수를 넓게 추정(‘밥’ → 일반식 등):** 더 많이 채움 / 틀리게 찍을 수 있음. 버림(하나로 분명할 때만)
- **채택:** 날짜 수마다 새 장 + 짧은 이름 동의어 + 분명한 값만 글에서 채우기

## 사유

- 서식은 날짜 열이 정해진 누적 서식이라, 기간이 길면 장이 늘어나는 것이 원문 쓰임과 같습니다.
- 인쇄 쪽에서 채우면 이미 승인한 기록도 다시 승인하지 않고 바로 맞게 나옵니다.
