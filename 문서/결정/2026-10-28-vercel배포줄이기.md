# Vercel 자동 배포는 main에 합칠 때만 한다 (브랜치·PR 미리보기 끔)

- **상태:** 유효
- **정한 날·사람:** 2026-10-28 · 2dion
- **관련:** [Vercel 배포 다시 켬](2026-10-19-vercel배포재개.md)(대체함), [기술 선택 v1.1](../설계/기술선택-v1.1.md) '배포: Vercel'

## 배경

Vercel 무료(Hobby) 요금제는 하루 배포 100번, 동시 빌드 1개까지입니다.[1] 10/27에는 하루 51번, 10/28에는 저녁까지 40번 배포했습니다. 그중 약 60%가 브랜치에 올릴 때마다 생기는 미리보기(Preview) 배포였습니다.[2] 여러 사람과 AI가 동시에 브랜치를 올리면서 한도에 가까워지고, 빌드 대기도 길어졌습니다.

## 결정

- `web/vercel.json`의 `git.deploymentEnabled`로 **main 브랜치만** 자동 배포합니다. 다른 브랜치(be/·fe/·qa/·claude/ 등)에 올려도 배포를 만들지 않습니다.[3]
- 그래서 배포는 **PR을 main에 합칠 때 1번**(Production) 생깁니다.
- 합치기 전 화면 확인은 로컬(`npm run dev`)이나 GitHub Actions "web 검사"(빌드 포함)로 합니다. 꼭 미리보기 주소가 필요하면 Vercel 대시보드 Deployments → Create Deployment에서 브랜치를 골라 손으로 1번 만듭니다(확인 필요: 이 설정이 손으로 만드는 배포까지 막는지 아직 안 해 봄).

## 검토한 대안

- Ignored Build Step(`ignoreCommand`)으로 web/이 안 바뀐 커밋 건너뛰기: 건너뛴 배포도 '취소된 배포'로 남아 하루 한도와 동시 빌드 칸을 똑같이 씁니다.[4] 한도를 줄이지 못해 버림.
- 모노레포 '바뀌지 않은 프로젝트 건너뛰기': 건너뛴 배포는 한도에 안 세지만, 저장소 루트에 npm workspaces와 루트 lockfile이 있어야 합니다.[5] 지금 구조(web/ 안의 lockfile)를 바꿔야 해서 버림.
- GitHub Actions에서 Vercel CLI로 web/이 바뀐 PR만 배포: 가장 정확하지만 Vercel 토큰을 GitHub 비밀값에 넣고 워크플로를 관리해야 함. 지금 줄인 양으로 충분하면 쓰지 않음(확인 필요: 그래도 한도에 가까워지면 다시 정함).

## 사유

미리보기를 끄면 하루 배포가 main 합치기 수(10/27~28 하루 약 20번)로 줄어 한도의 1/5 정도가 됩니다.[2] 설정 파일 한 개만 더하면 되고, 대시보드 설정이나 비밀값이 필요 없습니다.

## 영향

- PR에 Vercel 미리보기 주소와 Vercel 검사가 더 이상 뜨지 않습니다. PR 확인은 "web 검사"로 합니다.
- 문서만 바뀐 PR을 합쳐도 Production 배포는 1번 생깁니다(위 대안 1 이유로 막지 않음).
- `web/vercel.json`을 지우거나 고치면 다시 브랜치마다 배포됩니다.
