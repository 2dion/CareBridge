- **관련:** [기술 조합](2026-10-16-기술조합.md), [코디세이 API](2026-10-20-코디세이api.md), [STT Groq](2026-10-20-stt-groq.md), [파일 이름 검사 범위](2026-10-18-파일이름검사범위.md)

## 배경

기술 조합(Next.js + Vercel + Supabase, Claude는 코디세이, 받아쓰기는 Groq)은 정해졌지만, 폴더 위치·패키지 도구·검사 도구는 정하지 않았습니다. 10/23 기능 마감까지 여러 사람이 동시에 코드를 쓰므로 첫 코드 PR에서 한 번에 정합니다.[1]

## 결정

- 앱은 저장소의 `web/`, Supabase 설정은 `supabase/`에 둡니다. Vercel Root Directory는 `web`.
- Next.js 16(App Router, TypeScript), Node.js 22 이상, 패키지 도구는 npm.
- 스타일은 Tailwind CSS(create-next-app 기본값). 글꼴은 내려받지 않고 기기 한글 글꼴.
- 검사: ESLint(Next.js 기본), Prettier, `tsc`, Vitest. GitHub Actions "web 검사"가 `web/`이 바뀔 때 모두 돌림.
- `USE_MOCK_AI`가 `false`가 아니면 Mock 모드입니다. 스위치 하나가 Claude와 받아쓰기를 함께 막습니다. Mock이면 화면 위에 MOCK 띠를 보입니다.
- 모델 이름과 주소의 기본값은 `web/lib/config.ts` 한 곳에 둡니다.

## 검토한 대안

- 저장소 루트에 바로 Next.js: 폴더가 하나 줄지만 `문서/`·`참고자료/`와 코드 설정 파일이 뒤섞이고, 파일 이름 검사 결정에서 이미 `web/`을 코드 폴더로 적어 둠.
- pnpm·yarn: 설치가 빠르지만 팀원이 하나 더 설치해야 함.
- CSS Modules만 쓰기: 의존성이 하나 줄지만 반응형 화면을 빨리 만들기 어렵고, 기본 템플릿에서 빼는 수고가 듦.
- Jest: 오래 쓰였지만 TypeScript·ESM 설정이 더 필요함.
- Mock 스위치를 Claude·STT 따로: 한쪽 키만 있을 때 편하지만 설정이 늘어남. 필요해지면 나눔.

## 사유

새로 배울 것과 설정 파일을 가장 적게 하면서, 키 없는 팀원도 첫날부터 같은 검사를 통과시키게 하기 위해서입니다.
