# 화면·문서·코드가 같은 용어를 쓰도록 용어 표를 정하고, 화면 번호는 W·R·A 하나로 한다

- **상태:** 유효
- **정한 날·사람:** 2026-10-29 · 2dion(팀장)
- **관련:** 이슈 #94, [용어집 v1.0](../설계/용어집-v1.0.md), 결정 `2026-10-27-상태이름.md`·`2026-10-25-강사흐름통일.md`·`2026-10-27-녹음화면버튼.md`, 화면 설계 v1.3

## 배경

같은 것을 화면·코드·설계 문서·피그마에서 다르게 불렀습니다.[1] 상태 이름은 10/27에 새 이름으로 정했지만,[2] 문서·주석·베트남어에는 옛 이름(보냄, 되돌아온 기록, 기록함 등)이 남았습니다. 화면 번호도 W·R·A(문서) 말고 피그마의 M(휴대폰)·D(PC) 번호가 파일마다 따로 있어, 같은 M05가 '오늘'과 '기록 시작'을 함께 가리켰습니다.[3]

## 결정

1. **용어 표:** 개념(기록 상태, 사람·기관, 기록·서식, 항목, 동작, 녹음·AI, 화면) 단위로 '쓰는 이름 / 쓰지 않는 이름 / 영어 이름 / 베트남어 / 화면'을 한 표에 둡니다. 표는 [용어집 v1.0](../설계/용어집-v1.0.md)에 있습니다.
2. **영어 이름은 바꾸지 않습니다.** DB 표·칸·값, API, 코드 이름은 그대로 두고 대응만 적습니다.

## 검토한 대안

- **화면 순서로 정리:** 같은 말이 여러 화면에 걸쳐 여러 번 나와 다른 표기를 한 줄에서 비교하기 어렵습니다. 화면은 '화면' 칸으로 대신했습니다.
- **상태 이름만 '전송', 문장·버튼은 '보내다':** 낱말이 쉬워지지만, 같은 일을 두 말로 불러 혼동이 남습니다(팀장).
- **화면 번호에 M·D를 함께 씀:** 피그마 파일마다 번호가 달라 대응표가 계속 늘어납니다.
- **'담당자'(검토하는 사람):** 처음 고른 이름이지만, 맡은 일이 드러나지 않는 중립적인 말이라 검토·승인하는 사람을 가리키기 어렵습니다(10/29 팀장·기획 담당). 그래서 '관리자'로 바꿨습니다.
- **'관리자가 수정을 요청했어요':** 뜻은 분명하지만 '요청하다'가 딱딱합니다. 외국인 요양보호사의 최소 한국어 기준(E-7 비자, TOPIK 3급 등)을 생각해 말하듯 쓰는 '수정해 달라고 했어요'를 골랐습니다.[4]

## 사유

작성자가 같은 일을 한 이름으로만 보게 하고, 팀원과 AI 코딩 도구가 화면 번호 하나로 같은 화면을 가리키게 합니다. 영어 이름을 그대로 두어 DB·API는 바뀌지 않습니다.

## 영향

- **문서(기획 담당):** 용어 표를 설계 폴더의 [용어집 v1.0](../설계/용어집-v1.0.md)으로 따로 둠. 화면 문구 v1.0은 화면 글자가 코드에 들어가 [보관](../보관/설계/2026-10-29-화면문구-v1.0.md)으로 옮김(10/29 팀장). AGENTS.md·화면 설계 v1.3·기획안·데이터 구조·AI 규칙의 '쓰지 않는 이름'(담당자, 보냄, 되돌아온, 기록함, 음성 메모, R4 설정 등)은 이슈 #94 다음 PR에서 고침. 이미 쓴 결정 기록 본문은 그때 기록이라 고치지 않음.
- **화면(프론트엔드 담당):** 화면 글자를 표대로 고침(전송 통일 목록, W1 안내, W3 '수정할 내용', W2 버튼, 하단 탭 '기록', 담당자 → 관리자, 베트남어 người quản lý). 교육용 기관에서 작성자·관리자를 교육생·강사로 보이게 함(`organizations.is_training`, QA 테스트 뒤). 코드 주석의 피그마 M·D 번호를 W·R·A로 바꿈. PR #130.
- **피그마:** '개발 v1.0'은 화면을 프론트엔드 코드로 옮길 때 쓴 화면 초안이라, 코드가 생긴 지금은 화면 초안·참고 자료로만 둡니다. 용어·번호를 피그마에 맞추지 않습니다(팀장 10/29).
- **서버(백엔드 담당):** 오류 문구·DB 함수 메시지의 '담당자'·người phụ trách를 '관리자'·người quản lý로. DB·API 이름은 그대로.
- **테스트(QA 담당):** 화면 글자로 찾는 테스트를 새 이름으로 고치고, 옛 이름 검색 결과를 이슈 #94에 남김.
