# PR #67의 되돌림 사유·검토 요약·인쇄를 팀장 결정에 맞춘다

- **상태:** 유효
- **정한 날·사람:** 2026-10-27 · 2dion(팀장)
- **관련:** PR #67 상충점 7~10, 화면 설계 v1.3 W3·R2·R3, 데이터 구조 v1.6.2 공통 계약·서식 칸 대응

## 배경

피그마 ‘개발 v1.0’을 옮긴 PR #67에서 되돌림 항목 칩, 번역, 검토 요약과 인쇄가 문서와 달랐습니다. 팀장이 10/27 이 대화에서 방향을 정했습니다.[1]

## 결정

1. **되돌림 항목은 사유 문자열에 포함:** `[식사, 복약 관찰] 사유`처럼 `reason` 앞에 붙입니다. `return_items` 칸은 만들지 않고 작성자에게 사유 전체를 보여 줍니다.
2. **번역은 실제 API에서 채움:** 되돌리기 API는 항목 이름이 붙은 사유 전체를 번역해 `return_reason_native`로 돌려줍니다. 항목 수정 API는 담당자가 바꾼 `value_ko`를 재번역해 `value_native`로 돌려줍니다. Mock의 빈 번역을 번역 완료로 보지 않습니다.
3. **R2 요약은 ‘확인 필요 N · 처리 완료 M’:** N은 `status = needs_check`이고 `resolution`이 빈 항목 수, M은 `status = needs_check`이고 `resolution`을 고른 항목 수입니다. [확인함]과 [기록 안 함]을 모두 처리 완료로 셉니다. 다시 열면 N으로 돌아갑니다. ‘근거 못 찾음·설명 의심’ 숫자는 화면에 추가하지 않습니다. 검증 코드의 검사는 유지합니다.
4. **인쇄는 법정 양식 원문 그대로:** 별지 제16호·제12호의 칸·배치·일수 열·서명란·뒤쪽 유의사항을 유지합니다. 별도 HTML 양식이나 제16호 네 영역 아래의 독립 ‘특이사항’ 칸을 만들지 않습니다. 저장소에 확보한 원문 PDF를 사용합니다.

## 검토한 대안

- `return_items` 신설: 항목별 표시에 유리하지만 팀장이 기존 사유 문자열 방식을 선택했습니다.
- 검증 내부 숫자 노출: 응답 칸을 늘려야 하며, 이번에는 미처리·처리 완료 두 수로 정했습니다.
- 법정 서식을 닮은 HTML 출력: 원문에 없는 칸과 일수·서명 배치가 생겨 채택하지 않습니다.

## 사유

기존 계약으로 되돌림과 검토를 처리하고, 인쇄 양식은 확보한 법정 원문과 일치시킵니다.

## 영향

- **FE:** R2 요약 이름을 바꾸고 R3에서 법정 원문 PDF에 기록을 채워 미리보기·내려받기·인쇄합니다. 빈 원문 보기는 별도 버튼입니다. 제16호 3일·제12호 7일 칸 중 첫 날짜 열을 쓰고, 칸보다 긴 내용은 같은 원문을 복제해 이어 씁니다. 뒤쪽 유의사항은 그대로 붙이며 없는 정보·서명은 비워 둡니다.
- **BE:** 실제 기록 API의 되돌림 사유 번역·항목 재번역을 구현해야 합니다. 이 브랜치에는 기록 API가 아직 없습니다.
- **데이터·BE:** 법정 양식 사용 결정이 제16호 `notes`의 영역별 저장 방법을 정한 것은 아닙니다. 이번 인쇄 구현에서는 담당자가 자유 서술 `notes` 전체를 넣을 영역을 고르며, 이 선택은 PDF 생성에만 씁니다. 저장 칸·API는 늘리지 않습니다. 수면·불편감·복약 관찰은 기존 대응표의 신체활동지원 특이사항에, 인지 변화는 인지관리 및 의사소통 특이사항에 넣습니다. 복약 관찰만으로 간호 행위를 체크하거나 승인자를 종사자 서명으로 넣지 않습니다.
- **기획·설계:** R2 요약·되돌리기 계약 설명과 R3 인쇄 설명을 맞춥니다.
- **QA:** [확인함]·[기록 안 함]·다시 열기의 숫자, 원문 두 쪽과 제16호 3일·제12호 7일 열이 유지되는지 확인합니다.
