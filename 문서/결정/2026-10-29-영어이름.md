# 뜻이 겹치거나 둘로 갈린 영어 이름 세 개를 용어집에 맞춰 바꾸고, 강사의 베트남어는 giảng viên으로 한다

- **상태:** 유효
- **정한 날·사람:** 2026-10-29 · 2dion(팀장)
- **관련:** 이슈 #94·#145·#146, [용어통일 결정](2026-10-29-용어통일.md) 2번(이 결정이 일부 바꿈), [용어집 v1.0](../설계/용어집-v1.0.md), [데이터 구조 v1.6.4](../설계/데이터구조-v1.6.5.md)

## 배경

용어통일 결정은 "영어 이름은 바꾸지 않고 대응만 적는다"로 정했습니다.[1] 대응표를 만들고 보니 영어 이름 세 개가 한국어 이름과 어긋났습니다.[2]

- `record_items.confirmed`(작성자 [맞아요])는 관리자 [확인함]의 `resolution = confirmed_by_reviewer`와 이름이 겹쳐, 누가 확인했는지 이름만으로 알 수 없었습니다.
- Agent 도구 `submit_draft`(초안 반환)는 기록 전송 `/submit`·`submitted`와 같은 낱말을 써서 '전송'과 헷갈렸습니다.
- 용어 검색은 Agent 도구가 `search_terms`, DB 함수가 `search_glossary`로 한 가지 일에 이름이 둘이었습니다.

용어집의 '강사' 베트남어도 '확인 필요'로 비어 있었습니다.

## 결정

1. **영어 이름 세 개를 바꿉니다.**
   | 무엇 | 전 | 후 |
   | --- | --- | --- |
   | 작성자 [맞아요] 칸 (`record_items`, PATCH 입력, 이력 `before`·`after` 키) | `confirmed` | `confirmed_by_worker` |
   | Agent 도구 ② 용어 검색 (`agent_steps.tool` 값 포함) | `search_terms` | `search_glossary` |
   | Agent 도구 ④ 초안 반환 (`agent_steps.tool` 값 포함) | `submit_draft` | `return_draft` |
2. **나머지 영어 이름은 그대로 둡니다.** 역할 값 `worker`·`reviewer`, 화면 묶음 `(worker)`·`(reviewer)`, 상태 값 등은 RLS·권한 전체에 걸려 있어 바꾸지 않습니다. 오류 키 `unconfirmed_items`도 그대로입니다.
3. **강사의 베트남어는 giảng viên**입니다. 뜻을 그대로 옮깁니다. 교육생은 học viên입니다.
4. 화면에 교육생·강사로 구분해 보이는 일(`organizations.is_training`)은 프론트엔드 담당·QA 담당에게 이슈 #146으로 맡깁니다.

## 검토한 대안

- **대응만 적고 그대로 두기(용어통일 결정 2번):** DB·API는 안 바뀌지만, 새로 코드를 쓰는 사람과 AI 코딩 도구가 `confirmed`와 `confirmed_by_reviewer`, `submit`과 `submit_draft`를 계속 헷갈립니다.
- **`submit_draft` → `ai_submit`:** 여전히 '전송(submit)'과 겹칩니다. 한국어 '초안 반환'과 같은 `return_draft`로 정했습니다.
- **용어 검색을 `search_terms`로 통일:** 표 이름이 `glossary`라 DB 함수 이름 `search_glossary`에 맞추는 편이 바뀌는 곳이 적습니다.

## 사유

이름 하나에 뜻 하나만 두어 화면·코드·문서가 같은 것을 같은 이름으로 부르게 합니다(용어통일의 목적).[1] 세 이름은 기록 화면·Agent 안에서만 쓰여, 역할·상태 값보다 바꾸는 범위가 작습니다.

## 영향

- **DB(백엔드 담당):** 마이그레이션 `20261029130000_english_names.sql`. 칸 이름 바꾸기, `agent_steps.tool` 제약·쌓인 값 바꾸기, 칸 이름을 쓰는 함수 5개(`record_items_before_update`, `record_items_log_edit`, `records_before_update`, `save_ai_item`, `save_record_ai_draft`) 다시 만들기. 원격 DB에도 반영.
- **공통 계약:** 데이터 구조 v1.6.3 → v1.6.4. PATCH 입력 `confirmed` → `confirmed_by_worker`, Agent 도구 이름 두 개.
- **코드:** `web/` 서버·화면·데모 데이터. 데모 저장소 키를 `carebridge-demo-db-v3`로 올려 옛 데모 데이터는 새로 만듦.
- **문서:** 용어집, 기획안, AI 규칙, 기술 선택, 기술 검토, 코디세이 API, data/README, 교재 용어 목록 설명.
- **QA 담당:** `confirmed`로 PATCH를 보내던 테스트는 `confirmed_by_worker`로 바꿈.
