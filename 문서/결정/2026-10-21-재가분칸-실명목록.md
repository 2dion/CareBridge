# 재가 지원별 분 칸은 support.detail.minutes 키 6개, 실명 검사는 같은 기관 계정 이름으로

- **상태:** 일부 대체됨 (2026-10-30, 실명 목록·실명 보관 부분은 [어르신실명사진](2026-10-30-어르신실명사진.md). 분 칸은 유효)
- **정한 날·사람:** 2026-10-21 · 2dion (백엔드 담당 대신 결정)
- **관련:** 데이터 구조 v1.2 '서식 칸 대응'(support detail 시간 구조), AI 규칙 v1.1 '서버 검사' 검사 5·6, `web/lib/agent/validate-draft.ts`

## 배경

기록 검증 코드(#14)가 두 값을 첫 안으로 두고 "백엔드 담당과 확인 필요"로 남겼습니다.[1] 재가 제공시간 합 검사(검사 5)는 지원별 분이 어느 칸에 어떤 이름으로 들어가는지 알아야 하고, 실명 검사(검사 6)는 서버가 어떤 이름 목록을 넘길지 정해야 합니다. 데이터 구조 v1.2는 "세부 칸 이름은 BE가 정함", AI 규칙 v1.1은 "검사 방법은 구현 때 정함"으로만 적었습니다.[2][3]

## 결정

**1. 재가 지원별 분: `record_items.detail.minutes` (support 항목), 키 6개 고정**

별지 제12호에서 분을 적는 칸 6개를 그대로 옮깁니다.[4]

| 키 | 별지 제12호 칸 |
| --- | --- |
| physical | 신체활동지원 제공시간(합계) |
| cognitive_stimulation | 인지활동지원 > 인지자극활동 |
| daily_living_together | 인지활동지원 > 일상생활 함께하기 |
| cognitive_management | 인지관리지원 |
| emotional | 정서지원 |
| housework | 가사 및 일상생활지원 제공시간(합계) |

- 값은 정수(분)입니다. 제공하지 않은 영역은 키를 빼거나 0으로 둡니다. 다른 키는 쓰지 않습니다.
- 체크 칸(세면 등, 목욕, 체위변경 등)은 `detail.checks`(문자열 목록)에 둡니다.
- 시설(별지 제16호)은 지원별 분 칸이 없어 `minutes`를 쓰지 않습니다.
- 검사 5는 `minutes` 값의 합 ≤ 방문 시간(분)을 봅니다.

**2. 실명 검사 목록(`blockedNames`): 같은 기관 계정 이름(`profiles.name`)**

- 서버는 기록의 기관(`org_id`)에 속한 모든 계정의 `profiles.name`을 넘깁니다. 가명 표시(○)가 있거나 한 글자인 이름은 검사 코드가 뺍니다.
- 어르신은 DB에 가명(`residents.alias`)만 있어 시스템이 실명을 알 수 없습니다. 어르신·가족 실명은 AI 규칙(쓰기 원칙 5: '어르신', '보호자'로 씀)으로 막고, 검사로 다 잡지 못한다는 점을 한계로 둡니다.
- 어르신 실명을 따로 등록하는 칸은 MVP에서 만들지 않습니다.

## 검토한 대안

- 분 칸을 자유 키로 둠: 칸이 늘어도 고칠 것이 없지만, AI·화면·인쇄가 서로 다른 이름을 쓸 수 있음.
- 분을 form_fields에 둠: 인쇄에는 가깝지만, 항목(support)의 근거·확인 상태와 떨어짐.
- 실명 목록에 어르신 실명 칸을 더함: 더 많이 잡지만, 실명을 DB에 넣게 되어 '가명만 저장' 원칙과 어긋남.
- 실명 검사를 하지 않음: 코드는 줄지만, 직원 이름이 기록에 들어가는 것도 못 막음.

## 사유

분 칸은 법정 서식의 칸과 1:1로 맞추면 AI, 검증, 인쇄가 같은 이름을 씁니다. 실명은 시스템이 확실히 아는 이름만 검사하고, 모르는 이름은 프롬프트 규칙과 사람 확인에 맡기는 것이 '가명만 저장' 원칙을 지키는 가장 작은 방법입니다.[3][5]

## 영향

- **데이터 구조 v1.2:** '서식 칸 대응'의 support detail 시간 구조에 키 6개(이 PR).
- **AI 규칙 v1.1:** 검사 6의 '확인 필요'를 이 방법으로(이 PR).
- **코드:** `validate-draft.ts`는 이미 `detail.minutes`의 숫자를 모두 더하므로 동작은 같고, 주석의 '확인 필요'만 이 결정으로 바꿉니다(이 PR).
- **서버(백엔드 담당):** validate_draft·submit_draft를 부를 때 `blockedNames`에 같은 기관 `profiles.name` 목록을 넣습니다. Agent 프롬프트의 support detail 예시를 키 6개로 맞춥니다.
- **데이터 담당:** 서식 기준 JSON(별지 제12호)의 분 칸 이름을 이 키로 씁니다.
- **테스트(QA 담당):** 키 6개로 합 검사, 직원 이름이 들어간 기록이 '확인 필요'가 되는지.
