# 초안 서버 검사 보강: 섭취량 세 값, 내용 빈 '확인 필요', 확인 요청 문장 거르기, 재가 분 합 재검사, 프롬프트 규칙

## 배경

10/29 QA 점검(배포본, 실제 연결)에서 AI 초안과 서버 검사의 빈틈이 여섯 건 나왔습니다.[1]

- 식사 섭취량 `detail.intake` 값이 서식 기준(`"1/2 이상"`), AI 규칙·정답 사례·인쇄 코드(`half_or_more`)에서 서로 달랐고, 검사가 없어 `"needs_check"` 같은 값이 공식 기록에 저장됐습니다(#133).
- '확인 필요'인데 `value_ko`가 빈 항목을 서버가 그냥 저장해, W3 고치기 화면의 'AI가 정리한 내용'이 빈칸이었습니다(#141).
- AI가 "섭취량 확인 필요(… 불명확)" 같은 질문 문장을 `value_ko`에 넣어 승인 뒤 제12호 PDF에 찍혔습니다(#117).
- 작성자가 W3에서 지원별 분을 직접 넣어 합(200분)이 방문 시간(180분)을 넘어도 제공 지원이 '확인 필요'가 되지 않고 승인됐습니다. 검사 5는 Agent 초안 검증 때만 돌았고, `reason`은 로그인 사용자가 쓰지 못하는 칸이라 PATCH 길에서는 이유를 남길 수 없었습니다(#116).
- AI 초안이 재가 제12호 숫자 칸(방문 시작·종료, 지원별 분)을 비웠고(#115), 용어 검색이 비면 무조건 '확인 필요'로 두어 '확인 필요'가 너무 많았으며, 특이사항을 지어내고, 고친 글을 기록체로 정리하지 않고, 번역이 성별을 짐작했습니다(#121).

## 결정

1. **섭취량 저장 값은 `full` / `half_or_more` / `under_half` 세 가지입니다.** 서식 기준(`get_form_spec`)은 `"full (1, 전량)"`처럼 저장 값과 뜻을 함께 주고, 검사 7(`invalid_intake`)이 세 값이 아닌 `intake`를 빼고 식사를 '확인 필요'(이유 "섭취량을 정하지 못함" / "Chưa xác định được lượng ăn")로 둡니다. `null`이거나 없으면 검사하지 않습니다.
2. **'확인 필요'인데 `value_ko`가 비면 문제(`needs_check_without_value`)로 알립니다.** 상태는 그대로 두고 Agent가 근거 문장을 기록체로 옮겨 채우게 합니다. 자동 정리 중단 초안(9개 모두 빈 '확인 필요')은 그대로 저장됩니다.
3. **`value_ko`의 확인 요청 문장은 서버가 걸러 냅니다(검사 8, `question_in_value`).** "확인 필요", "확인이 필요", "확인해 주세요", "확인 요망", "확인 바람", "확인 요청", "확인할 것", "용어 확인", "불명확", "불분명"이 든 문장(괄호 안이면 괄호만)을 `value_ko`에서 빼고 항목을 '확인 필요'로 둡니다. `reason`이 비었으면 뺀 문장을 `reason`에, `reason_native`에는 코드 이유 번역을 넣습니다. 프롬프트(Agent·항목 보태기)에도 같은 규칙을 적습니다.
4. **재가 제공 지원은 작성자가 고친 뒤와 전송 직전에 다시 검사합니다.** 검사 5 코드를 `checkSupportMinutes`로 떼어 Agent 초안 검증과 재검사가 같은 코드를 씁니다. 작성자가 `support`나 `visit_time`을 PATCH로 고친 뒤와 `/submit` 직전에 `web/lib/records/support-check.ts`가 돌아, 합이 넘으면 '확인 필요' + 이유(한국어·모국어)를 붙이고, 합이 맞으면 서버가 붙였던 검사 5 이유만 걷어(AI 이유는 보존) 다른 이유가 없고 내용이 있으면 '관찰'로 되돌립니다. 방문 시간은 `records.visit_start~visit_end` → `form_fields.total_minutes` → `visit_time.detail.start·end` 순으로 찾습니다. 재검사가 실패해도 고친 내용 저장과 전송은 막지 않습니다.
5. **`save_ai_item`에 mode `check`를 더합니다.** `status`·`reason`·`reason_native`만 바꾸고, `value_ko`·`evidence`·`detail`·`source`·`confirmed_by_worker`는 그대로입니다. 작성자 본인이 draft·returned일 때만 되고(`not_record_worker`), 기준 글이 다르면 `stale_item`, 상태 값이 틀리면 `invalid_item`입니다. 마이그레이션 `20261029160000_save_ai_item_check.sql`.
6. **프롬프트 규칙을 보강합니다.** (a) 재가 숫자 칸: 방문 시각은 `visit_time.detail.start·end`("HH:MM")와 `form_fields.total_minutes`, 지원별 분은 `support.detail.minutes` 키 6개에 말한 숫자를 채우고, 말하지 않은 숫자는 비움. 서식 기준에 말→키 대응(청소·빨래 → `housework` 등)을 적음. (b) `search_glossary` 결과가 비어도 뜻이 분명한 일상 표현은 기록체로 정리해 '관찰'로 두고, "용어 검색 결과 없음"만으로 '확인 필요'로 두지 않음(AI 규칙 '상태 판정 기준' 2번과 도구 설명을 같이 고침). (c) `notes`·`next_check`도 원문에 없으면 '언급 없음'. (d) 번역은 성별을 정하지 않음(ông/bà). (e) 항목 보태기는 한국어 말투 그대로 쓴 글도 기록체로 고침.
7. **코드 이유의 번역은 앞부분으로 찾습니다.** "지원별 제공시간 합이 방문 시간보다 김 (200분 > 180분)"처럼 숫자가 붙은 이유도 번역에 숫자를 그대로 붙입니다(전에는 빈칸).

## 검토한 대안

- **섭취량 값을 서식 기준의 `"1/2 이상"`으로 통일:** 사람이 읽기 쉬움 / AI 규칙 예시·정답 사례·인쇄 코드가 이미 영어 값을 쓰고, 공백·슬래시가 든 값은 키로 쓰기 나빠 버림.
- **확인 요청 문장은 프롬프트로만 막기:** 코드가 단순 / 프롬프트만 고치면 다시 섞일 수 있어(QA 지적) 서버 검사를 둠. 프롬프트도 같이 고침.
- **재검사 결과를 `save_ai_item(item)`으로 저장:** 함수 추가 없음 / `source = worker`·`confirmed_by_worker = false`로 덮어써 작성자의 [맞아요]가 풀리고 AI 출처 항목을 작성자 수정으로 바꿔 버려 버림.
- **재검사용 새 RPC를 따로 만들기:** 뜻이 분명 / 기관·기록·기준 글 검사가 `save_ai_item`과 같아 mode로 합침(항목하나저장 결정의 사유와 같음).
- **`reason` 쓰기를 로그인 사용자에게 열기:** 가장 빠름 / 10/28 기록계약보강 4번과 어긋나 버림.
- **방문 시간이 바뀔 때 화면(FE)이 `status`만 바꾸기:** 서버 변경 없음 / 이유를 남길 수 없고 전송 직전 재검사도 못 해 버림.

## 사유

승인 조건·시간 합·상태 변화는 코드가 맡는다는 원칙(AGENTS.md 5번)대로, 사람이 고친 뒤에도 같은 검사가 서버에서 돌아야 합니다. 저장은 기존 서버 전용 함수에 가장 작은 mode 하나를 더해 권한 계약(10/28)을 지킵니다. 프롬프트는 QA가 본 실제 문장을 예로 넣어 다음 점검에서 비교할 수 있게 했습니다.
