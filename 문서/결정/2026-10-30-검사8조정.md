# 서버 검사 8은 AI의 의문만 걸고, 정상 기록 문장은 지우지 않는다

- **상태:** 유효
- **정한 날·사람:** 2026-10-30 · 백엔드 담당 (QA 버그 목록 10/30, 이슈 #177)
- **관련:** AI 규칙 v1.1.2 서버 검사 8, 결정 [2026-10-29-초안검사보강](2026-10-29-초안검사보강.md), 이슈 #117 #177

## 배경

10/29에 검사 8(`question_in_value`)을 넣어 AI가 `value_ko`에 쓴 확인 요청 문장("섭취량 확인 필요(… 불명확)")을 걸러 냈습니다(#117). 그런데 이 검사가 정상 기록도 지웠습니다. "내일 오전 혈압 확인 필요"(다음 확인사항)와 관찰한 증상 "말씀하실 때 발음이 불분명하심"의 내용이 빈칸이 되고 '확인 필요'로 바뀝니다. 공식 기록 내용이 사라지는 문제라 위험도가 높습니다(#177). 항목 보태기·글로 고치기도 같은 검사를 써서 작성자가 직접 말한 문장도 지워질 수 있었습니다.

## 결정

1. **다음 확인사항(`next_check`)은 검사 8에서 뺍니다.** 내용 자체가 "○○ 확인 필요" 같은 할 일입니다.
2. **'불명확'·'불분명'은 낱말 목록에서 빼고, AI의 의문 꼴일 때만 겁니다.** "~지 불명확", "불명확함(…)"처럼 판단을 못 하겠다는 말입니다. 원문에서 관찰한 증상("발음이 불분명하심")은 걸지 않습니다.
3. **문장을 통째로 지우지 않고 확인 요청 토막만 뺍니다.** 괄호 안 확인 요청은 괄호만, 쉼표로 이어진 문장은 확인 요청이 든 토막만 뺍니다. 토막이 하나뿐이면 그 문장을 뺍니다. 숫자 안의 점("1.5")에서는 문장을 자르지 않습니다.
4. #117 사례("섭취량 확인 필요(반 그릇이 … 불명확)")는 지금처럼 걸러지고, 빠진 문장은 `reason`으로 옮겨집니다.

## 검토한 대안

- 대안 A: 검사 8을 없애고 프롬프트만 믿기 / 프롬프트만 고치면 다시 섞인다는 #117의 경험 때문에 버림
- 대안 B: '불명확'·'불분명'을 목록에 그대로 두기 / 관찰한 증상을 지우는 원인이라 버림
- 대안 C(채택): 걸러 내는 범위를 AI의 의문 꼴로 좁히고, 지울 때도 필요한 만큼만 지우기

## 사유

원칙 2(지어내지 않음)는 AI가 덧붙이는 것뿐 아니라 원문을 정리한 내용을 서버가 빼는 것도 원문과 달라지게 하므로, 서버 검사는 AI가 덧붙인 확인 요청만 골라내야 합니다.
