# 담당 연결(assignments)의 작성자·어르신 짝은 만든 뒤 바꾸지 못하고, 바꾸려면 지우고 다시 넣는다

- **상태:** 유효
- **정한 날·사람:** 2026-11-07 · 백엔드 담당 (이슈 #394 2번, 검토 세션 지적)
- **관련:** 결정 [담당끊기전검사](2026-11-07-담당끊기전검사.md)(끊기 전 검사·담당 이력), 데이터 구조 v2.3.11 권한 규칙 `assignments`, RLS `assignments_reviewer_update`

## 배경

- RLS 정책 `assignments_reviewer_update`는 같은 기관 관리자의 `update`를 칸 구분 없이 허용합니다. API로 `worker_id`·`resident_id`를 바꾸면 담당 끊기 전 검사(`assignments_before_delete`, 지우기에만 돎)를 건너뛰고, 담당 이력(`assignment_history`)은 옛 짝을 못 찾아 열린 채 남습니다.
- 앱(M4 어르신 수정)은 담당을 바꿀 때 지우고 다시 넣기만 써서 화면 경로는 없지만, 규칙은 DB가 맡아야 합니다(바꾸지 않는 원칙 5).

## 결정

1. `assignments`의 `worker_id`·`resident_id`·`org_id`는 만든 뒤 바꾸지 못합니다. 바꾸려면 지우고(끊기 전 검사·이력이 돎) 다시 넣습니다.
2. DB 트리거 `assignments_keep_keys`(before update)가 막고, 오류 키는 `assignment_key_locked`입니다. 같은 값으로 다시 쓰는 것은 막지 않습니다.
3. 바꿀 수 있는 칸은 `start_date`·`visit_days`·`schedule`입니다. RLS 정책은 그대로입니다.

## 검토한 대안

- **칸 권한(`grant update (start_date, visit_days, schedule)`)으로 좁히기:** 정책 한 줄로 끝남 / PostgREST `upsert`(on conflict do update)가 보낸 칸을 모두 `set`에 넣어 `worker_id`·`resident_id`에도 update 권한이 필요하고, 앱의 M4 저장 경로(upsert)가 깨짐. 버림
- **앱에서만 지우고 넣기:** 지금 상태 / API 직접 호출을 막지 못함. 버림
- **채택:** 트리거로 짝 고정 + 같은 값 덮어쓰기는 허용(upsert 경로 유지)

## 사유

지우기에만 있는 검사·이력을 바꾸기로 우회할 수 없게 하면서, 앱의 저장 방식(upsert)을 바꾸지 않는 가장 작은 변경입니다.
