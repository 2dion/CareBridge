# W6(도우미) 대화를 '대화' 단위로 묶고, '이전 대화' 목록에서 하나씩 불러온다

- **상태:** 유효
- **정한 날·사람:** 2026-11-03 · 2dion(팀장)
- **관련:** 결정 [2026-10-31-도우미대화저장](2026-10-31-도우미대화저장.md) 10번(추후 적용 → 이번에 정함), 데이터 구조 v2.1.0(표 `helper_conversations`, `helper_messages.conversation_id`, 공통 계약 helper API 3개), 화면 설계 v2.1.0 W6·W6 · 이전 대화, 이슈 #251

## 배경

- 10/31 결정으로 도우미 질문·답이 `helper_messages`에 남고, W6를 열면 최근 50개가 한 채팅창에 이어 보입니다(이슈 #218, PR #222).[1]
- 질문이 쌓이면 한 줄로 길게 이어져 예전 질문을 찾기 어렵습니다. 팀장은 10/31에 "다음 주에 별도 이전 대화 기록 화면을 만들어 질문 내용이 많아지면 분리하여 불러오는, 지금 Claude나 GPT 같은 모습"으로 정했고, 대화를 묶는 단위는 그때 정하기로 했습니다.[1][2]

## 결정

1. **묶음 단위 = 대화:** 작성자가 [새 대화]를 누르고 처음 물은 질문부터 다음 [새 대화]까지가 대화 하나입니다. 날짜가 바뀌어도 자동으로 나누지 않습니다.
2. **새 표 `helper_conversations`:** 대화 1개 = 1행. 제목, 마지막 질문 시각, 질문 수를 둡니다. 표 14개 → 15개. `helper_messages`에 `conversation_id`(필수)를 더합니다.
3. **빈 대화는 만들지 않음:** [새 대화]는 화면만 비웁니다. 그 뒤 첫 질문을 서버가 저장할 때 대화 행을 만듭니다(`POST /api/helper/ask`에 `conversation_id` 없이 보냄).
4. **제목:** 서버가 첫 질문 앞 30자(넘으면 '…')로 정합니다. AI로 제목을 짓지 않습니다(토큰 절약, 짐작 없음). 이름 바꾸기는 추후 적용입니다.
5. **이어서 묻기:** 이전 대화를 열고 물으면 그 대화에 붙습니다. 서버는 그 대화가 묻는 사람의 것인지 확인합니다(아니면 404 `conversation_not_found`).
6. **AI 입력은 그대로:** 같은 대화의 앞 질문도 다음 질문의 AI 입력에 넣지 않습니다. 질문 하나에 한 번 호출, 교재 검색만으로 답하는 규칙(AI 규칙 W6)이 그대로입니다. 대화는 화면에서 찾기 쉽게 묶는 단위일 뿐입니다.
7. **쓰기·읽기 권한:** `helper_messages`와 같습니다. 넣기·고치기는 서버(service_role)와 DB 트리거만, 작성자는 내 대화만 읽기, 같은 기관 관리자·강사는 기관 전체 읽기. 작성자가 대화를 지우는 기능은 두지 않습니다(10/31 결정 7번 그대로).
8. **기존 행 옮기기:** 지금 있는 `helper_messages`는 작성자·한국 날짜별로 대화 하나씩 묶습니다. 제목은 그날 첫 질문 앞 30자입니다.
9. **W6 화면:** 열면 가장 최근 대화(마지막 질문 시각 기준)를 보여 줍니다. 머리에 [새 대화]와 [이전 대화]를 둡니다. 대화가 하나도 없으면 지금처럼 빈 채팅창과 추천 질문입니다.
10. **W6 · 이전 대화 (새 하위 화면):** 내 대화 목록을 마지막 질문 시각 최근 순으로 20개씩 보여 줍니다(제목, 날짜, 질문 수). 누르면 W6로 돌아와 그 대화를 보여 줍니다.
11. **추후 적용:** 대화 이름 바꾸기·검색·숨기기, 관리자·강사가 대화를 보는 화면(10/31 결정 그대로).

## 검토한 대안

- **대안 A: 날짜별 자동 묶음(새 표 없음):** 마이그레이션이 적음 / 하루에 여러 주제를 물으면 한 묶음에 섞이고, 작성자가 새 주제를 시작할 수 없어 'Claude·GPT 같은 모습'과 다름. 버림(기존 행 옮기기에만 씀)
- **대안 B: `conversation_id` 칸만 두고 목록은 그때그때 모아 계산:** 표가 늘지 않음 / 목록을 열 때마다 묶어 세야 하고 제목·시각을 둘 곳이 없음. 버림
- **대안 C: [새 대화]를 누르면 바로 빈 대화 행을 만듦:** 화면 코드가 단순 / 질문 없는 빈 대화가 목록에 쌓임. 버림
- **대안 D: AI로 대화 제목 짓기:** 읽기 좋은 제목 / 질문마다 호출이 늘고 짐작이 들어감. 버림
- **대안 E: 같은 대화의 앞 질문을 AI에 넘겨 이어 묻기('그럼 그건?')를 알아듣게:** 대화가 자연스러움 / 토큰이 대화 길이만큼 늘고, 교재 근거만으로 답한다는 규칙이 흐려짐. 버림(필요하면 다시 결정)
- **채택:** 새 표 1개 + 칸 1개 + 목록 API 1개, 화면은 W6 머리 버튼 2개와 하위 화면 1개

## 사유

- 작성자가 주제별로 질문을 찾아볼 수 있고, 나중에 강사가 '어떤 주제로 막혔는지'를 대화 단위로 볼 바탕이 됩니다.
- AI 호출 방식과 권한 경계는 그대로라 비용·안전 규칙을 다시 검증할 필요가 적습니다.

## 영향

- **DB(BE):** 마이그레이션(표·RLS·`helper_messages.conversation_id`·기존 행 묶기·마지막 시각·질문 수 트리거), SQL 테스트, CareBridge-Codyssey에 적용. 공모전 DB(CareBridge)에는 적용하지 않음
- **서버(BE):** `web/lib/helper/ask.ts`·`ask-supabase.ts`(대화 확인·만들기), `web/lib/helper/messages.ts`(`conversation_id`), 새 `web/app/api/helper/conversations/route.ts`
- **화면(FE):** `web/app/(worker)/helper/page.tsx`(머리 버튼, 대화 불러오기), 새 하위 화면, `web/lib/real/actions.ts`, Mock 데모 저장 모양
- **문서:** 데이터 구조 v2.0.1 → v2.1.0, 화면 설계 v2.0.1 → v2.1.0, AI 규칙 W6 8번에 한 구절, 용어집 두 줄
