# 로그인 전 병기는 영어로, 글 입력 안내는 ‘한국어 또는 모국어’로 한다

- **상태:** 유효
- **정한 날·사람:** 2026-11-07 · 2dion
- **관련:** 결정 [언어선택화면](2026-11-05-언어선택화면.md) 2번(로그인 전 베트남어 줄을 대체), 결정 [모국어추가](2026-11-05-모국어추가.md), 화면 설계 v2.3.3 A0·A1·A2·W2·W3, `web/lib/i18n/languages.ts` `PRE_LOGIN_LANG`

## 배경

- 로그인 전 화면(A0 스플래시·A1 로그인)과 A2(회원가입)에서 모국어를 고르기 전에는 한국어 아래 번역 줄이 늘 베트남어였습니다(`DEFAULT_NATIVE_LANG = "vi"`). 중국어·몽골어 등 다른 언어 사용자를 생각하지 않은 모양입니다.
- W2(글로 기록)·W3(내용 수정·내용 추가)의 입력 안내도 ‘한국어 또는 베트남어’로 언어가 고정돼 있었습니다.
- 서버는 입력 언어를 따로 처리하지 않고 어느 언어로 써도 한국어 기록체 + 작성자 모국어 번역으로 정리합니다. 안내에 특정 언어 이름을 쓸 이유가 없습니다.

## 결정

1. **로그인 전 병기 언어:** A0·A1과, A2에서 모국어를 고르기 전의 번역 줄은 **영어**입니다. 국제 공용어라 가장 많은 사람이 읽을 수 있습니다. 코드는 `PRE_LOGIN_LANG = "en"` 하나로 둡니다.
2. **A2에서 고른 뒤:** 모국어를 고르면 그 화면의 번역 줄이 고른 언어로 바뀝니다(언어선택화면 결정 2번 뒷부분 그대로). 모국어 칸의 처음 값(`vi`)과 가입 때 보내는 값은 바꾸지 않습니다.
3. **로그인한 뒤:** 작성자 프로필의 모국어로 병기합니다(지금과 같음). A0에서 이미 로그인한 사람도 자기 모국어입니다.
4. **글 입력 안내:** W2 ‘한국어 또는 베트남어로 작성할 수 있어요’와 W3 입력칸 안내 ‘(한국어 또는 베트남어)’를 **‘한국어 또는 모국어’**로 바꿉니다. 언어 이름을 넣지 않습니다.
5. **바뀌지 않는 것:** 언어 목록과 켜짐(`enabled`), 가입 API, 새 Mock 계정의 처음 모국어(`DEFAULT_NATIVE_LANG = "vi"`), 화면 틀 한국어 원칙.

## 검토한 대안

- **베트남어 그대로:** 바꿀 것이 없음 / 다른 언어 사용자에게 읽을 수 없는 줄이 첫 화면부터 보임
- **로그인 전 번역 줄 없이 한국어만:** 가장 단순함 / 한국어를 아직 못 읽는 사람이 로그인·가입에서 막힘
- **입력 안내에 작성자 모국어 이름 넣기(예: ‘한국어 또는 몽골어’):** 더 구체적 / 서버가 언어별로 다르게 처리하지 않아 이름을 넣을 이유가 없고, ‘모국어’ 하나로 모든 언어에 맞음

## 사유

로그인 전에는 그 사람의 언어를 모르므로 가장 널리 읽히는 영어가 맞고, 입력은 어느 언어든 같은 길로 처리되므로 ‘모국어’ 한 말로 통일합니다.

## 영향

- **화면(FE):** A0(`web/app/page.tsx`)·A1(`web/app/(auth)/login/page.tsx`)은 `NativeLanguageProvider`로 영어, A2(`signup/page.tsx`)는 고르기 전 영어. W2(`records/[id]/write`)·W3(`records/[id]/items/[key]`) 안내 문구. 영어 번역 키(`a0.*`·`a1.*`·`a2.*`)는 이미 있음.
- **테스트:** `lib/i18n/pre-login-language.test.tsx`(A1·A2 고르기 전 영어 줄만), `languages.test.ts`(`PRE_LOGIN_LANG`), `signup-language.test.tsx`(고른 언어 미리보기).
- **문서:** 화면 설계 v2.3.2 → v2.3.3, 언어선택화면 결정 상태 줄.
- **서버·DB:** 바뀌지 않음.
