# 파일 이름 검사는 문서/·참고자료/에만

- **상태:** 유효
- **정한 날·사람:** 2026-10-18 · 2dion
- **관련:** 루트 README '파일 이름 규칙', `.github/scripts/check-filenames.py`

## 배경

10/15에 파일 이름 규칙(Shift 없이 치는 글자만, 날짜-내용-사람-버전)을 정했고, 10/17부터 GitHub Actions가 모든 파일 이름을 검사했습니다. 그런데 Next.js·Supabase는 `[id]`, `(auth)`, `_` 같은 이름을 정해 두고 씁니다.[1][2]

## 결정

규칙과 자동 검사는 `문서/`와 `참고자료/`에만 적용합니다. 코드 폴더(`web/`, `supabase/`, `.github/` 등)는 각 도구가 정한 이름을 따르고, 코드가 깨졌는지는 CI(lint·타입 검사·빌드)가 확인합니다.[1]

## 검토한 대안

- 저장소 전체에 적용: 이름이 한 기준으로 통일되지만, 프레임워크가 요구하는 이름을 쓸 수 없어 코드가 돌지 않음.
- 코드 폴더만 예외 목록으로 뺌: 폴더가 늘 때마다 목록을 고쳐야 함.

## 사유

규칙의 목적은 사람이 찾고 올리는 문서를 깔끔하게 두는 것이고, 코드 이름은 도구가 정한 대로 써야 돌아갑니다.[1]

## 영향

- `check-filenames.py`의 `CHECKED_DIRS`가 `문서/`, `참고자료/`입니다.
- 코드 폴더와 코드 파일 이름은 영어로 씁니다(AGENTS.md '폴더·파일 이름 규칙').
