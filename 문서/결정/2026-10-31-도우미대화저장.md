# W6(도우미) 대화를 서버(DB)에 저장하고, 작성자는 지난 대화를 이어 보며 관리자·강사도 읽을 수 있게 한다

- **상태:** 유효
- **정한 날·사람:** 2026-10-31 · 2dion(팀장)
- **관련:** 데이터 구조 v1.7(표 `helper_messages`, 권한 규칙, 공통 계약 `POST /api/helper/ask`·`GET /api/helper/messages`), 화면 설계 v1.3.2 W6(도우미)·A2(회원가입), AI 규칙 v1.1.5 '⑤ 도우미 답', 이슈 #152(대체), 이슈 #218

## 배경

- 데이터 구조 v1.1부터 W6 대화는 '저장하지 않고 화면에만' 두었습니다. 개인정보가 담길 수 있고, 기록과 도우미는 별개이기 때문입니다.[1]
- 10/29 멘토링 뒤 이슈 #152(PR #174)는 서버 대신 **브라우저(localStorage)에만** 계정별 최근 50개를 남기게 했습니다. 이때 '서버에 저장하기로 바꾸면 결정 기록을 먼저 쓴다'고 적었습니다.[2]
- 10/31 BE 확인: 질문해도 DB 13개 표는 그대로이고, 같은 계정이라도 다른 브라우저·기기에서는 지난 대화가 보이지 않습니다.[3]
- 팀장 10/31: 작성자(교육생)가 자기가 물은 내용을 계속 확인할 수 있어야 하고, 도우미 기록을 서버에 남겨 관리자(강사)가 업무에 어려운 점을 파악하거나 학습에 도움 될 정보를 얻는 데 쓴다.[4]

## 결정

1. **새 표 `helper_messages`:** 질문 1개와 그 답 1개를 한 행으로 남깁니다. 표 13개 → 14개. 칸은 데이터 구조 v1.7 '표별 칸'을 따릅니다(질문 원문, 검색용 한국어, 답 한국어·모국어, 출처, 교재에서 찾았는지, 안전 안내를 붙였는지).
2. **무엇을 저장하나:** 서버가 답을 돌려준 질문(200)만 저장합니다. 교재에서 찾지 못한 답(`found = false`)도 저장합니다. 강사가 '교재에 없어서 막힌 질문'을 보는 데 가장 쓸모가 있기 때문입니다. 로그인 안 함·권한 없음·입력 오류·AI 실패·키 없음(401·403·400·502·503)은 저장하지 않습니다.
3. **누가 쓰나:** 서버만(service_role) 넣습니다. 화면 키(authenticated)로는 넣기·고치기·지우기를 모두 막습니다. 답과 출처를 꾸며 넣지 못하게 하기 위해서입니다(10/27 권한정리와 같은 방식).[5] `org_id`는 DB가 작성자 프로필에서 채웁니다.
4. **누가 읽나 (RLS):** 작성자·교육생은 내 행만, 같은 기관 관리자·강사는 기관 전체를 읽습니다. 다른 기관은 누구도 읽지 못합니다.
5. **API:** `POST /api/helper/ask`는 입력·출력을 그대로 두고 출력에 `id`·`created_at`을 더합니다. 저장이 실패해도 답은 돌려주고 `id`를 빈값으로 둡니다(서버 기록에 남김). 새 `GET /api/helper/messages`는 작성자 본인의 대화를 최근 50개씩 돌려줍니다.
6. **W6 화면(MVP):** 열 때 `GET /api/helper/messages`로 지난 대화를 불러와 **지금 채팅창 위쪽에 이어서** 보여 줍니다. 실제 모드(Supabase 로그인)에서는 브라우저 저장을 쓰지 않습니다. Supabase 설정이 없는 Mock 데모만 지금처럼 브라우저에 남깁니다.
7. **[대화 지우기]:** 실제 모드에서는 숨깁니다. 서버 기록은 작성자가 지우지 않습니다. 기다리던 중 실패한 말풍선은 저장하지 않으니 화면에만 남습니다.
8. **알리기:** 작성자가 저장 사실을 알고 묻도록, W6 상단 고지와 A2(회원가입) 개인정보 '수집 항목'에 '도우미 질문·답(관리자·강사가 볼 수 있음)'을 병기로 더합니다. 질문에는 어르신·가족 실명을 쓰지 말라는 안내도 함께 둡니다(AGENTS.md 원칙 9).
9. **보관 기간:** 회원 탈퇴(계정 삭제) 때까지. 계정을 지우면 그 사람의 행도 함께 지웁니다.
10. **추후 적용(다음 주):** W6 '이전 대화 기록' 화면(대화를 묶어 나눠 불러오는 Claude·ChatGPT 같은 모양)과 관리자·강사가 도우미 기록을 보는 화면. 대화 묶음 단위(새 표 또는 칸)는 그 화면을 설계할 때 결정 기록으로 정합니다.

## 검토한 대안

- **대안 A: 브라우저 저장 그대로(이슈 #152):** 새 표·API가 없음 / 기기를 바꾸면 사라지고 강사가 볼 수 없어 팀장 요구와 맞지 않아 버림
- **대안 B: 화면이 Supabase로 바로 넣기(RLS로 내 행 넣기 허용):** 서버 코드가 짧음 / 공개 키로 답·출처를 꾸며 넣을 수 있어 강사가 읽는 자료로 믿을 수 없음. 버림
- **대안 C: 기존 표(`audio_jobs`, `record_events`)에 함께 넣기:** 표가 늘지 않음 / 기록과 도우미는 별개라는 원칙과 기록 이력의 뜻이 섞여 버림
- **대안 D: 실패한 질문도 저장:** 강사가 더 많이 봄 / [다시 시도]마다 같은 질문이 쌓이고 답 없는 행이 화면을 어지럽혀 MVP에서는 버림(추후 다시 볼 수 있음)
- **대안 E: 지금 대화 묶음 표(`helper_conversations`)까지 만들기:** 다음 주 화면 준비 / 그 화면 모양이 아직 정해지지 않아, 칸을 미리 정하면 다시 바꿀 수 있음. 다음 주로 미룸
- **채택:** 서버만 쓰는 새 표 1개 + 불러오기 API 1개. 바뀌는 곳이 표 1개, API 2곳, W6 한 화면

## 사유

- 작성자가 어느 기기에서든 자기 질문을 다시 볼 수 있고, 강사가 같은 기관 교육생의 막힌 점을 모아 볼 바탕이 생깁니다.[4]
- 저장·권한은 코드와 DB가 맡고(원칙 5·7), 화면은 불러와 보여 주기만 하면 됩니다.
- 저장된다는 사실을 화면과 가입 동의에 밝혀야 작성자가 알고 쓸 수 있습니다.

## 영향

- **DB(BE):** 마이그레이션(표·RLS·`org_id` 채움 트리거·색인), `supabase/README.md` 표 목록, SQL 테스트, 원격 DB 적용
- **서버(BE):** `web/app/api/helper/ask/route.ts`·`web/lib/helper/ask.ts`(답한 뒤 저장), 새 `web/app/api/helper/messages/route.ts`
- **화면(FE):** `web/app/(worker)/helper/page.tsx`(불러오기, 실제 모드 localStorage 중단, [대화 지우기] 숨김, 상단 고지), A2 수집 항목, `web/lib/real/actions.ts`
- **문서:** 데이터 구조 v1.6.6 → v1.7, 화면 설계 v1.3.1 → v1.3.2, AI 규칙 v1.1.4 → v1.1.5, 용어집 한 줄
- **운영:** 질문은 원래도 코디세이 Claude로 가며 운영자가 볼 수 있습니다. 이제 DB에도 남으므로 시연·테스트는 지금처럼 가상 이름·합성 질문만 씁니다(AGENTS.md 원칙 9, 코디세이 API 사용 방법).
