# W3 처리 시간 제한과 재처리 성공 뒤 작업 상태

- **상태:** 제안
- **정한 날·사람:** 2026-10-31 · 제안 JiNS03, 확인 필요(기획 담당)
- **관련:** 이슈 #234, #235, AI 규칙 v2.0.1 멈춤 규칙, 화면 설계 v2.0.0 W3

## 배경

서버가 끊기면 `audio_jobs`가 처리 중에 남아 W3 '정리 중'에서 빠져나올 수 없습니다. 재처리가 성공해도 앞선 `failed` 작업이 남아 W3가 실패 화면으로 보입니다. 화면 설계는 실패하면 [다시 시도]를 보이라고 하지만, 서버가 끊긴 경우의 시간 기준은 없었습니다.

## 결정

1. Agent 전체 시간은 4분입니다. 넘으면 실패로 끝냅니다.
2. 처리 시작 6분이 지나도 끝나지 않은 작업은 화면이 실패로 다룹니다. 상태 값은 늘리지 않습니다.
3. Agent가 성공하면 서버가 그 기록의 끝나지 않은 녹음 작업과 실패 작업을 `done`으로 끝냅니다.

## 검토한 대안

- 화면이 시간을 세지 않고 서버 정리 작업으로 `failed`를 남기기: 상태가 정확함 / 정리 작업 주기만큼 더 기다리고 일이 늘어남
- 상태 값 `timed_out` 추가: 원인이 분명함 / 공통 계약과 표가 바뀌고 화면 동작은 같음
- 기준을 5분으로: 더 빨리 알 수 있음 / `maxDuration` 300초와 같아 처리 중인 작업을 실패로 볼 수 있음

## 사유

`maxDuration`이 300초라 그보다 긴 6분이면 함수가 끝난 뒤입니다. Agent를 4분에서 끊으면 받아쓰기 시간을 더해도 실패를 기록할 여유가 남습니다.

- FE: `draftStateOf` 시간 판정
