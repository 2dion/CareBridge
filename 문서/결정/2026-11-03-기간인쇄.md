# M3(승인한 기록)에 '기간 인쇄'를 더해, 한 어르신의 승인한 기록 여러 날을 법정 원문 한 장에 모아 찍는다

- **상태:** 유효
- **정한 날·사람:** 2026-11-03 · 2dion(팀장)
- **관련:** 10/18 팀 결정 '인쇄 = 기록 1건(하루) 1장'(일부 대체), 결정 [2026-10-27-피그마상충점](2026-10-27-피그마상충점.md)(법정 원문 PDF에 채움, 그대로), 데이터 구조 v2.2.0(공통 계약 `GET /api/residents/:id/print`), 화면 설계 v2.2.0 M3 · 기간 인쇄, 이슈 #155

## 배경

- 별지 제12호(재가 방문요양)는 1장 = 7일, 별지 제16호(시설급여)는 1장 = 3일입니다. 날짜마다 열이 하나씩 있습니다.[1][2]
- 지금 인쇄는 기록 1건(하루)을 1장으로 찍고, 원문의 첫 날짜 열만 채웁니다(10/18 팀 결정, 공모전 MVP).[3] 그래서 한 주를 종이로 남기려면 7장이 나오고, 원문의 나머지 열은 늘 비어 있습니다.
- 10/29 멘토링에서 제12호가 여러 날을 누적해 쓰는 서식인지 확인하자는 이야기가 나왔고(이슈 #155), 11/03 확인 결과 누적 서식이 맞았습니다.[4] 팀장은 11/03 코디세이 제출용으로 묶어 찍기를 설계하기로 했습니다.[5]

## 결정

1. **이름과 자리:** M3(승인한 기록)에 [기간 인쇄]를 더하고, 새 하위 화면 'M3 · 기간 인쇄'에서 고릅니다. 지금의 [인쇄·PDF](기록 1건)는 그대로 둡니다.
2. **묶는 단위:** 어르신 1명 + 서식(`form_type`) 1개 + 기간입니다. 서식은 그 어르신의 지금 `care_type`으로 정합니다(시설 → 제16호, 재가 → 제12호).
3. **기간:** 관리자가 시작 날짜를 고르고, 끝 날짜는 서식의 1장 날짜 수로 정해집니다(제12호 시작 + 6일, 제16호 시작 + 2일). 요일은 정해져 있지 않습니다. 처음 값은 제12호가 이번 주 월요일, 제16호가 오늘로부터 2일 전입니다. 시작 날짜는 오늘보다 뒤일 수 없습니다.
4. **채우는 기록:** 그 기간에 **승인 완료(`approved`)된 기록만** 채웁니다. 다음 날은 열을 비우고, 화면에 그 날과 이유를 보여 줍니다.
   - 승인 전(`draft`·`submitted`·`returned`) → '승인 전이라 뺌'
   - 기록 없음 처리(`no_care_days`) → '기록 없음 처리한 날'
   - 기록 없음 → '기록 없음'(재가의 방문하지 않는 요일도 여기)
   - 다른 서식(`form_type`이 지금 서식과 다름) → '다른 서식이라 뺌'
5. **승인한 날이 하루도 없으면** 인쇄하지 않습니다. 서버는 409 `not_approved`(기존 키)를 돌려주고, 화면은 [PDF 만들기]를 끕니다.
6. **날짜 열:** 돌봄 날짜가 시작 날짜로부터 며칠째인지에 따라 1번째~7번째(제16호는 3번째) 열에 넣습니다. 날마다 작성자가 달라도 됩니다.
7. **머리말:** 수급자 성명·기관명은 한 번만 찍습니다. 연도 칸은 시작 날짜의 연도, 월/일은 열마다 찍습니다.
8. **특이사항:**
   - 제12호는 날짜별 칸이 아니라 한 장에 하나인 가로 칸입니다. 날마다 `11/3 …`처럼 날짜를 앞에 붙여 날짜 순으로 이어 씁니다.
   - 제16호는 날짜 열마다 영역별 특이사항 4칸이 있어 그날 열에 넣습니다. 자유 서술 notes를 넣을 영역은 지금처럼 관리자가 **날마다** 고르며, 저장하지 않습니다. notes가 있는 날에 영역을 고르지 않으면 [PDF 만들기]를 끕니다.
9. **넘치는 글:** 지금처럼 같은 원문을 복제해 이어 씁니다('2/3 이어쓰기'). 뒤쪽 유의사항은 맨 끝에 한 번 붙입니다.
10. **표시:** 서명·없는 정보는 비웁니다. '합성 사례 · 공식 기록지 아님', 교육용 기관이면 '연습용'을 찍습니다. 승인한 기록만 넣으므로 '승인 전' 표시는 쓰지 않습니다.
11. **API 1개 추가:** `GET /api/residents/:id/print?from=YYYY-MM-DD`(관리자·강사). 출력은 날짜별 칸 목록이고, 각 칸에 기록 1건 인쇄와 같은 모양의 기록 또는 뺀 이유가 들어갑니다. 새 표·칸은 없고, 만든 PDF는 저장하지 않습니다.
12. **권한:** 기록 1건 인쇄와 같습니다. 관리자·강사만(아니면 403 `reviewer_only`), 같은 기관 어르신만(아니면 404 `resident_not_found`).
13. **추후 적용:** 여러 어르신을 한 번에 찍기, 한 달처럼 여러 장을 한 번에 찍기, 서명 받기.

## 검토한 대안

- **대안 A: 기록 1건 1장 그대로(10/18 결정 유지):** 만들 것 없음 / 원문 열 대부분이 비고 한 주에 7장이 나와, 기관이 실제로 쓰는 모양과 다름. 버림(1건 인쇄는 남김)
- **대안 B: 시작 날짜를 월요일로 고정:** 고를 것이 줄어듦 / 원문에 요일이 정해져 있지 않고, 기관마다 주 시작이 다를 수 있음. 버림(처음 값만 월요일)
- **대안 C: 승인 전 기록이 섞이면 인쇄를 막음:** 공식 기록만 나감이 분명 / 한 날 때문에 주 전체를 못 찍음. 버림(빼고 찍고 화면에 알림)
- **대안 D: 한 기관은 재가나 시설 하나만:** 서식이 섞이지 않음 / 데모 기관 1에 시설·재가 어르신이 함께 있어 데이터·시연을 바꿔야 함. 묶음 기준에 서식을 넣으면 섞여도 문제없음. 버림
- **대안 E: 만든 PDF를 Storage에 저장:** 다시 받기 쉬움 / 승인본이 바뀌지 않으므로 그때 다시 만들면 되고, 저장·지우기 관리가 늘어남. 버림
- **채택:** 어르신 + 서식 + 기간, 승인한 기록만, API 1개, 새 표 없음

## 사유

- 법정 원문 한 장을 그대로 채우므로 기관이 종이로 보관하는 모양과 같아집니다.
- 승인 완료 기록만 넣고 서식으로 나누므로, 승인 규칙과 재가·시설 구분을 새로 검증할 필요가 없습니다.

## 영향

- **서버(BE):** 새 `web/app/api/residents/[id]/print/route.ts`, 기간 기록 모으기(`web/lib/records/` 쪽), Supabase 읽기(records·no_care_days·residents, 관리자 RLS 그대로)
- **PDF(BE·FE):** `web/lib/print/pdf.ts`·`fields.ts`가 날짜 열 번호를 받아 2~7번째 열 좌표에 찍게(지금은 첫 열 좌표만 있음), 제12호 특이사항 날짜 붙여 잇기, 제16호 날짜별 notes 영역
- **화면(FE):** M3 [기간 인쇄] 버튼, 새 하위 화면 'M3 · 기간 인쇄'(어르신·시작 날짜 고르기, 날짜별 상태 목록, 제16호 날마다 영역 고르기, [PDF 만들기]), Mock 데모
- **테스트(QA):** 승인 전·기록 없음·기록 없음 처리·다른 서식 날이 빈 열로 나오는지, 승인 0일이면 409, 다른 기관 어르신 404, 제12호 7번째 열·제16호 3번째 열 좌표
- **문서:** 데이터 구조 v2.1.0 → v2.2.0, 화면 설계 v2.1.0 → v2.2.0, 기술 선택 v2.0.0 한 줄, 용어집 한 줄
