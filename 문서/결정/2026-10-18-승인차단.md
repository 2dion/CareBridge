# '확인 필요'가 남으면 승인 막기

- **상태:** 유효
- **정한 날·사람:** 2026-10-18 · 2dion
- **관련:** 기획안 결정 8, 화면 설계 R2(검토 화면), 데이터 구조 '공통 계약'(상태 값)

## 배경

v1.0은 R2(검토 화면)에서 '확인 필요'를 모두 확인해야 [승인]이 눌린다고만 적었습니다. 외부 피드백 검토에서, 화면 버튼만 막으면 우회할 수 있고 확인했다는 뜻이 무엇인지 정해지지 않았다는 점이 나왔습니다(A2).[1][2]

## 결정

- '확인 필요'가 남은 기록은 승인할 수 없습니다.
- 담당자는 남은 항목마다 [확인함](내용 유지) 또는 [기록 안 함](내용 비우고 '언급 없음', 사유를 이력에 남김)을 골라야 합니다. 그래야 [승인]이 눌립니다.
- 서버도 승인 요청 때 다시 검사합니다. 화면만 믿지 않습니다.[3]

## 검토한 대안

- v1.0 그대로(화면에서만 확인): 구현이 빠르지만 API를 직접 부르면 확인 안 된 기록이 승인됨.
- 경고만 띄우고 승인 허용: 담당자 부담이 적지만, 확인 안 된 내용이 공식 기록으로 넘어감.

## 사유

돌봄 기록은 사람이 책임지는 공식 기록이라, 확인 안 된 내용이 넘어가는 길이 화면에도 서버에도 없어야 합니다.[3][4]

## 영향

- R2(검토 화면): 항목별 [확인함]/[기록 안 함] 버튼, 남은 항목이 있으면 [승인] 비활성.
- 승인 API: 남은 '확인 필요'가 있으면 거절. 승인 조건은 AI가 아니라 코드가 판단합니다(AGENTS.md 원칙 3·5).
- 테스트: '확인 필요가 남은 승인 차단'을 화면과 API 양쪽에서 시험합니다(시연·일정 v1.1 테스트 계획).[5]
