# 공모전 제출 환경과 코디세이 개발 환경 분리

2026-11-02 · @2dion · 이슈 #242

## 배경

공모전 제출 사이트와 데이터를 유지하면서 코디세이 파이널 프로젝트 개발을 계속한다. 저장소 포크 대신 기준 브랜치와 클라우드 프로젝트를 분리한다.

## 결정

1. 공모전 `main`과 기존 Vercel 프로젝트 `care-bridge`, 기존 Supabase `CareBridge`를 유지한다. 공모전 주소는 `https://care-bridge-kappa.vercel.app`이다. 현재 배포 커밋은 `006886384c93cd347e9561b972d113fe599b8077`이며, 공모전 제출 당시 커밋과 동일한지는 별도 확인하지 않았다.
2. 코디세이 기준 브랜치는 `main-codyssey`다. 기능 브랜치와 PR은 이 브랜치를 기준으로 한다. GitHub 기본 브랜치는 이번 작업에서 바꾸지 않는다. (11/04 대체: 기본 브랜치를 `main-codyssey`로, 공모전 브랜치를 `main-contest`로 바꿈 → [2026-11-04-기본브랜치전환](2026-11-04-기본브랜치전환.md))
3. 코디세이 Vercel 프로젝트는 `carebridge-codyssey`, Root Directory는 `web`, Production Branch는 `main-codyssey`로 둔다. 공모전 프로젝트는 Ignored Build Step `exit 0`으로 Git 자동 빌드를 건너뛴다. 사이트를 멈추는 Pause는 사용하지 않는다.
4. 코디세이 Supabase는 같은 Free 조직의 새 프로젝트 `CareBridge-Codyssey`(`fffgpgrnppxxqccncstf`, 서울)다. 기존 조직 구성원 역할을 유지하며 중복 초대하지 않는다. 새 프로젝트에서 스키마·RLS·Storage와 합성 데이터를 구성한다. 기존 사용자 비밀번호와 저장 파일은 복제하지 않는다.
5. 코디세이 Vercel의 Production·Preview는 모두 새 DB 키를 사용한다. AI·받아쓰기 키는 서버에만 둔다. 기존 Sensitive 값은 다시 읽을 수 없으므로 필요하면 새 프로젝트에 별도 입력한다.
6. 기본 브랜치를 유지하므로 예약 녹음 정리는 기존 main workflow가 계속 맡는다(11/04 대체: 공모전 사이트 정리는 main-codyssey workflow가 이어 맡음 → [2026-11-04-기본브랜치전환](2026-11-04-기본브랜치전환.md)). 코디세이는 새 Supabase Cron으로 매시간 17분에 새 사이트를 호출한다. 비밀 값은 Vault에서 읽고, `CODYSSEY_CRON_SECRET`을 쓰는 GitHub 수동 실행은 진단용으로 유지한다.
7. 브랜치 전환은 로컬 `.env.local`과 Supabase CLI 연결을 바꾸지 않는다. DB 작업 전에 프로젝트 ref를 확인한다.

## 운영 보강

- `main-codyssey`에 기존 main과 같은 PR 필수·강제 푸시 금지·삭제 금지 보호 규칙을 추가한다. 승인 인원은 기존과 같이 0명이며 CI는 PR에서 확인한다.
- 기관·역할별 코디세이 전용 가입 코드 4개를 발급하고 비공개로 전달한다. 코드 값은 저장소에 넣지 않는다.
- 실제 AI 검증은 `USE_MOCK_AI=false`인 배포 사이트에서 합성 사례로 진행하고 결과·한계를 이슈 #242에 기록한다.

## 문서 버전

코디세이 현행 기획·설계·용어·API·시연 문서는 v2.0.0부터 시작한다. 기존 판은 2026-11-02 날짜로 보관한다. 과거 기술 검토와 공모전 제출 영상 대본은 당시 자료로 보관하며, 새 기술 검토나 코디세이 시연 결과로 재표시하지 않는다. 앱 패키지 버전은 바꾸지 않는다.

## 검증 범위

실제 생성·배포·DB 검사 결과와 남은 설정은 이슈 #242와 작업 완료 보고에 기록한다. 사이트 배포 성공만으로 실제 AI 호출·음성 인식·파일 업로드 전체 검증을 완료했다고 보지 않는다.

## 대안

- 같은 Vercel 프로젝트에서 Preview만 분리: 가능하지만 공모전과 개발용 환경 변수·배포 설정을 같은 곳에서 관리해야 한다.
- Supabase 계정 추가: 데이터 분리는 별도 프로젝트로 가능하고, 같은 조직의 기존 역할을 유지하면 재초대가 필요 없다.
