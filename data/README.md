## 합성 사례 형식

- `draft` = { `transcript_ko`, `items`(9개, 순서 고정), `form_fields` } — AI 규칙 v1.1.1 초안 모양. 시설(제16호)은 `form_fields`를 비우고 값은 항목의 `detail`에 둡니다(데이터 구조 v1.2 '서식 칸 대응').
- `transcript` = 받아쓴 원문(records.transcript). **근거(evidence)는 이 원문에 이어진 한 구간 그대로**입니다. 기록 검증 코드(`web/lib/agent/validate-draft.ts`)가 띄어쓰기·문장부호를 빼고 비교합니다.
- `evidence_ko`(근거의 한국어 뜻), `source_note`, `evidence_extra`는 사람이 보기 위한 칸입니다. 검증 코드는 무시합니다.
- `must_not_appear` = 품질 측정 때 "지어낸 내용"으로 세는 오답입니다.

## 서식 기준 (forms/)

- 데이터 구조 v1.2: 서식 기준은 **표를 만들지 않고 서버 코드 안 고정값(JSON)**. 이 두 파일이 그 원본이고, 코드 위치는 백엔드 담당이 정합니다.
- 구조: `header` / `sections[].fields[]`(key, label, input, options, option_codes, rule, ai_policy, detail_key) / `item_map`(9개 항목 → 서식 칸) / `storage_note`.
- 코드값: 섭취량 `full / half_or_more / under_half`(10/22 확정), 변화상태 `improved / same / worse`. 제12호 지원별 분은 `support.detail.minutes` 키 6개, 체크는 `support.detail.checks`(결정 2026-10-21-재가분칸-실명목록).
- 원문: `참고자료/도메인/서식/법정/`. `rule`은 서식 뒷면 유의사항, `ai_policy`는 AI가 그 칸에서 하지 말아야 할 것.
