# 케어브릿지(CareBridge)

## 업무 기록 문서 분석을 통한 AI 채팅 질문 설계 가이드

> **목적**: 요양보호사가 작성·참여하는 업무 기록의 **실제 서식과 기록 항목**을 분석하고, 이를 외국인 요양보호사에게 **AI가 먼저 묻는 채팅 질문**으로 변환하는 방법을 설명합니다.
>
> **적용 범위**: 요양원 등 **시설급여** 환경을 가정한 초기 설계입니다. 서식에 있는 항목과 AI가 추가로 물을 만한 정보는 구분합니다. 현장 인터뷰 결과를 전제로 작성한 자료는 아닙니다.

## 1. 어떤 문서를 분석했는가?

### 1.1 핵심 분석 문서: 장기요양급여 제공기록지(시설급여/단기보호)

- **문서명**: 「노인장기요양보험법 시행규칙」 **별지 제16호서식** 「장기요양급여 제공기록지(시설급여/단기보호)」
- **역할**: 수급자별로 제공된 돌봄·간호·기능회복 관련 내용을 기록하는 서식
- **분석 이유**: 실제 기록란을 기준으로 AI가 수집해야 할 정보를 역으로 도출할 수 있기 때문
- **서식 링크**: [국가법령정보센터 — 시설급여/단기보호 급여제공기록지](https://www.law.go.kr/flDownload.do?flSeq=101841187&gubun=)

**확인한 서식의 주요 구성**

| 구분       | 서식에서 확인되는 항목(발췌)                     | AI 설계에서의 의미                   |
| :------- | :----------------------------------- | :---------------------------- |
| 수급자 기본정보 | 수급자명, 생년월일, 장기요양등급, 인정번호, 침실, 기관명    | 누구의 기록인지 정확히 연결해야 함           |
| 개인위생     | 세면·구강·머리감기·몸단장·옷 갈아입히기, 목욕           | 수행한 돌봄 종류 확인                  |
| 식사       | **식사 종류**, **섭취량**                   | 단순히 '식사 도와드림'으로는 기록이 부족할 수 있음 |
| 신체활동     | 체위변경, 화장실 이용·기저귀 교환, 이동 도움, 산책·외출 동행 | 지원 유형과 수행 내용 확인               |
| 특이사항     | 돌봄 영역의 특이사항                          | 평소와 다른 관찰 사실 및 보고 사항 확인       |
| 간호 및 처치  | 혈압·체온, 욕창관리, 투약관리, 특이사항              | 담당 직종·권한에 따라 기록 범위를 구분해야 함    |
| 기능회복훈련   | 신체·인지기능 관련 훈련·프로그램, 특이사항             | 프로그램 참여와 수행 사실 확인             |
| 기타       | 작성자, 입·퇴소·외박·외출 관련 정보                | 작성자와 날짜·상황 등 기록 맥락 확인         |

**주의:** 링크의 서식은 확인 가능한 공식 서식의 한 버전입니다. 실제 적용 전에는 **최신 시행규칙 별지와 해당 기관에서 사용하는 서식·전산화면**을 다시 확인해야 합니다. 위 표는 서식 전체의 완전한 전사가 아니라 질문 설계에 필요한 주요 항목을 추린 것입니다.

### 1.2 관련 기준 문서: 장기요양급여 제공기준 및 급여비용 산정방법 등에 관한 고시

- **문서명**: 「장기요양급여 제공기준 및 급여비용 산정방법 등에 관한 고시」
- **참고 조항**: 제7조(장기요양급여제공 기록), 제43조(시설급여 제공기준)
- **활용**: 급여제공기록지 작성·관리의 취지와 시설에서 제공하는 주요 서비스 영역 확인
- **링크**: [국가법령정보센터 — 고시(2026.10.1. 시행)](https://www.law.go.kr/LSW/admRulLsInfoP.do?admRulNm=%EC%9E%A5%EA%B8%B0%EC%9A%94%EC%96%91%EA%B8%89%EC%97%AC+%EC%A0%9C%EA%B3%B5%EA%B8%B0%EC%A4%80+%EB%B0%8F+%EA%B8%89%EC%97%AC%EB%B9%84%EC%9A%A9+%EC%82%B0%EC%A0%95%EB%B0%A9%EB%B2%95+%EB%93%B1%EC%97%90+%EA%B4%80%ED%95%9C+%EA%B3%A0%EC%8B%9C&docType=JO&joNo=003600000&languageType=KO&paras=1)

고시에서는 시설급여의 식사, 구강관리, 목욕, 배변관리, 이동지원 등 서비스와 급여제공기록지 기록·관리의 관계를 확인할 수 있습니다. **고시가 기록의 근거라면, 별지 서식은 실제 어떤 칸을 채울지 살펴보는 자료**입니다.

### 1.3 보조적으로 참고할 문서

| 문서                 | 용도                 | 이번 개발에서의 위치                         |
| :----------------- | :----------------- | :---------------------------------- |
| 수급자별 급여제공계획        | 어떤 돌봄이 계획되어 있는지 파악 | **질문을 고르는 참고정보**. 실제 수행 기록과 혼동하지 않음 |
| 인수인계·관찰 기록(기관별 양식) | 다음 근무자에게 전달할 관찰 내용 | 특이사항·보고 질문 설계에 참고                   |
| 사고·이상상황 보고(기관별 양식) | 사고 발생 및 조치 내용 전달   | 일반 채팅 기록보다 **즉시 보고 절차**가 우선         |

※ 보조 문서는 기관마다 서식·작성 주체가 다를 수 있으므로 **현재 확보한 공식 시설급여 기록지와 동일한 수준으로 항목을 검증한 것은 아닙니다.** 초기 MVP의 기준 문서는 우선 **시설급여 제공기록지 1종**으로 정합니다.

## 2. 문서 분석 결과: 무엇을 물어야 하는가?

문서를 분석할 때 중요한 것은 '식사 지원'이라는 업무명만 찾는 것이 아니라, **그 업무의 기록란을 채우기 위해 필요한 정보**를 분해하는 것입니다.

| 서식에서 확인한 영역 | 서식에서 확인되는 내용               | AI가 수집할 정보         | 구분           |
| :---------- | :------------------------- | :----------------- | :----------- |
| 식사          | 식사 종류, 섭취량                 | 어떤 식사였는지, 얼마나 드셨는지 | **서식 기반**    |
| 개인위생        | 세면·구강관리·옷 갈아입히기 등          | 실제 수행한 지원 종류       | **서식 기반**    |
| 신체활동        | 화장실 이용·기저귀 교환, 이동 도움, 체위변경 | 어떤 지원을 수행했는지       | **서식 기반**    |
| 산책·외출       | 산책 또는 외출 동행                | 어떤 활동에 동행했는지       | **서식 기반**    |
| 특이사항        | 자유기록란                      | 관찰한 사실과 전달할 사항     | **서식 기반**    |
| 식사 후속 확인    | 식사 중 불편 여부 등               | 추가 기록·보고가 필요한지     | **AI 설계 제안** |
| 이동 후속 확인    | 불편·위험 상황 여부 등              | 특이사항 기록·보고가 필요한지   | **AI 설계 제안** |

**구분이 중요합니다.** 예를 들어 '식사 종류'와 '섭취량'은 확인한 서식에 있는 항목이지만, '식사 중 불편했는지'는 해당 정보를 정확히 확인하기 위해 **AI가 추가로 설계하는 질문**입니다. 후자를 모든 기관의 법정 필수 입력란이라고 설명해서는 안 됩니다.

## 3. 왜 단순 번역이 아니라 AI 채팅 질문 설계가 필요한가?

**상황**: 요양보호사가 모국어로 “오늘 김 어르신 식사를 도와드렸어요”라고 말했습니다.

- **단순 번역**: “김 어르신의 식사를 도왔습니다.” → 문장은 한국어가 되었지만 **식사 종류와 섭취량** 정보는 없음.
- **단순 요약**: “식사 지원 실시” → 더 짧아졌지만 **서식의 필요한 칸을 채울 수 없음**.
- **AI 질문 설계**: “어떤 식사였나요?” → “얼마나 드셨나요?” → 필요한 정보를 확인한 뒤 해당 기록 항목으로 변환.

즉, 케어브릿지의 AI는 번역기나 자유대화 챗봇에 머무르지 않고, **문서의 빈 항목을 채우기 위해 필요한 정보를 대화로 수집하는 역할**을 해야 합니다.

> **핵심 설계 공식**
> **기록 서식의 항목 → 필요한 정보 → 기본 질문 → 답변 분석 → 필요한 경우 후속 질문 → 기록 초안**

질문은 많이 하는 것이 목적이 아닙니다. **필요한 정보를 빠뜨리지 않으면서 요양보호사가 부담 없이 답하도록 만드는 것**이 목적입니다.

## 4. 기록 항목을 채팅 질문으로 바꾸는 방법

### 4.1 식사 기록: 실제 서식 항목에서 출발하기

**분석 출발점**: 시설급여 제공기록지에는 식사의 **종류**와 **섭취량**을 기록하는 칸이 있습니다. 확인한 서식에는 식사 종류(일반식·죽·유동식 등)와 섭취량 구분이 제시되어 있습니다.

| 설계 단계    | 예시                                   |
| :------- | :----------------------------------- |
| 서식 항목    | 식사 종류, 섭취량                           |
| 필요한 정보   | 수급자, 식사 지원 여부, 식사 종류, 섭취량            |
| 기본 질문    | “오늘 김○○ 어르신의 식사를 도와드렸나요?”            |
| 첫 후속 질문  | “어떤 식사를 드셨어요? 일반식, 죽, 유동식 중에 알려주세요.” |
| 다음 후속 질문 | “얼마나 드셨어요?”                          |
| 선택적 확인   | “식사 중 평소와 다른 점은 없었나요?”               |
| 기록 초안    | 확인된 답변을 실제 서식의 선택지·특이사항란에 매핑         |

**대화 예시** *(실제 구현에서는 요양보호사의 설정 언어, 예: 베트남어로 질문)*

> **AI**: 오늘 김○○ 어르신의 점심 식사를 도와드렸나요?
> **요양보호사**: 네.
> **AI**: 어떤 식사를 드셨어요?
> **요양보호사**: 죽을 드셨어요.
> **AI**: 얼마나 드셨어요?
> **요양보호사**: 절반 정도 드셨어요.
> **AI**: 식사 중 특별히 전달할 사항은 없었나요?
> **요양보호사**: 없었어요.

**수집 결과 예시**

```yaml
수급자: 김○○  # 실제 시스템에서는 수급자 ID로 연결
업무: 식사
식사시점: 점심
식사종류: 죽
섭취량_원문: 절반 정도
특이사항_응답: 없음
확인상태: 사용자 확인 필요
```

**중요:** “절반 정도”라는 자연어 답변을 서식의 `1/2 이상` 또는 `1/2 미만` 같은 **경계가 있는 선택지**에 임의로 확정하면 안 됩니다. 필요하다면 “절반 이상 드셨나요, 절반보다 적게 드셨나요?”처럼 **선택지에 맞춘 확인 질문**을 추가해야 합니다. 이처럼 실제 서식의 입력 방식이 후속 질문을 결정합니다.

### 4.2 다른 업무도 같은 원리로 설계하기

| 업무 영역 | 문서에서 출발할 항목     | 기본 질문 예시                   | 답변에 따라 필요한 질문                       |
| :---- | :-------------- | :------------------------- | :---------------------------------- |
| 개인위생  | 세면·구강관리·옷 갈아입히기 | “오늘 어떤 위생 관리를 도와드렸나요?”     | “세면, 구강관리, 옷 갈아입히기 중 어떤 활동이었나요?”    |
| 이동 지원 | 이동 도움           | “오늘 이동을 도와드린 적이 있나요?”      | “어떤 이동이었나요? 전달할 특이사항이 있었나요?”        |
| 배설 지원 | 화장실 이용·기저귀 교환   | “화장실 이용이나 기저귀 교환을 도와드렸나요?” | “어떤 도움을 드렸나요?”                      |
| 산책·외출 | 산책·외출 동행        | “오늘 어르신과 산책하거나 외출하셨나요?”    | “산책이었나요, 외출이었나요?”                   |
| 특이사항  | 특이사항란           | “오늘 평소와 달랐던 점이 있었나요?”      | “언제, 어떤 상황에서 확인하셨나요? 담당자에게 전달하셨나요?” |

위 질문들은 **서식에 맞춘 AI 설계 예시**이지, 공식 서식에 적힌 질문 문구가 아닙니다.

### 4.3 답변에 따라 질문을 달리해야 하는 이유

| 사용자 답변            | AI 동작                               |
| :---------------- | :---------------------------------- |
| “안 했어요.”          | 수행했다고 기록하지 않음. 필요한 경우 미수행 사유 확인     |
| “죽을 절반 정도 드셨어요.”  | 식사 종류는 저장하고, 섭취량 선택지가 모호하면 재확인      |
| “잘 모르겠어요.”        | 미확인으로 남김. 추측해서 채우지 않음               |
| “그건 아까 말했어요.”     | 이전 대화에서 같은 정보가 확인되었는지 점검            |
| “아니요, 다른 어르신이에요.” | 기록 대상 수급자를 다시 확인한 뒤 연결 수정           |
| “넘어지셨어요.”         | 일반 기록 질문을 계속하기보다 기관의 즉시 보고·대응 절차 안내 |

**질문 종료 기준**은 단순한 질문 개수가 아니라 **선정한 서식의 필수 입력 정보가 확인되었는지**입니다. 확인되지 않은 항목은 별도 표시하여 요양보호사·관리자가 검토할 수 있어야 합니다.

## 5. AI 버디의 질문 생성 및 대화 제어

### 5.1. AI가 먼저 질문하는 구조

케어브릿지의 핵심은 사용자가 자유롭게 업무 내용을 입력하도록 기다리는 것이 아니라, **AI가 먼저 질문을 시작하는 것**입니다.

로그인 시 시스템이 확인할 정보:

- 사용자의 언어 설정
- 현재 날짜
- 해당 날짜의 담당 수급자 정보
- 수급자별 돌봄 계획 또는 질문에 필요한 업무 정보
- 해당 날짜에 이미 수집한 답변

담당 수급자 정보가 없거나 확인되지 않았다면 AI가 임의로 지정해서는 안 됩니다.

### 5.2. 수급자 확인 방식

외국인 요양보호사는 한국어 이름보다 얼굴이나 익숙한 위치 정보로 어르신을 기억할 수 있습니다. 따라서 채팅 화면에서는 담당 수급자의 **얼굴 사진, 이름, 필요한 식별 정보**를 함께 제공하는 방식을 고려합니다.

> **AI 버디:** “오늘은 이 어르신부터 이야기해 볼까요?”
>
> **화면:** [수급자 사진] 김○○ 어르신
>
> **AI 버디:** “오늘 이 어르신의 식사를 도와드렸나요?”

얼굴 사진은 식별을 돕는 보조 수단이며, 실제 기록은 시스템에 등록된 고유 수급자 식별정보와 연결해야 합니다. 사진 사용 권한과 개인정보 보호 조치도 검토해야 합니다.

### 5.3. 질문의 분기와 종료 기준

질문은 정해진 순서를 무조건 반복하지 않고 **답변에서 확인된 정보와 서식의 미확인 항목**을 기준으로 선택합니다. 구체적인 분기 예시는 **4.3절**을 참고합니다.

- 서식에 필요한 정보가 확인되었다면 같은 질문을 반복하지 않습니다.
- 답변이 모호하면 원문을 보존하고, 서식의 선택지에 맞는 추가 질문을 합니다. 예: “절반 정도” → “절반 이상 드셨나요, 절반보다 적게 드셨나요?”
- “잘 모르겠어요”와 같은 답변은 **미확인**으로 남기고 임의로 채우지 않습니다.
- 대화 중 수급자가 바뀌면 **기록 대상 ID를 다시 확인**합니다.
- 낙상 등 긴급 상황에서는 일반 기록 질문보다 **기관의 즉시 보고·대응 절차**를 우선합니다.

**질문 종료 기준**은 질문 개수가 아니라 **해당 서식의 필수 입력 정보가 충분히 확인되었는지**입니다. 확인되지 않은 정보는 기록 초안에 별도로 표시해 검토할 수 있어야 합니다.

## 6. 케어브릿지 '오늘의 채팅'과 기록 자동 생성

### 6.1. 전체 처리 흐름

```text
오늘의 채팅 시작
    ↓
담당 수급자 확인 (사진·이름 등)
    ↓
수급자와 기록 서식의 필요한 항목 확인
    ↓
AI가 모국어로 자연스럽게 질문
    ↓
답변에서 정보 추출 → 부족하면 후속 질문
    ↓
수급자별 기록 초안 생성
    ↓
요양보호사 확인 → 관리자 검토·수정·승인
    ↓
업무 기록 대화 이후 자연스러운 일상 대화
```

### 6.2. 요양보호사 화면

요양보호사는 날짜별로 생성되는 하나의 **'오늘의 채팅'**을 사용합니다.

- 오늘의 채팅
- 설정된 모국어
- 오늘 담당하는 수급자의 얼굴 사진·이름 등 식별 정보(실제 기록은 수급자 고유 ID에 연결)
- 모국어로 먼저 질문하는 AI 버디와의 대화
- 음성 입력 및 텍스트 입력

**업무 진행률, 체크리스트, 문서 작성 상태를 요양보호사 화면에 표시하지 않습니다.** 사용자는 친근한 AI 버디와 대화하고, 기록 수집·정리는 시스템 내부에서 이루어집니다.

### 6.3. 수급자별 정보 분리

하나의 채팅에서 여러 수급자에 대해 이야기하더라도 기록은 각각 분리되어야 합니다.

| 수급자 | 대화에서 수집한 업무 내용 예시 |
| :-- | :---------------- |
| 김○○ | 점심 식사 지원, 식사량 절반  |
| 박○○ | 화장실 이동 시 부축       |
| 이○○ | 말벗 활동 진행          |

각 기록에는 해당 내용을 뒷받침하는 원문 대화와 확인 상태를 연결하는 것이 좋습니다.

### 6.4. 관리자 검토 및 승인

| 확인 영역 | 내용                           |
| :---- | :--------------------------- |
| 원문    | 해당 업무 기록과 관련된 모국어 답변         |
| 번역문   | 원문을 한국어로 번역한 내용              |
| 정리본   | 업무 기록 서식에 맞춰 AI가 작성한 내용      |
| 확인사항  | 누락 정보, 모호한 표현, 추가 확인이 필요한 항목 |
| 처리 기능 | 수정, 반려, 승인                   |

업무 기록의 근거로 필요한 대화와 업무 종료 후 이루어지는 **개인적인 대화는 분리하여 관리**해야 합니다.

## 7. 업무 기록 이후의 AI 버디 대화

케어브릿지는 업무 기록 자동화만을 목적으로 하는 서비스가 아닙니다. 업무 기록을 마친 뒤에는 AI가 자연스럽게 하루를 마무리하는 대화로 이어지도록 설계합니다.

> **AI 버디:** 오늘 어르신들 이야기는 잘 정리했어요. 오늘도 수고 많으셨어요.
>
> **AI 버디:** 이제 잠깐 편하게 이야기해 볼까요? 오늘 하루는 어떠셨어요?
>
> **요양보호사:** 오늘 조금 힘들었어요.
>
> **AI 버디:** 힘든 하루였군요. 어떤 일이 가장 어려우셨어요? 이야기하고 싶으시면 편하게 말씀해 주세요.

이 단계에서는 업무 기록을 위한 질문보다 사용자의 이야기를 듣고 공감하는 대화가 중심입니다.

- 개인적인 대화는 관리자에게 자동 전달하지 않습니다.
- 사용자가 **명시적으로 공유를 요청한 지원 사항**만 별도로 처리합니다.
- 음성의 톤이나 분위기를 참고하더라도 감정 상태를 단정하지 않습니다.
- 개인적인 대화 내용은 수급자의 공식 업무 기록에 혼합하지 않습니다.

## 8. 학생들이 이번에 해야 할 작업

1. **기준 서식 확정**: 위 공식 시설급여 기록지를 열어 실제 항목과 선택지를 확인합니다. 기관 실사용 서식이 확보되면 차이를 비교합니다.
2. **항목–질문 매핑표 작성**: `서식 항목 | 입력 형태(체크/선택/텍스트) | 필요한 정보 | 기본 질문 | 후속 질문 | 기록 결과`를 작성합니다.
3. **대화 시나리오 2~3개 작성**: 식사 기록의 정상 응답, 모호한 답변에 대한 재질문, 다른 수급자로 대화가 전환되는 상황을 포함합니다.
4. **Figma 화면에 반영**: ‘오늘의 채팅’과 담당 수급자 사진, 관리자 3열 검토 화면을 구체화합니다.

### 멘토링에서 확인할 핵심 질문

> **“AI가 이 질문을 하는 이유는 무엇이며, 답변은 업무 기록 문서의 어느 항목에 들어가는가?”**

학생들이 모든 주요 질문에 대해 이 관계를 설명할 수 있다면, 단순 챗봇이 아니라 **업무 기록을 이해하고 작성하는 AI 버디**로 설계가 발전하고 있는 것입니다.
